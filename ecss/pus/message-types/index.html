    PUS message type catalogue¶

    This page is a reference card for the Packet Utilization Standard. The first part lists all 318 standard message types of ECSS-E-ST-70-41C (PUS-C, 15 April 2016): 240 requests (TC) and 78 reports (TM) in 20 service types. It was compiled from the clause 8 interface headings, which name each message type and give its layout, and from Annex C, which summarises every message type with its applicability constraint.12 The second part shows how one real mission database uses the type and subtype numbers: the Solar Orbiter MIB release MIB__20250916M25925PFMS001_SOL (16 September 2025), a PUS-A mission database.2015

    How a message type is identified¶

    A message type is identified by the pair (service type ID, message subtype ID) and carried in the secondary header of every TC and TM packet (see PUS packet structures). Both IDs range from 1 to 255. Standard service types use IDs up to 127 and mission-specific types 128 or above; within a standard service type, the standard subtypes are at most 127 and a mission may add its own from 128 up.45 PUS-A used the same split: types and subtypes 0 to 127 reserved for the standard, 128 to 255 for missions.12 This wiki writes requests as TC[x,y] and reports as TM[x,y], following the standard's own notation.1

    Applicability constraints¶

    Each message type inherits the applicability constraint of its capability type, which tells a mission whether it must provide it, may provide it, or may provide it only together with another capability.16 Annex C uses these labels:

    Label in Annex C Meaning Count in PUS-C
    minimum always provided by every subservice of that type 81
    by declaration provided if the mission says so when specifying the subservice 100
    implied by X provided automatically whenever capability X is provided 53
    requires X may be declared only if capability X is provided 28
    X response the report sent in answer to request X 58 (2 of them also "minimum")

    The counts are this wiki's tally of the catalogue below. TM[3,25] and TM[3,26] are counted twice: both are minimum periodic reports and also the responses to the one-shot requests TC[3,27] and TC[3,28].7

    Printed slips found while compiling

    Annex C is informative, and a few of its cells disagree with the normative clauses. Annex C lists the 6.12.3.9.1b alternatives as "TC[12,4], TC[12,5]", while the requirement itself names the delete-all and delete capabilities, TC[12,4] and TC[12,6].910 It gives the third response row of TM[11,10] as "TC[11,10] response" where TC[11,16] is meant. For TM[15,36] it prints "TC[15,36] response" and "6.15.4.5.3" as the interface clause, for TC[15,35] and 8.15.2.33. For TM[17,4] it prints "TC[17,4] response" for TC[17,3], and "TC[15.25]" with a dot.11 The catalogue below uses the corrected values. It also writes the name of TM[5,4] in lower case, as Annex C does; the clause 8.5.2.4 heading capitalises it.2

    Solar Orbiter: type and subtype usage in the MIB¶

    The release and how it was counted¶

    The figures below come from this wiki's own queries on release MIB__20250916M25925PFMS001_SOL. Its version description record (vdf) has the name 25925PFM, the comment 20250916-CSW3.1.2_MAS7.33, release 25925 and issue 733.20 For each (type, subtype) the page counts:

    • TM definitions: rows of pid with that PID_TYPE and PID_STYPE. SCOS-2000 keys a packet definition on type, subtype, APID and the extra identification fields, so one PUS report type can map to many rows.14
    • TC definitions: rows of ccf with that CCF_TYPE and CCF_STYPE and the nominal packet header NOM_TC. Left out are 125 HPC1_TC high-priority commands and 5 NO_HDR entries, none of which has a type, and 6 NOS2KHDR ground commands of type 251 (open or close TM and TC links and sessions).20

    Solar Orbiter follows PUS-A. Its TM/TC ICD tailors the services from the ESA PUS (applicable document AD1, ECSS-E-70-41A) and allows other TM and TC than the standard ones of each capability set only if agreed with ESA and Astrium.15 The comparison therefore uses both editions:

    Observations¶

    • Unused services. Types 4, 7 and 10 do not occur, as the ICD states ("not used at all").1920
    • Verification. Only TM(1,1), (1,2), (1,7) and (1,8) appear; there are no start or progress reports (1,3) to (1,6), matching the ICD's service 1 list.1620
    • CPDU numbering. CPDU commands use (2,3), the PUS-A number; PUS-C moved "distribute CPDU commands" to TC[2,4].13220
    • Memory management. Only the absolute-address variants (6,2), (6,5), (6,6), (6,9) and (6,10) are used; PUS-A's base-plus-offset messages (6,1), (6,3), (6,4), (6,7) and (6,8) are absent.1320
    • Large data transfer. Uplink uses PUS-A subtypes (13,9) to (13,11) and (13,13) to (13,16). Of these, (13,13) "Abort Reception of Uplinked Data" and the reports (13,14) and (13,15) exist only in PUS-A, while (13,16) keeps its number in PUS-C as TM[13,16] large packet uplink abortion report. Downlink uses private subtypes from 129 up rather than (13,1) to (13,8). See CFDP and ST[23].2013
    • OBCPs. (18,1) to (18,4) are absent; the mission loads and starts OBCPs with (18,140) and stops and deletes them with (18,141).2017
    • The one "C". (17,3) "Request Connection Test" is not in PUS-A Table 43 but has the number of the PUS-C TC[17,3] "perform an on-board connection test". Whether this is deliberate is not stated in the available sources.13220
    • Own services in the standard range. Type 16 is Solar Orbiter's "On-Board Traffic Management" (MilBus commands), 20 "Information Distribution", 21 "Science Data Transfer" and 22 "Context Saving". PUS-C later gave 20, 21 and 22 different meanings: parameter management, request sequencing and position-based scheduling.18320
    • Extensions. Every mission-specific subtype inside a standard PUS-A service is numbered 128 or higher, as both editions require.12520

    Inference

    Types 160 to 166 and 170 are not in the ICD's service list. Their MIB entries describe ground-side packets and commands, for example "Time Correlation Report" (164,1), "Bad Telemetry Packets" (162,1) or "PSS Set TC Bit Rate" (170,7), on APIDs 1966 and 1948. They therefore look like ground system definitions rather than spacecraft services. Similarly, types 247, 248 and 251 fall in the SolO-Hi and SPICE ranges, yet their descriptions mention the OBC, the SSMM and "Saved Synthetics". The MIB does not document either point.

SELECT * FROM vdf;                                            -- release identification
SELECT CCF_PKTID, COUNT(*) FROM ccf GROUP BY CCF_PKTID;       -- NOM_TC 5318, HPC1_TC 125, NOS2KHDR 6, NO_HDR 5
-- TM definitions per (type, subtype), with the lowest SPID as example
SELECT CAST(PID_TYPE AS INT) t, CAST(PID_STYPE AS INT) s, COUNT(*), MIN(CAST(PID_SPID AS INT))
  FROM pid GROUP BY 1, 2 ORDER BY 1, 2;
-- nominal TC definitions per (type, subtype), with the first command name as example
SELECT CAST(CCF_TYPE AS INT) t, CAST(CCF_STYPE AS INT) s, COUNT(*), MIN(CCF_CNAME)
  FROM ccf WHERE CCF_PKTID = 'NOM_TC' GROUP BY 1, 2 ORDER BY 1, 2;
-- totals below and above type 128
SELECT CASE WHEN t < 128 THEN 'std' ELSE 'mission' END, COUNT(*), SUM(tm), SUM(tc) FROM (
  SELECT t, s, SUM(tm) tm, SUM(tc) tc FROM (
    SELECT CAST(PID_TYPE AS INT) t, CAST(PID_STYPE AS INT) s, 1 tm, 0 tc FROM pid
    UNION ALL
    SELECT CAST(CCF_TYPE AS INT), CAST(CCF_STYPE AS INT), 0, 1 FROM ccf WHERE CCF_PKTID = 'NOM_TC')
  GROUP BY t, s) GROUP BY 1;
