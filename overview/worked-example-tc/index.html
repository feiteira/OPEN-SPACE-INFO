    Worked example: building a real Solar Orbiter telecommand¶

    This page builds one real Solar Orbiter telecommand from its definition in the public Mission Information Base (MIB) down to the bits that leave the ground station antenna. The command definition, its parameter, the textual de-calibration, the packet header template and the verification stages are real rows of the release MIB__20250916M25925PFMS001_SOL (database 25925PFM, comment 20250916-CSW3.1.2_MAS7.33).1 Their meaning comes from the SCOS-2000 Database Import ICD issue 7.0.2 The Solar Orbiter packet and frame rules come from the Solar Orbiter TM-TC and Packet Structure ICD (SOL.S.ASTR.TN.00079 issue 7).3 The CCSDS and ECSS standards supply the coding rules. Every byte shown is computed on this page.

    What is real and what is illustrative

    Real (from the sources cited): command name, APID, type, subtype, acknowledgement flags, parameter type, alias table, packet header template, verification stages, the Solar Orbiter spacecraft ID (650), the MAP ID convention and the frame and packet length limits. Illustrative (chosen by this wiki and labelled as such): the packet sequence count (42), the source ID (120), the virtual channel (1), the frame sequence number (5) and the choice between AD and BD service. The CRCs, BCH parity octets and randomized octets are computed from those values with the algorithms of the standards.

    We enable the METIS housekeeping report with SID 108, so this page is the uplink twin of Worked example: decoding a real Solar Orbiter telemetry packet, which decodes exactly that report. The general uplink chain is described on Uplink: from operator command to on-board execution.

    The command we picked¶

    We wanted a command with a single parameter that is harmless by design: it changes what telemetry is generated, not the state of the spacecraft. TC(3,5) "Enable housekeeping parameter report generation" fits. In the Solar Orbiter ICD it carries a single 1-octet SID and starts the generation of one defined housekeeping report.17 The METIS version is:77

    Property Value
    Command ZIT00305 "Enable HK Par. Rep. Gen"
    Detailed description TC(3,5) - ENABLE HK PARAMETER REPORT Generation
    PUS service type / subtype 3 / 5
    APID 1084 (0x43C) = Process ID 67, packet category 12
    Parameter PIT00301 "HK_SID", 8 bits, textual de-calibration CITT1120TC
    Packet header template NOM_TC
    Acknowledgement flags 9 = 0b1001 (acceptance and completion reports)
    Verification stages 59001 (acceptance), 59003 (completion), both report based

    Solar Orbiter allocates Process IDs 67 to 71 to METIS, and every telecommand APID has packet category 12.186 All 126 METIS commands go to APID 1084, while the SID 108 report is generated on APID 1092 (Process ID 68).7783 The command definition, its parameter and its verification stages are identical in the April 2020 release MIB__20200416M10720PFMS001_SOL. Two things around them differ: the alias set has grown from 17 entries in 2020 to 18 in 2025 (HK_SID_110 was added), and in the 2020 NOM_TC header template the source ID is a fixed area of value 0 instead of a header parameter (see step 3).86

    flowchart TD

    B --> C["PUS-A TC packet<br/>13 octets, APID 1084"]
    C --> D["TC segment<br/>header 0xC1: no segmentation, MAP 1"]

    Step 1: the command definition (CCF)¶

    The CCF holds one record per command.53 The record of ZIT00305, field by field:77

    # Field Value Meaning (ICD §3.3.3.2.1)
    1 CCF_CNAME ZIT00305 unique command name
    2 CCF_DESCR Enable HK Par. Rep. Gen short description (24 characters)
    3 CCF_DESCR2 TC(3,5) - ENABLE HK PARAMETER REPORT Generation detailed description
    4 CCF_CTYPE (empty) a normal packet command; R, F, S, T and N would mark control segments, BC frames, packets without CRC, SLE and NIS throw events
    5 CCF_CRITICAL N not critical (hazardous)
    6 CCF_PKTID NOM_TC packet header template from the TCP table
    7-9 CCF_TYPE, CCF_STYPE, CCF_APID 3, 5, 1084 copied into the header fields of PCDF type T, S and A
    10 CCF_NPARS 1 one CDF element
    11 CCF_PLAN N not plannable by any source
    12 CCF_EXEC Y may be loaded stand-alone on a manual stack
    13 CCF_ILSCOPE N no interlock by default
    14 CCF_ILSTAGE C stage an interlock would wait for: completion
    15 CCF_SUBSYS 110 on-board subsystem identifier
    16-17 CCF_HIPRI, CCF_MAPID N, (empty) not a high-priority command; no forced MAP ID
    18 CCF_DEFSET (empty) no default parameter value set
    19 CCF_RAPID (empty) no redundant APID
    20 CCF_ACK 9 default value of the 4-bit Ack field, modifiable at load time
    21 CCF_SUBSCHEDID 110 default on-board sub-schedule if loaded time-tagged

    Field meanings from the ICD.53545556 The interlock stage only matters when an interlock is set; with CCF_ILSCOPE = N there is none.55 CCF_CRITICAL = N is not unusual: in this release 5448 of the 5454 commands have N and the other 6 leave the field empty, so no command is flagged critical in the MIB.85 The ICD leaves the extra protection of critical commands to each mission.53

    There is no PTV row for ZIT00305, so no static pre-transmission validation applies, and no PSM row, so no parameter set.78 The DST table has a single row, for APID 1372. APID 1084 is therefore routed to the default destination, the NCTRS.8557

    Step 2: the application data (CDF, CPC and the alias set)¶

    The CDF lists the elements of the application data field, in the order of CDF_BIT. SCOS-2000 encodes them with no gaps, so even padding bits must be declared.60 ZIT00305 has a single element:78

    CDF_ELTYPE CDF_ELLEN CDF_BIT CDF_GRPSIZE CDF_PNAME CDF_INTER CDF_VALUE CDF_TMID
    E (editable) 8 0 0 PIT00301 R (empty) (empty)

    CDF_BIT counts from the end of the packet header, data field header included, so bit 0 is the first bit after the 10-octet NOM_TC header. CDF_ELLEN is informative for parameters: the length really comes from the parameter's PTC/PFC.61 An editable element with an empty CDF_VALUE and no dynamic default has no default at all: the operator must type a value before the command can be loaded.62

    The parameter itself is defined in the CPC:78

    Field Value Meaning (ICD §3.3.3.2.2)
    CPC_PNAME, CPC_DESCR PIT00301, HK_SID name and description
    CPC_PTC / CPC_PFC 2 / 8 enumerated, 8 bits
    CPC_DISPFMT A engineering values are entered and shown as ASCII text
    CPC_RADIX (empty → default D) raw values displayed in decimal
    CPC_CATEG T textual (de-)calibration, so CPC_PAFREF is mandatory
    CPC_PRFREF (empty) no range check set
    CPC_CCAREF (empty) no numerical (de-)calibration
    CPC_PAFREF CITT1120TC alias set in PAF/PAS
    CPC_INTER, CPC_DEFVAL R, (empty) no parameter-level default

    Meanings from the ICD and Appendix A.585973 The Solar Orbiter ICD calls the SID an unsigned integer of 1 byte; an 8-bit enumerated value encodes the same way.1773

    The textual de-calibration CITT1120TC¶

    Commanding calibrations work in both directions, from engineering to raw for encoding and from raw to engineering for display, and must be one-to-one.66 The PAF row CITT1120TC ("HK SID", raw format U) has 18 aliases in the PAS:79

    PAS_ALTXT PAS_ALVAL PAS_ALTXT PAS_ALVAL
    SID_1_BOOT 1 HK_SID_107 107
    IIC_SID_20 20 HK_SID_108 108
    HK_SID_101 101 HK_SID_109 109
    HK_SID_102 102 HK_SID_110 110
    HK_SID_103 103 TASKs_Status 112
    HK_SID_104 104 HK_SPARE_1 ... HK_SPARE_4 113 ... 116
    HK_SID_105 105 IIC_COPY 120
    HK_SID_106 106

    The operator picks HK_SID_108, SCOS-2000 looks up PAS_ALVAL and encodes the raw value 108 = 0x6C.6779 The alias set mirrors the telemetry textual calibration CITT1120TM used for the SID field of the METIS reports, entry for entry.79

    Six METIS commands share PIT00301: TC(3,1) define, TC(3,3) clear, TC(3,5) enable, TC(3,6) disable, TC(3,9) report and TC(3,130) collection interval.78

    Range checks and numerical de-calibrations: not used here¶

    PIT00301 has neither a range set (PRF/PRV) nor a numerical curve (CCA/CCS).78 For contrast, the platform command ZCD00305, the same TC(3,5) for the central software's data management application on APID 172 (Process ID 10), uses an 8-bit unsigned SID parameter (PCD03011, PTC 3 / PFC 4) with range set VCD00353.807318 That range set has one raw range, 1 to 192, although its description reads "Integer between 1 and 19".80 SCOS-2000 accepts a value equal to either bound.68

    Inference

    The mismatch between the VCD00353 description ("1 and 19") and its values (1 to 192) is most likely a truncation: PRF_DESCR holds at most 24 characters, and "Integer between 1 and 192" has 25.72 The April 2020 release has the same description and range.86 The MIB itself does not say which is intended; the PRV values are what SCOS-2000 checks. The uplink walk-through reaches the same reading.

    Step 3: the packet header template (TCP, PCPC, PCDF)¶

    SCOS-2000 builds the packet header from a template. The TCP names the templates, the PCPC names the header parameters and the PCDF lays the elements out by bit offset from the start of the packet.50 The Solar Orbiter MIB defines four templates: HPC1_TC (high-priority CPDU commands, no data field header), NOM_TC (normal commands), NO_HDR (control frames and segments) and NOS2KHDR (NIS throw events).81 5318 commands use NOM_TC, 125 use HPC1_TC, 6 use NOS2KHDR and 5 use NO_HDR.85

    The 13 PCDF elements of NOM_TC:81

    PCDF_BIT PCDF_LEN PCDF_DESC PCDF_TYPE PCDF_PNAME PCDF_VALUE (hex) Filled by
    0 3 Version Number F 0 fixed
    3 1 Type F 1 fixed: telecommand
    4 1 DataFieldHeaderFlag F 1 fixed
    5 11 APID A PH_APID 0 CCF_APID
    16 2 Sequence Flag F 3 fixed: 0b11
    18 14 Sequence Count P PH_SSC 0 command system
    32 16 Packet Length P PH_LEN 0 command system
    48 1 Secondary Header Flag F 0 fixed
    49 3 PUS Version F 1 fixed: PUS version 1
    52 4 Ack K DFH_ACK 0 CCF_ACK
    56 8 Service Type T DFH_TYPE 0 CCF_TYPE
    64 8 Service Subtype S DFH_STPE 0 CCF_STYPE
    72 8 Source ID O DFH_SRC 0 see below

    Rows from the MIB (all with radix H; all PCPC parameters are unsigned, code U);81 type letters from the ICD: F fixed, A APID, T type, S subtype, K acknowledgement flags, P set automatically by the command subsystem.51 The packet length counts the actual length, repeated groups included, and the multiplexer keeps a sequence counter per APID. Operators cannot edit header parameters on a manual stack.51

    Inference

    Open point, PCDF_TYPE = O. The Source ID element uses type O, which is not among the six types listed in ICD issue 7.0, nor in the other ICD issues in this wiki's library. Its exact semantics are not stated in the available sources. Since the PCDF value is 0 and the Solar Orbiter ICD reserves values 110 to 113 and 120 to 122 for ground sources, it is presumably a mission-specific type through which the command source inserts its own identifier. This is an inference.1951 The April 2020 release supports this reading: there the same element is a fixed area (PCDF_TYPE = F, value 0, no PCDF_PNAME), the PCPC has only six parameters (no DFH_SRC) and the template is described as "Normal Header", so every NOM_TC command encoded with that release carried source ID 0.86

    The NOM_TC template matches the Solar Orbiter ICD's description of the TC packet: version 000, type 1, data field header flag 1 (all commands except CPDU commands), sequence flags 11 ("stand-alone"), then a 4-octet data field header with the CCSDS secondary header flag 0, PUS version 1, the Ack field, type, subtype and an 8-bit source ID.67919 It is the PUS-A layout of ECSS-E-70-41A §5.3.3 with the optional source ID present and no spare.21

    Layout from the MIB PCDF and the Solar Orbiter ICD.819

    Bits Content
    4 TC packet PUS version number, set to 2
    4 acknowledgement flags (same bit meanings)
    8 + 8 message type: service type ID, message subtype ID
    16 source ID
    optional spare

    The PUS-C header is 5 octets instead of Solar Orbiter's 4, because the version field grows to 4 bits and the source ID to 16 bits.23 See PUS packet structures and PUS-A vs PUS-C.

    The Ack field¶

    In PUS-A the four Ack bits ask for success reports: bit 3 (the least significant) for acceptance, bit 2 for start of execution, bit 1 for progress and bit 0 (the most significant) for completion; failure reports are always generated.21 Solar Orbiter restricts the field to 0000, 0001, 1000 and 1001; the start and progress bits must be zero.915 CCF_ACK = 9 is 0b1001: acceptance and completion. 5225 of the 5454 commands in the release use 9.85 The flags can be changed when a command is loaded, and unsetting a flag also disables the matching report-based verification stage.5665

    Step 4: assemble the packet¶

    Putting the pieces together, with an illustrative sequence count of 42 and source ID 120:

    Octets Field Bits Value Origin
    0-1 version, type, DFH flag, APID 000 1 1 10000111100 0x1C3C PCDF fixed values + CCF_APID 1084
    2-3 sequence flags, sequence count 11 00000000101010 0xC02A fixed 11 + count 42 (illustrative)
    4-5 packet length 6 0x0006 7 octets in the data field, minus one
    6 sec. header flag, PUS version, Ack 0 001 1001 0x19 fixed + CCF_ACK 9
    7 service type 3 0x03 CCF_TYPE
    8 service subtype 5 0x05 CCF_STYPE
    9 source ID 120 0x78 "direct commands" ground source (illustrative choice)
    10 SID (PIT00301) 108 0x6C HK_SID_108 via CITT1120TC
    11-12 packet error control CRC-16 0x4F50 computed over octets 0-10 
    1C 3C C0 2A 00 06 19 03 05 78 6C 4F 50        (13 octets)

    Header field rules from CCSDS 133.0-B-2 and the Solar Orbiter ICD;24678 values from the MIB rows above.778179

    How the remaining fields are set:

    • Sequence count. The Solar Orbiter ICD wants it kept per APID and source ID, for tracing the command through the ground system; the receiving application does not check it.7 In SCOS-2000 the multiplexer maintains it per APID.51
    • Packet length. C = (octets in the data field) − 1 = (4 + 1 + 2) − 1 = 6. The Solar Orbiter static acceptance checks require 5 ≤ C ≤ 241 and compare C with the number of received octets.815
    • Packet error control. A CRC with generator \(G(x) = x^{16} + x^{12} + x^5 + 1\), shift register preset to all ones, computed over the whole packet except the last 16 bits.1022 The SCOS-2000 releaser appends it to every command unless CCF_CTYPE = S.54 This wiki's implementation reproduces the Solar Orbiter ICD's test vectors (00 00 → 1D0F, AB CD EF 01 → 04A2, 14 56 F8 9A 00 01 → 7FD5) before being applied here.10

    The size limits fit together. The Solar Orbiter ICD limits a TC packet data field to 242 octets (4 header + 236 application data + 2 error control), which makes the largest packet 248 octets.8 Its overview drawing (figure 3.1-1) stacks the layers: a TC frame of at most 256 octets is a 5-octet frame header, a frame data field of at most 249 octets (a 1-octet segment header plus up to 248 octets of packets) and a 2-octet frame error control field.511 SCOS-2000's default maximum command size (CMDP_MAX_BLOCK_SIZE) is also 248 octets.52

    Inference

    The sources do not say that SCOS-2000's 248-octet default and the Solar Orbiter 248-octet packet limit were chosen to match. They are simply equal.

    Step 5: how the command will be verified (CVP, CVS, CVE)¶

    SCOS-2000 verification is either report based (PUS service 1 reports) or parameter based (checks on telemetry values). The CVP attaches stages to a command, the CVS defines each stage and the CVE holds the criteria of parameter-based stages.63 ZIT00305 has two stages:82

    CVS_ID CVS_TYPE CVS_SOURCE CVS_START CVS_INTERVAL CVS_SPID CVS_UNCERTAINTY
    59001 A acceptance R report 0 s 16 s (empty) (empty → −1, standard window)
    59003 C completion R report 0 s 32 s (empty) (empty → −1, standard window)

    Values from the MIB, columns in ICD field order;82 meanings from the ICD.6465 CVS_START is the delay after release before the window opens, CVS_INTERVAL the sampling interval used to compute the window, and an empty CVS_UNCERTAINTY keeps the default window of the TC Spacon.64 Report-based stages need no CVE rows, and there are none for these two stages.82 Stage 59001 is attached to all 126 METIS commands on APID 1084 and stage 59003 to 125 of them; the exception, ZIT00605 (TC(6,5) dump memory), uses completion stage 59004 with a 4561 s interval instead.82

    The acceptance and completion stages are passed by METIS service 1 reports on APID 1073 (Process ID 67, category 1, reserved for TC verification):8318

    • TM(1,1) acceptance success, SPID 59001, and TM(1,7) completion success, SPID 59003. Both carry the 2-octet TC packet ID and the 2-octet packet sequence control of the command, which the MIB places at octets 16 and 18 (NIT82001, NIT82002).8316
    • For our command these four octets would be 1C 3C C0 2A. The SCOS-2000 verifier extracts them from every service 1 report to find the command instance.74
    • Failures arrive as TM(1,2) or TM(1,8) with a 2-octet failure ID after the echo. The PIC identifies service 1 subtypes 2 and 8 by a 16-bit PI1 at octet 20, so each failure ID gets its own SPID (for example TM(1,2) failure ID 2, "PEC_ERROR", is SPID 59007).8320 The verifier itself uses only the subtype, not the failure code.74

    Inference

    The verification stage IDs 59001 and 59003 are equal to the SPIDs of the METIS TM(1,1) and TM(1,7) packets. This looks like a naming convention of the Solar Orbiter MIB; the ICD does not require it, and CVS_SPID is empty for these stages.

    MET-->>S2K: TM(1,7) on APID 1073, echo 1C3C C02A (stage 59003)
    MET-->>S2K: TM(3,25) SID 108 on APID 1092 from now on

    The ground stages R, U and O are the interlock stages named in the ICD (reception at the ground station, uplink, on-board reception); in BD mode O is treated as U.55 Stages A and C come from the CVS rows above.82 The CLCW that every Solar Orbiter TM frame carries reports the FARM-1 state of the TC virtual channel, including V(R), the sequence number of the next Type-AD frame it expects.1436

    Inference

    The ICD does not say how SCOS-2000 detects stage O. For an AD frame, a V(R) that has moved past the frame's N(S) shows that FARM-1 accepted it, which is presumably what closes the stage; the diagram does not claim more than that the CLCW carries this information.

    Inference

    That the enabled SID 108 report then appears on APID 1092, although the command went to APID 1084, is deduced from the MIB: the alias HK_SID_108 of the command and the SID value 108 of SPID 59208 are the same, and METIS defines SID 108 only on APID 1092.7983 The MIB does not link commands to the packets they enable. ICD Appendix C also warns that SCOS-2000 needs the packet definition in the database before the report is enabled on board.76

    Step 6: the TC segment and the transfer frame¶

    The segment header¶

    Solar Orbiter puts every TC packet in a TC segment. The 1-octet segment header has 2 sequence flags, always 11 because packets are never segmented, and a 6-bit MAP ID: 0 for CPDU commands, 1 for all normal commands.11 The segment data field may hold several complete packets (aggregation), each found from the length of the one before; SCOS-2000 supports this blocking, but high-priority commands cannot be aggregated.127555 Our segment holds one packet:

    Field layout from CCSDS 232.0-B-4 §4.1.3.2.2 and table 4-2,28 values from the Solar Orbiter ICD.11

    The frame header¶

    The TC transfer frame adds a 5-octet primary header and a 2-octet frame error control field (FECF).2526

    Field Bits Solar Orbiter rule Our frame
    Version number 0-1 00 00
    Bypass flag 2 0 = Type-A, FARM acceptance checks; 1 = Type-B, checks bypassed AD: 0, BD: 1
    Control command flag 3 0 = data, 1 = control command 0
    Spare 4-5 00 00
    Spacecraft ID 6-15 0x28A (650), also used by the ETB and OBC-DM 650
    Virtual channel ID 16-21 one VC per on-board TC decoder; the ICD lists 000001 and 000010 1 (illustrative)
    Frame length 22-31 total octets − 1; Solar Orbiter frames are at most 256 octets, so bits 22-23 are 00 20
    Frame sequence number 32-39 AD: the FOP-1 counter V(S); BD and BC: 0x00 AD: 5 (illustrative), BD: 0

    Rules from the Solar Orbiter ICD §3.4 and CCSDS 232.0-B-4 §4.1.2.132627 The ICD's VC wording is not fully consistent: it calls the "suggested values" zero and one but encodes the two decoders as 000001 and 000010.13 The frame is 5 + 1 + 13 + 2 = 21 octets, so the length field holds 20.

    The FECF is present. The text of the Solar Orbiter ICD §3.4 only counts the frame length "to the last bit of the FRAME ERROR CONTROL FIELD (if present)", but its drawings settle the question: figure 3.1-1 shows a 2-octet TC frame error control field (CRC) at the end of every TC frame, and the frame drawing of §3.4 lists a 16-bit frame error control field after the data field, with at most 251 octets for the two together.513 This matches the ICD's TC coding reference, ECSS-E-ST-50-04C, in which all TC frames carry the FECF, and the current ECSS adoption notice of CCSDS 232.0-B-4, which makes it mandatory.43331

    The FECF uses the same CRC as the packet error control (generator \(x^{16} + x^{12} + x^5 + 1\), preset to all ones), computed over the 19 preceding octets.30 This wiki's implementation reproduces the FECFs of the CCSDS 230.1-G-3 examples (4C A9 for the Unlock frame, BB 22 for the BD example, 9F 71 for the AD example).47

    02 8A 04 14 05 | C1 | 1C 3C C0 2A 00 06 19 03 05 78 6C 4F 50 | 03 FF
header           seg  TC packet                                 FECF

    Bypass 0, N(S) = 5 (illustrative). The FARM-1 passes the frame on only if N(S) equals V(R), the sequence number it expects next; the outcome is reported in the CLCW carried by every Solar Orbiter TM frame.273614

    22 8A 04 14 00 | C1 | 1C 3C C0 2A 00 06 19 03 05 78 6C 4F 50 | 56 0B
header           seg  TC packet                                 FECF

    Bypass 1 and N(S) = 0, as the Solar Orbiter ICD requires for BD frames. The FARM acceptance checks are bypassed; the frame validation checks still apply.1327

    The MIB also defines the COP-1 control frames that prepare AD mode: UNLOCK (control command flag set, one fixed octet 0x00) and SETVR (fixed area 0x8200 followed by an editable 8-bit V(R)), both with CCF_CTYPE = F and the empty header template NO_HDR.84 Their structure is the CCSDS Unlock and Set V(R) control commands.29

    Step 7: the CLTU¶

    The frame is wrapped in a Communications Link Transmission Unit for the physical layer: a 16-bit start sequence, BCH codewords and a 64-bit tail sequence.41 Each BCH codeword carries 56 information bits followed by 7 complemented parity bits and a filler bit 0, using the (63,56) modified BCH code with \(g(x) = x^7 + x^6 + x^2 + 1\).3738 If the frame does not fill the last codeword, fill octets 0x55 (alternating bits starting with 0) are appended.39

    Our 21-octet frame is exactly three 7-octet blocks, so no fill is needed and the CLTU is 2 + 3 × 8 + 8 = 34 octets. ECSS-E-ST-50-04 puts exactly one frame in each CLTU.32

    Inference

    Randomization. Whether Solar Orbiter randomizes its TC frames is not stated in the available sources. With BCH coding, CCSDS requires the randomizer unless the system designer verifies that the link works without it, so in practice it is optional and fixed per physical channel by management. In ECSS-E-ST-50-04, which the Solar Orbiter ICD lists as its TC coding reference, randomization is always used; the ECSS handbook adds that some European on-board hardware cannot handle it.44344 Both forms are therefore shown.

    On board, the decoder looks for the start sequence, decodes each codeword (ECSS-E-ST-50-04 always uses single-error-correction mode, which is why the FECF is needed), removes the randomization after decoding, and stops at the tail sequence, which is built to be uncorrectable.4033354643 Acquisition and idle sequences around the CLTU depend on the physical layer operations procedure (PLOP) and are not shown.47 Details: TC synchronization and channel coding: the CLTU.

    Step 8: from SCOS-2000 to the antenna¶

    With no DST entry for APID 1084, SCOS-2000 releases the command to the NCTRS, the default destination for spacecraft commands.5785 Towards the ground station, the CCSDS SLE forward CLTU service is the standard service "that enables a mission to send CLTUs to a spacecraft".48 (The alternative Forward Space Packet service, whose book the library holds as a historical copy, takes packets instead and leaves the frames and CLTUs to the provider.)6970 Which ground component encodes the frame and the CLTU for Solar Orbiter is not stated in the sources used for this page; see NCTRS, NIS and the ground station interface. The CLTU then modulates the uplink carrier at one of the telecommand bit rates of the spacecraft transponder (7.8125 to 4000 bit/s in the MIB's calibration of the transponder's TC bit rate parameter);71 see radio frequency, modulation and ranging. The ICD notes that a CLTU has a mission-specific maximum size, which constrains CMDP_MAX_BLOCK_SIZE.52

    The released command is archived too. The Solar Orbiter data delivery ICD says the archive keeps a TC packet per released command (SPID 100) with its verification status and the full packet sent to the spacecraft, plus a separate packet (SPID 200) with the static PTV and verification details from the MIB.49
