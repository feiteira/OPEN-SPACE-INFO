    css.dat: Command sequences definition¶

    ICD 7.0 §3.3.3.3.213,879 rows in Solar Orbiter 2025-09-16

    The css table lists the elements of each command sequence, one record per element, in the order given by CSS_ENTRY (consecutive, without gaps). An element is a command, a nested sequence or (future extension) a formal parameter standing for a command or sequence chosen later. For each element the table defines the release timing - a delta release time relative either to the previous command of the expanded sequence (or to its manual dispatch time) or to the start of the sequence - and the execution time tag, relative either to the previous time-tagged command or to the execution start of the sequence; whether a command needs its own manual dispatch (ARM and GO) on the stack; grouping (commands released as an uninterrupted batch) and blocking (commands aggregated into a single segment); the interlock scope and stage, overriding the command defaults; and flags to override dynamic PTV, static PTV and CEV checks for individual commands. All these attributes are defaults: the command requests can still be edited on a manual stack after the sequence is loaded. CSS_NPARS gives the number of SDF entries holding the element's parameter values. Since SCOS-2000 R5.0 these tables are converted on request into XML sequence definitions held in the FARC rather than the run-time MIB, imported as a delta without re-importing the TM/TC database.1

    Key: CSS_SQNAME, CSS_ENTRY

    #FieldTypeM/ODescription
    1CSS_SQNAMEChar(8)MName of the sequence (CSF_NAME) the element belongs to.
    Refers to csf.CSF_NAME. Solar Orbiter: filled in 13,879 of 13,879 rows; e.g. AIPF981A, ASYF100K, ASYS500I, ASYF100D, ASYF100E ICD PDF p. 169

    Solar Orbiter: filled in 13,879 of 13,879 rows; e.g. Report Current Monitoring List, Report Current FMON Status List, Disable HK Para Rpt Gen, Unprotect Func Mon Parameters, Protect Func Mon Parameters ICD PDF p. 169
    3CSS_ENTRYNumber(5)MEntry number of the element, giving its position in the sequence. Entries must be consecutive (no gaps). Part of the key.
    Solar Orbiter: filled in 13,879 of 13,879 rows; e.g. 1, 2, 3, 4, 5 ICD PDF p. 169
    4CSS_TYPEChar(1)MType of the element.
    • C Command.
    • S Sequence (nested).
    • T Textual comment, non-uplinkable entry (not supported by SCOS-2000).
    • F Formal parameter representing a command (future extension).
    • P Formal parameter representing a sequence (future extension).
    Solar Orbiter: filled in 13,879 of 13,879 rows; e.g. C, S ICD PDF p. 169
    5CSS_ELEMIDChar(8)OIdentifier of the element: for type C a valid command name (CCF_CNAME), which ICD 7.0 says must not contain group repeater parameters (but see the SDF section, which since R4.2 allows commands with fully defined repeated groups); for type S a valid sequence name (CSF_NAME); for types F and P a formal parameter name (CSP_FPNAME) of this sequence; for type T it must be empty.
    Refers to ccf.CCF_CNAME / csf.CSF_NAME / csp.CSP_FPNAME. Solar Orbiter: filled in 13,879 of 13,879 rows; e.g. ZCL00C08, ZCL08E0A, ZCD00F91, ZCX08401, ZIM00336 ICD PDF p. 169
    6CSS_NPARSNumber(3)ONumber of editable parameters of the element, i.e. the number of SDF records for this element; only relevant for elements of type C or S. Grey in ICD 7.0: not used by SCOS-2000 processing.
    Solar Orbiter: filled in 13,879 of 13,879 rows; e.g. 0, 1, 2, 3, 4 ICD PDF p. 170
    7CSS_MANDISPChar(1)OWhether the command needs its own manual dispatch (ARM and GO) on a manual stack. Must be left empty for commands inside a group or block (CSS_GROUP or CSS_BLOCK = M or E) except the first command of the group/block. Irrelevant for non-command elements.
    • Y The command requires a separate manual dispatch.
    • N The element is dispatched together with the previous command (import default).
    Default N. Solar Orbiter: filled in 13,879 of 13,879 rows; e.g. Y, N ICD PDF p. 170
    8CSS_RELTYPEChar(1)OReference used with CSS_RELTIME to compute the command release time tag, or the release start time of a nested sequence.
    • R Relative to the release time of the previous command in the expanded sequence, or to the command's own dispatch time if it has a manual dispatch flag (import default).
    • A Relative to the start time of the sequence the element belongs to; for the top-level sequence the start time is given by the user at load time (printed in italics in ICD 7.0).
    Default R. Solar Orbiter: filled in 13,879 of 13,879 rows; e.g. R, A ICD PDF p. 170
    9CSS_RELTIMEChar(8)ODelta release time of the element, written as hh.mm.ss up to 23.59.59 (other separators such as ':' are accepted). For a command with RELTYPE=R and manual dispatch, the release time is the dispatch time plus this delta; for a command with RELTYPE=R without manual dispatch, it is the release time of the last command before it in the expanded top-level sequence (if the previous element is a nested sequence, its last command) plus the delta; with RELTYPE=A it is the release start time of the current sequence plus the delta. For a nested sequence the same rules give its release start time. An empty value means no release time tag (release as soon as possible) for a command, and a zero delta for a nested sequence. It must be empty for commands inside a group or block other than the first one.
    Solar Orbiter: filled in 13,835 of 13,879 rows; e.g. 00.00.01, 00.00.00, 00.00.01.000, 00.00.02, 00.00.05 ICD PDF p. 170
    10CSS_EXTIMEChar(17)ODelta execution time tag of the element, written [+][ddd.]hh.mm.ss[.mmm] for positive and -[ddd.]hh.mm.ss[.mmm] for negative intervals (other separators accepted). With PREVREL=R the execution time of a command (or the execution start of a nested sequence) is the execution time of the last execution time-tagged command before it in the expanded top-level sequence plus the delta; with PREVREL=A it is the execution start time of the current sequence plus the delta. An empty value means a command is not execution time-tagged (executed on board on receipt) and a nested sequence has zero delta execution start time. (ICD 7.0 prints the first part of this description twice.)
    Solar Orbiter: filled in 13,784 of 13,879 rows; e.g. 00.00.01, 00.00.00, 00.00.01.000, 00.00.02, 00.00.05 ICD PDF p. 172
    11CSS_PREVRELChar(1)OReference used with CSS_EXTIME to compute the execution time tag of a command or the execution start time of a nested sequence.
    • R Relative to the execution time tag of the previous time-tagged command in the expanded sequence (import default).
    • A Relative to the start time of the sequence the element belongs to; for the top-level sequence the user gives it at load time.
    Default R. Solar Orbiter: filled in 13,879 of 13,879 rows; e.g. R, A ICD PDF p. 175
    12CSS_GROUPChar(1)OGrouping condition (commands only): grouped commands are released as one batch that cannot be interleaved with commands released by other command sources. A group has at least a start and an end command, with a configurable maximum number of middle commands; only the first command (S) may have a manual dispatch flag or a release time tag. Empty when the command is not grouped; irrelevant for non-command elements.
    • S Start of the group.
    • M Middle of a group.
    • E End of the group.
    Solar Orbiter: filled in 56 of 13,879 rows; e.g. E, S, M ICD PDF p. 175
    13CSS_BLOCKChar(1)OBlocking condition (commands only): blocked commands are released in a single data unit by aggregating their packets into one segment data field. A block has at least a start and an end command, with a configurable maximum number of middle commands; a block may sit inside a group but not a group inside a block; only the first command may have a manual dispatch flag or release time tag. The total block length must stay within a mission-configurable limit, and high-priority commands (CCF_HIPRI=Y) are not allowed in a block. Empty when not blocked.
    • S Start of the block.
    • M Middle of a block.
    • E End of the block.
    Solar Orbiter: filled in 76 of 13,879 rows; e.g. E, S, M ICD PDF p. 176
    14CSS_ILSCOPEChar(1)OInterlock scope for this command element, overriding CCF_ILSCOPE. For commands inside a block or group, G and L are only allowed on the last command (E). If empty, the command definition applies. Irrelevant for non-command elements.
    • G Global interlock of the whole system.
    • L Interlock of the local commanding source only.
    • S Interlock of local commanding for the subsystem of the command.
    • B Interlock of global commanding for the subsystem only (italic in ICD 7.0: not currently supported).
    • F Local commanding source interlocked only on verification failure (no WAIT state).
    • T Local subsystem commanding interlocked only on verification failure (no WAIT state).
    • N No interlock.
    • empty Interlock scope taken from the command definition (CCF_ILSCOPE).
    Solar Orbiter: filled in 12,500 of 13,879 rows; e.g. N ICD PDF p. 176
    15CSS_ILSTAGEChar(1)OVerification stage that the interlock of this command element waits for, overriding CCF_ILSTAGE. O is handled as U in BD mode. The importer prevents requesting a CEV stage (A or C) not foreseen in the command's CVP/CVS profile and substitutes the highest applicable stage (A or O). If empty, the command definition applies.
    • R Reception/acceptance at the ground station.
    • U Uplink (radiation/transmission).
    • O On-board reception/acceptance (transfer); handled as U in BD mode.
    • A Application acceptance.
    • C Completion.
    • empty Stage taken from the command definition (CCF_ILSTAGE).
    Solar Orbiter: filled in 12,494 of 13,879 rows; e.g. C ICD PDF p. 177
    16CSS_DYNPTVChar(1)OWhether the dynamic PTV checks (feasibility checks, time checks, interlocks) are overridden for this command element. Irrelevant for non-command elements.
    • Y Dynamic PTV overridden for this command.
    • N Dynamic PTV applied (import default).
    Default N. Solar Orbiter: filled in 13,879 of 13,879 rows; e.g. N ICD PDF p. 178
    17CSS_STAPTVChar(1)OWhether the static, telemetry-based PTV check (PTV table) is overridden for this command element. Irrelevant for non-command elements.
    • Y Static PTV overridden for this command.
    • N Static PTV applied (import default).
    Default N. ICD PDF p. 178

    • Y CEV checks disabled for this command.
    • N CEV checks performed (import default).
    Default N. Solar Orbiter: filled in 13,879 of 13,879 rows; e.g. N, Y ICD PDF p. 179

    Relationships¶

    • CSS_SQNAME → csf.CSF_NAME: Sequence owning the element.
    • CSS_ELEMID → ccf.CCF_CNAME (type C) / csf.CSF_NAME (type S) / csp.CSP_FPNAME (types F, P): Element identity depends on CSS_TYPE.
    • CSS_SQNAME + CSS_ENTRY → sdf.SDF_SQNAME + sdf.SDF_ENTRY: Parameter values of the element; CSS_NPARS should equal the number of SDF records.
    • CSS_ILSCOPE / CSS_ILSTAGE → ccf.CCF_ILSCOPE / ccf.CCF_ILSTAGE: Overrides; empty means the command defaults apply.
    • CSS_ILSTAGE → cvp.CVP_CVSID / cvs: Requested CEV stages must exist in the command verification profile.
    • CSS_STAPTV → ptv: Overrides the static PTV checks of the command.
    • CSS_BLOCK → ccf.CCF_HIPRI: High-priority commands cannot be blocked.

    History across ICD issues¶

    ICD 5.1 (2001, section 3.3.3.3.2, PDF p.78-86) already defines the 18 fields with the same names and defaults (CSS_ILSCOPE including F and T), except that CSS_EXTIME is Char(16). ICD 6.7 Draft A (PDF p.157-168), ICD 6.9 (PDF p.161-171) and ICD 7.0 (PDF p.168-179) have CSS_EXTIME as Char(17). ICD 6.5 split the long CSS_RELTIME and CSS_EXTIME descriptions over two pages (Annex 1, PDF p.256) and the evolution-line changes clarified their input formats (Annex 1 item 8, PDF p.244). pyscos2000 (ICD 7.2) has 18 columns in the same order but names field 17 CSS_STATPTV, marks only CSS_SQNAME as key (not CSS_ENTRY), and treats CSS_NPARS as mandatory; defaults N, R, R, N, N, N for CSS_MANDISP, CSS_RELTYPE, CSS_PREVREL, CSS_DYNPTV, CSS_STATPTV and CSS_CEV match the ICD.

    Notes from the extraction

    Name discrepancy: ICD 7.0 (and 5.⅙.7/6.9) field 17 is CSS_STAPTV, pyscos2000 and the Solar Orbiter SQLite use CSS_STATPTV. Optionality: CSS_NPARS carries no M in ICD 7.0 but is mandatory in pyscos2000. Key: pyscos2000 omits CSS_ENTRY from the key. Solar Orbiter 2025-09-16 (18 columns, 13879 records; 9089 in 2020): only types C (12629) and S (1250) are used; every sequence starts with entry 1 having CSS_RELTYPE='A' and CSS_PREVREL='A' and all other entries 'R'; entries are consecutive from 1 in every sequence and CSS_NPARS always matches the SDF count. CSS_RELTIME exceeds the declared Char(8) and the hh.mm.ss format in 1107 records, which carry milliseconds (e.g. '00.00.01.000'); CSS_EXTIME values use the same style and are never negative. CSS_COMM is filled in every record although the ICD marks it unsupported. 234 distinct commands containing group repeaters are used in 2467 sequence elements, which ICD 7.0 allows since R4.2 only for fully defined repeated groups although its CSS_ELEMID description still forbids them. In the 46 group/block members that are not the first (M or E), CSS_MANDISP is 'N' instead of empty and CSS_RELTIME is filled, contrary to the ICD rule. Groups (24) and blocks (34) never contain high-priority commands. CSS_ILSCOPE is 'N' or empty and CSS_ILSTAGE 'C' or empty; CSS_DYNPTV and CSS_STATPTV are always N, CSS_CEV is Y for 17 elements.
