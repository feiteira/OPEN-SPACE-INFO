    MIB parameter types: PTC/PFC in SCOS-2000¶

    Every value that SCOS-2000 extracts from telemetry or puts into a telecommand has a type, written as a pair of small integers: the Parameter Type Code (PTC) and the Parameter Format Code (PFC). The PTC names the abstract type, for example unsigned integer, real or absolute time. The PFC selects the concrete encoding and, through it, the width in bits. The pair comes from the ESA Packet Utilisation Standard. The Database Import ICD defines which pairs the SCOS-2000 MIB accepts, how wide each one is, and the text syntax in which values of each type are written in the ASCII tables.1

    This page covers the full SCOS-2000 type table, the value syntax, the related fields (width, endianness, time correlation, calibration category) and the differences from PUS-A (2003) and PUS-C (2016). It ends with the frequency of each PTC/PFC pair in the real Solar Orbiter MIB. The PUS definitions themselves are on PUS parameter types.

    Where types appear in the MIB¶

    Field Table Type Role
    PCF_PTC, PCF_PFC pcf Number(2), Number(5) Type of a monitoring parameter. Mandatory. PTC in the range 1 to 13.3
    CPC_PTC, CPC_PFC cpc Number(2), Number(5) Type of a command parameter. Mandatory.4
    CSP_PTC, CSP_PFC csp Number(2), Number(5) Type of a sequence formal parameter5
    PCF_WIDTH pcf Number(6) "Padded" width in bits, used only when extracting through vpd6
    PCF_ENDIAN pcf Char(1) Byte order of whole-byte types: B (default) or L7
    PCF_CORR, PCF_OBTID pcf Char(1), Number(5) Whether time correlation is applied to time values, and which on-board clock8
    CPC_CORR, CPC_OBTID, CPC_ENDIAN cpc as above The same for command parameters. CPC_ENDIAN is a future extension.910
    PCF_CATEG, CPC_CATEG pcf, cpc Char(1) Calibration category. It must be consistent with the type.1112

    For telemetry, the type controls decoding. SCOS-2000 uses PCF_PTC/PCF_PFC to decode parameters extracted from packets (PCF_NATUR = R or C). A synthetic parameter must still carry a valid pair that matches the format of its computed value, otherwise it is rejected at import. A saved synthetic parameter must have PTC 13.3 For commands, the type both drives encoding and constrains the raw values that are accepted in the MIB and on the stack. The importer syntax-checks every command and sequence parameter value against its type, and replaces bad values with 0, an empty string or 1970.001.00.00.00.13

    Remember the distinction made in §1.3.1 of the ICD. The raw value is the value before calibration. The encoded value is the bit pattern on the link. The two coincide only for unsigned integers. A 16-bit signed integer with raw value −1 is encoded as 0xFFFF.14

    The SCOS-2000 type table¶

    Appendix A of the ICD (Table 4) lists every supported pair, together with the internal type and the width the importer assumes. It refers to the PUS nomenclature of ESA PSS-07-101 (Packet Utilisation Standard, issue 1, May 1994). Pairs that SCOS-2000 supports beyond that document are printed in bold, and pairs listed there but unsupported are printed in italics.12 The bold and italic marking does not survive in the text extraction used by this wiki, so the support status below is taken from the comment column and from Appendix C.

    PTC 1 Boolean and PTC 2 enumerated¶

    PTC PFC SCOS-2000 internal type Width Notes
    1 0 unsigned integer 1 bit Boolean
    2 1 … 32 unsigned integer PFC bits Enumerated. PUS permits only some PFCs. SCOS-2000 only limits the width to 32 bits.1

    An enumerated value has discrete, unordered values, each meaning a text. An error code is the classic example.15 In the MIB, those texts come from a textual calibration (PCF_CATEG = S, see Calibration).11 In the Solar Orbiter MIB, 25,081 of the 29,443 enumerated parameters have one.39

    PTC 3 unsigned and PTC 4 signed integers¶

    PFC Width (PTC 3 and 4) Unsigned range Signed range SCOS-2000
    0 … 12 PFC + 4 bits (4 … 16) 0 to 2^(PFC+4) − 1 −2^(PFC+3) to 2^(PFC+3) − 1 supported
    13 24 bits 0 to 16,777,215 −8,388,608 to 8,388,607 supported
    14 32 bits 0 to 2^32 − 1 −2^31 to 2^31 − 1 supported
    15 48 bits 0 to 2^48 − 1 −2^47 to 2^47 − 1 not supported
    16 64 bits 0 to 2^64 − 1 −2^63 to 2^63 − 1 not supported

    The widths are those of ICD Table 4.1 The ranges follow the PUS definitions.16 Unsigned integers are most-significant-bit first. Signed integers use two's complement, with bit 0 as the sign.16 Appendix C confirms the 32-bit limit: PFC 15 and 16 are not supported.17 In practice, PTC 3 PFC 12 is the familiar 16-bit word and PFC 14 the 32-bit one.

    PTC 5 real¶

    PFC Format Width SCOS-2000
    1 IEEE 754 single precision 32 bits TM and TC
    2 IEEE 754 double precision 64 bits TM and TC
    3 MIL-STD-1750A single precision 32 bits TM and TC. ESA missions often call it "PTC=5, PFC=2".
    4 MIL-STD-1750A extended precision 48 bits commands only (from R3.0), not telemetry

    All four rows come from ICD Table 4.1 The command-only restriction for 5/4 was clarified in ICD 6.1 (S2K-40-DCR-808), and Appendix C repeats it.1817 The remark about "PTC=5, PFC=2" means that older ESA mission documents, such as the Rosetta Space/Ground ICD cited by Table 5, number the MIL single-precision format as PFC 2. SCOS-2000 numbers it PFC 3, so a translation is needed when such documents feed a MIB.19

    The bit layouts below follow PUS-A, which reproduces both standards:20

    The extended layout is derived from the PUS-A examples, which print each value as "Mantissa (MS) Exp Mantissa (LS)" with 6, 2 and 4 hexadecimal digits.21 As an example taken from PUS-A, 0.5 × 2^1 in MIL single precision is 0x40000001. The mantissa is 0x400000 (0.5) and the exponent is 0x01.20

    PTC 6 bit string¶

    PFC Meaning Width SCOS-2000
    0 variable-length bit string variable not supported
    1 … 32 fixed-length bit string, handled as an unsigned integer PFC bits monitoring only

    SCOS-2000 treats fixed bit strings as unsigned integers of PFC bits, at most 32, and only on the monitoring side.1 PUS-C also uses fixed-length PTC 6 for spare fields, whose bits must all be zero.22

    PTC 7 octet string and PTC 8 character string¶

    PTC PFC Meaning Width SCOS-2000
    7 0 variable-length octet string variable commands and sequences only
    7 n > 0 fixed octet string n octets TM and TC
    8 0 variable-length character string variable commands and sequences only
    8 n > 0 fixed character string n characters (octets) TM and TC

    Variable-length strings can be given values from a Stack Import file or on a manual stack. To receive values from stack files, they must be editable elements of the command (CDF_ELTYPE = E).23 In PUS, a variable-length string is preceded by an unsigned length field n. SCOS-2000 command sources work out the length by counting the octets or characters in the value, and they do not read n. Before R4.0, n had to be part of the value or a separate parameter. From R4.0, SCOS-2000 can be configured to insert n automatically.1924

    The width of n is not fixed by PUS-C. It is declared per application process.25 Octet and character strings cannot be calibrated.19 On the telemetry side, variable-length strings are not decoded natively. Memory dumps and similar data need special processing.17

    PTC 9 absolute time¶

    PFC Format Coarse octets Fine octets Total SCOS-2000
    0 CUC or CDS with explicit P-field – – variable not supported
    1 CDS without µs – – 6 supported from R5.0
    2 CDS with µs – – 8 commands only
    3 … 6 CUC 1 0 … 3 1 … 4 supported
    7 … 10 CUC 2 0 … 3 2 … 5 supported
    11 … 14 CUC 3 0 … 3 3 … 6 supported
    15 … 18 CUC 4 0 … 3 4 … 7 supported
    30 Unix time: 4 octets seconds since 1970-01-01T00:00:00, then 4 octets of µs within the second – – 8 SCOS-2000 specific, "not defined in PUS". Added in ICD 6.7.

    All rows come from ICD Table 4.2627 For PFC 3 to 18, the number of coarse octets is ⌊(PFC + 1) / 4⌋ and the number of fine octets is (PFC + 1) mod 4. That is exactly the PUS rule.28 SCOS-2000 cannot recognise a time format from a P-field: the format must be known implicitly from the MIB.17 Absolute time values are converted between raw and encoded form by a mission-specific time correlation routine, and they cannot be calibrated.19 The CUC and CDS codes themselves are explained on Time code formats.

    The CDS layout follows PUS-C Table 7-10 note 2, and the CUC value is t = C1·256³ + C2·256² + C3·256 + C4 + F1·256⁻¹ + F2·256⁻² (+ F3·256⁻³).28 The Unix layout is the one given in ICD Table 4.26

    Worked example (illustrative bytes). Take a PTC 9 / PFC 17 field with bytes 0x2A 0x3B 0x4C 0x5D 0x80 0x00. The coarse time is 0x2A3B4C5D = 708,529,245 s and the fine time is 0x8000 / 65,536 = 0.5 s, so t = 708,529,245.5 s after the epoch. Which epoch, and whether on-board time correlation applies, depend on PCF_CORR and PCF_OBTID (see below). The bytes are constructed for this explanation. They are not taken from a real packet.

    PTC 10 relative time¶

    PFC Format Coarse octets Fine octets SCOS-2000
    3 … 18 CUC (same numbering as PTC 9) 1 … 4 0 … 3 supported

    The rows come from ICD Table 4.29 A relative time is a positive or negative offset, negative values being two's complement.30 It cannot be calibrated. PCF_CORR and CPC_CORR must be N for relative times (clarified in issue 7.0, changes S2K-8572 and S2K-8778).831

    Relative-time PFC numbering differs between PUS-A and SCOS-2000

    PUS-A (ECSS-E-70-41A, 2003) numbers relative CUC times from PFC 1 to 16, with ⌊(PFC + 3) / 4⌋ coarse and (PFC + 3) mod 4 fine octets.32 SCOS-2000, like PUS-C, uses PFC 3 to 18 with the absolute-time rule.2930 The same four-coarse, two-fine relative time is therefore PFC 15 in PUS-A and PFC 17 in SCOS-2000. A mission whose packet ICD follows PUS-A must translate relative-time PFCs when building its MIB.

    Inference

    The translation rule is this wiki's arithmetic from the two formulas. The ICD refers to PSS-07-101 (1994) rather than to PUS-A, and that document is not in the library, so which numbering PSS-07-101 used is not stated in the available sources.

    PTC 11 deduced¶

    PFC Meaning SCOS-2000
    0 Deduced. Type and width come from another, earlier field of the same packet. TM (through vpd) and TC
    n > 0 Deduced with a forced width of n bits commands only

    These rows are from ICD Table 4.33 PUS defines a deduced field as one whose actual type and encoding are deduced from preceding fields of the same packet, from mission constants, or both.34 The typical case in the ICD is a parameter value whose type follows from a preceding on-board parameter identifier (PUS "Parameter#").35 SCOS-2000 implements this as follows:

    • Telemetry. A deduced parameter is decoded only in variable packets (vpd). Its PCF_RELATED names the parameter that carries the on-board parameter ID. That ID is matched against PCF_PID to find the real parameter, whose PTC/PFC is then used. PCF_WIDTH either forces a fixed slot width or, if empty, lets the slot follow the width of the identified parameter, padded by that parameter's own PCF_WIDTH.356
    • Commands. A deduced command parameter (CPC_PTC = 11) inherits type, width and calibration from the TM parameter named by the first "Parameter ID" command parameter in the same (repeated) array. CPC_PFC = 0 keeps that width, and a value above 0 forces the width in bits. Deduced command parameters were introduced with SCOS-2000 R5 (ICD 6.4).36437

    A deduced data structure, as opposed to a deduced field, is not supported.38

    Real example. In the Solar Orbiter MIB, variable structure TPSD 14406 ("OBCP telemetry", TM(18,144)) contains a repeated group of two fields. The group counter is NCD12091 with VPD_GRPSIZE = 2. The first field, NCD12904, is the parameter ID: PTC 3, PFC 14, flagged VPD_PIDREF = Y. The second, NCD12905 "OBCHP_S18_Param Value", is deduced: PTC 11, PFC 0, with PCF_RELATED = NCD12904.39

    PTC 13 saved synthetic¶

    PTC PFC Meaning
    13 0 Saved synthetic parameter. Its value characteristics come from the related synthetic parameter (PCF_RELATED).40

    PTC 13 is specific to SCOS-2000: the PUS-C list of type codes ends at PTC 12.57 Each saved synthetic value occupies a 13-byte slot in its synthetic packet: 8 bytes of value, 1 byte of value type and 4 bytes of validity flags. The order of these parts within the slot is not stated in the available sources.41 Solar Orbiter's two saved synthetics, NTTSS030 and NTTSS031, carry PCF_WIDTH = 104 bits (13 bytes) and sit at byte offsets 0 and 13 of packet 66838.39

    Special command parameter types¶

    The ICD defines three "special PUS command parameter types". Command ID and Parameter ID are expressed through CPC_CATEG on top of an ordinary PTC. Deduced command parameters use PTC 11, the same code as deduced telemetry fields:361217

    Kind How it is declared What SCOS-2000 encodes Typical use
    Command ID CPC_CATEG = A, PTC 7, PFC 0 The complete raw packet of the named command (CCF_CNAME), with configurable header fields Commands that embed a TC, such as TC(19,1)
    Parameter ID CPC_CATEG = P, PTC 3 (any width) The on-board ID (PCF_PID) of the named TM parameter Commands that list TM parameter IDs, such as TC(4,6) and TC(12,1)
    Deduced CPC_PTC = 11 See PTC 11 Parameter-value lists

    Command ID and Parameter ID came from Cryosat and were integrated into the ICD with release 4.0 (issue 6.0).42 Deduced command parameters came later, with R5 (issue 6.4).37 Solar Orbiter has 2 Command ID parameters, both PTC 7 / PFC 0 ("Complete TC packet" and "TC to send upon event"). It has 152 Parameter ID parameters, all PTC 3 / PFC 14.39

    Raw value syntax¶

    Wherever the MIB holds a value, for example a default (CPC_DEFVAL, CDF_VALUE, SDF_VALUE), a limit (OCP_LVALU), a calibration point or a constant (PCF_PARVAL), the value is text in the raw format of its type (ICD Table 5):19

    Type Encoding on the link Raw format in the MIB Examples from the ICD
    Unsigned integer unsigned integer Digits in the selected radix. Decimal is the default. Binary, octal or hexadecimal are possible. 15, 1111, 17, F
    Signed integer two's complement Decimal only 127, -1, -127
    Real (IEEE single or double) IEEE 754 Scientific or fixed-point notation 23.13, -1.2E3, 2.5E38 (single), 1.6E308 (double)
    Real (MIL single) MIL-STD-1750A Scientific or fixed-point notation 23.13, -1.2E3, 1.6E38
    Octet string unsigned integer Hex digits, two per octet, no spaces 0AAFBB
    Character string ASCII ASCII characters ANY-STRING
    Absolute time per PUS yyyy.ddd.hh.mm.ss 2001.159.23.59.59
    Relative time per PUS +/-[ddd.]hh.mm.ss[.mmm] -00.01.00, +251.23.59.59.010

    Engineering (calibrated) values of unsigned integers are always input and displayed in decimal, even when the calibration's engineering format is unsigned. The engineering format of command parameters is dictated by the associated calibration.19 For integer fields of the tables, as opposed to parameter values, the C++ prefixes 0x and 0 select hexadecimal and octal.43 When a command or sequence parameter value does not match its type, the importer substitutes 0 (integers, reals, relative times), an empty string or 1970.001.00.00.00 (absolute times). A mandatory field left null becomes 0 or an empty string.13

    Related fields¶

    Width and padding¶

    PCF_WIDTH is the "padded" width of a parameter in bits. It is used only by the variable packet (vpd) extraction, to find where the next field starts when a slot is wider than the PTC/PFC implies. Padding bits always precede the value (they are its most significant bits). For fixed packets (plf) the width is always implied by PTC/PFC, and PCF_WIDTH is ignored.644 On the commanding side, CDF_ELLEN gives each element's length in bits.45

    Endianness¶

    PCF_ENDIAN (added in ICD 6.7, S2K-DCR-5192) declares the byte order of types whose length is a whole number of bytes. Issues 6.7 Draft A and 6.9 describe it as a field that "can be used in the future". Issue 7.0 drops "in the future" (S2K-8353, applicable from SCOS-2000 6.0.1).5831 B means big endian, most significant byte first, and is the default. L means little endian. The conversion applies to signed and unsigned integers, strings, octet strings, absolute times and relative times.72731 CPC_ENDIAN has the same values but is marked as a future extension (S2K-7749): issue 7.0 assigns it to "No SCOS version".1031 PUS itself always transmits the most significant bit first.16

    Time correlation flags¶

    PCF_CORR = Y (the default) applies time correlation to an absolute time parameter when it is decoded. N extracts the time without correlation. PCF_OBTID selects which on-board clock's format and correlation to use. The value is 1 to N for N clocks, and when it is left empty the MISCconfig default TCO_DEFAULT_OBT_ID applies. With N and no OBT ID, the epoch is the MISCconfig variable TCO_ESA_EPOCH. The command-side fields CPC_CORR and CPC_OBTID mirror these.89 All four fields arrived with SCOS-2000 R5.2 (ICD 6.7, S2K-SCR-4917), together with PFC 30.27 See Time correlation in SCOS-2000.

    Calibration category and type¶

    The category must agree with the type:114612

    • PCF_CATEG = N (numerical) covers numerical parameters, with or without a numerical, polynomial or logarithmic calibration. It also covers PTC 6, 7, 9 and 10.
    • S (status) is for parameters with a textual calibration.
    • T (text) is for PTC 8 character strings only.
    • PCF_CURTX must be empty for PTC 7, 8, 9 and 10. Strings and times are never calibrated.
    • CPC_CATEG must be null or N for strings and times, unless the parameter is a Command ID (A) or a Parameter ID (P).

    SCOS-2000 compared with PUS-A and PUS-C¶

    SCOS-2000 implements most of the PUS type system. The differences are listed below, because each one either limits what a mission's packets may contain or calls for a translation when the MIB is generated.

    Topic PUS-A (2003) PUS-C (2016) SCOS-2000 MIB (ICD 7.0)
    Boolean PFC 0 (1 bit)47 PFC 0, or n > 1 bits48 PFC 0 only
    Enumerated widths 1–16, 24, 32 bits15 1–64 bits49 1–32 bits
    Unsigned/signed integers PFC 0–16 (up to 64 bits)50 PFC 0–16, plus unsigned 17–19 = 1, 2, 3 bits16 PFC 0–14 (up to 32 bits)
    Real PFC 1–420 PFC 1–451 PFC 1–3. PFC 4 for commands only.
    Bit string PFC 0 variable, n fixed52 same22 Only n ≤ 32, monitoring only, as unsigned
    Variable octet/character string supported53 supported25 Commands and sequences only. Length n counted, optionally inserted (R4.0).
    Absolute time PFC 0–1854 PFC 0–46 (19–46: CUC with 4 to 10 fine octets)28 PFC 1–18 (2 for TC only) and 30 (Unix). No P-field.
    Relative time PFC 0–16, (PFC + 3) / 4 rule32 PFC 2 (CDS) and 3–1830 PFC 3–18
    Deduced PFC 034 PFC 055 PFC 0. PFC > 0 (forced width) for TC only. No deduced structures.
    Packet (PTC 12) – PFC 0 TM, PFC 1 TC56 Not in Table 4. Command ID parameters (7/0) carry TC packets instead.
    Saved synthetic (PTC 13) – – SCOS-2000 specific

    The SCOS-2000 column summarises ICD Table 4 and Appendix C.117 The PUS migration itself is covered in PUS-A vs PUS-C.

    What the numbers show¶

    • Within the SCOS-2000 limits. No parameter uses an integer wider than 32 bits, a MIL-STD real, a variable bit string or an explicit P-field.391 The time types are the 4-octet coarse CUC formats 9/15 and 9/17, plus three ground-side oddities (next point).
    • Two SCOS-specific time formats. The Unix-time format 9/30 appears exactly twice, NYG02101 "Period From" and NYG02102 "Period To", both in the "Time Correlation Report" packet (SPID 66840, APID 1966). The CDS-with-µs format 9/2 appears once, in telemetry: NYG02204 "GS Acceptance Time" in SPID 66850, "TM Packet used by the Releaser G/S response". ICD Table 4 says that 9/2 is supported for command parameters only.3926 The same packet holds the only little-endian parameter in the MIB, NYG02201 "GS Packet Size" (PTC 3, PFC 14, PCF_ENDIAN = L).39
    • Enumerated widths beyond PUS-A. 242 enumerated parameters use widths that PUS-A does not list (17, 18, 19, 21, 22, 25, 28, 30 and 31 bits). SCOS-2000 (up to 32 bits) and PUS-C (up to 64 bits) both allow them.391549
    • Small fields. Fields of 1 to 3 bits are encoded as Booleans (1/0, 4,380 parameters), enumerated (2/1–⅔, 13,306) or bit strings (6/1–6/3, 878), never as the PUS-C unsigned PFCs 17–19, which SCOS-2000 does not list.3916
    • Time correlation. All 50 parameters with PCF_CORR = N are relative times (47) or the three ground-side times above. No parameter sets PCF_OBTID.398
    • Consistency with the category rules. Category T occurs only with PTC 8 (120 parameters). No string or time parameter has a PCF_CURTX.3911

    Inference

    The parameters NYG021xx and NYG022xx are on APID 1966, in packets with mission-specific types (164 and 165) that describe ground functions. Unix-time, CDS-with-µs and little-endian encodings therefore most likely describe data produced by ground software rather than by the spacecraft. Whether SCOS-2000 decodes a 9/2 monitoring parameter despite the Table 4 restriction is not stated in the available sources.
