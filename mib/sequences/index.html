    Command sequences and parameter sets¶

    A spacecraft procedure rarely consists of one telecommand. Switching on an instrument, changing an on-board mode or dumping a packet store takes a fixed series of commands, released at set intervals and sharing a few values that the operator supplies. In SCOS-2000 such a series is a command sequence: an ordered list of commands and nested sequences, stored in the MIB as a template with place-holders called formal parameters. When the operator loads the sequence on a command stack, SCOS-2000 asks for the formal parameter values, expands nested sequences like macros, computes release and execution times, and turns the result into individual command requests.13 The MIB describes a sequence in four tables: csf (the sequence), css (its elements), sdf (the values of element parameters) and csp (its formal parameters). Five more tables define parameter sets, named collections of preset values for commands and sequences. This page covers all nine tables field by field and shows how the Solar Orbiter MIB uses them. Individual commands are described on Commanding in the MIB and their verification on Command verification in the MIB.

    Concepts and terminology¶

    The ICD uses three terms that are easy to confuse:4

    • An element is one entry of a sequence: a command, a nested sequence, or (in principle) a formal parameter standing for a command or sequence name that is given later.
    • An element parameter is a parameter of an element: a command parameter if the element is a command, or a parameter of the nested sequence if the element is a sequence.
    • A formal parameter is an argument of the sequence being defined. Seen from a parent sequence, the formal parameters of a nested sequence are called sequence parameters.

    An element parameter gets its value in one of three ways: explicitly in sdf, from the default of the original definition (cdf for commands, csp for nested sequences), or by mapping it to a formal parameter of the current sequence. Several element parameters may share one formal parameter if they have the same raw and engineering formats.4 A sequence can contain sequences to any depth, provided it never contains itself.3

    The ICD illustrates the tables with two sequences. SQ1 has three elements: command CMD1, sequence SQ2 and a formal parameter element FP3. SQ2 has two commands, CMD3 and CMD6. SQ1's formal parameters are FP1 (a command parameter), FP2 (a sequence parameter) and FP3 (a command or sequence name); SQ2's are FP4 and FP5.5

    Where sequences live: from the run-time database to the FARC¶

    In SCOS-2000 releases before R5, sequence tables were imported with all other ASCII tables into the run-time database; ICD issue 5.1 describes csf, css, sdf and csp without any special handling, and issue 7.0 dates the separate storage of sequences from R5.0.323 ICD issue 6.4, written for SCOS-2000 R5, moved TC sequence and TM display definitions out of the run-time (POST) MIB database into the FARC as XML files.29 FARC is the SCOS-2000 File Archive.33 From R5 the command sources load sequence definitions from the FARC; the XML format is specified in a separate document, ICD-0051 "SCOS-2000 TC Sequences definitions ICD", which is not among the available sources.67

    The ASCII tables remain the import format, for full backward compatibility. On request their content is converted into XML files and imported into the FARC with a "delta" approach: only the sequences in the delivered files are replaced, and previously imported sequences stay available.36 The ICD lists two consequences: sequences and displays are imported independently of the TM/TC database, so a sequence can be updated without importing a new database; and the delta import never removes old definitions.6

    B -->|"SCOS-2000 R5 and later:<br/>convert on request, delta import"| D["XML sequence files<br/>in the FARC"]

    css: sequence elements¶

    css has one record per element. Everything it says about a command is a default: after loading, the command requests can still be edited on the manual stack.10

    # Field Type Meaning and values Default
    1* CSS_SQNAME Char(8), M Sequence the element belongs to
    2 CSS_COMM Char(32) Comment; for a textual comment element it is shown in command sources
    3* CSS_ENTRY Number(5), M Position of the element; consecutive, no gaps
    4 CSS_TYPE Char(1), M C command; S sequence; T textual comment (not supported by SCOS-2000); F formal parameter standing for a command, P for a sequence (future extensions)
    5 CSS_ELEMID Char(8) CCF_CNAME for C, CSF_NAME for S, CSP_FPNAME for F/P, null for T. The field text still says a command element must not contain group repeaters, although sdf allows them since R4.2 (see below)
    6 CSS_NPARS Number(3) Number of editable parameters (records in sdf)
    7 CSS_MANDISP Char(1) Y the command needs its own manual dispatch (ARM and GO); N it is dispatched with the previous command. Null for non-first commands of a group or block N
    8 CSS_RELTYPE Char(1) R release time relative to the previous command (or to its own dispatch if manually dispatched); A relative to the start of the sequence R
    9 CSS_RELTIME Char(8) Delta release time hh.mm.ss (up to 23.59.59, other separators allowed). Null for a command means release as soon as possible; for a sequence, zero offset
    10 CSS_EXTIME Char(17) Delta execution time [+][ddd.]hh.mm.ss[.mmm] or negative -[ddd.]hh.mm.ss[.mmm]. Null means not execution time-tagged (command) or zero offset (sequence)
    11 CSS_PREVREL Char(1) R execution time relative to the previous time-tagged command; A relative to the sequence's execution start R
    12 CSS_GROUP Char(1) S, M, E: start, middle, end of a group released as a batch, not interleaved with other sources
    13 CSS_BLOCK Char(1) S, M, E: start, middle, end of a block aggregated into one TC segment
    14 CSS_ILSCOPE Char(1) Interlock scope G, L, S, B, F, T, N; null takes CCF_ILSCOPE
    15 CSS_ILSTAGE Char(1) Interlock stage R, U, O, A, C; null takes CCF_ILSTAGE
    16 CSS_DYNPTV Char(1) Y override dynamic PTV (feasibility and time checks, interlocks) N
    17 CSS_STAPTV Char(1) Y override static (telemetry-based) PTV N
    18 CSS_CEV Char(1) Y disable command execution verification checks N

    Release times, execution times and manual dispatch¶

    Release times and execution times are computed by two parallel sets of rules. For release (CSS_RELTYPE, CSS_RELTIME):12

    • a command with R and manual dispatch is released CSS_RELTIME after the operator dispatches it;
    • a command with R and no manual dispatch is released CSS_RELTIME after the release of the previous command of the expanded top-level sequence. If the previous element is a nested sequence, that means its last command;
    • a command with A is released CSS_RELTIME after the release start time of its own sequence;
    • a nested sequence with R starts CSS_RELTIME after the last command before it; with A, after the start of the containing sequence. The start of the top-level sequence is given by the operator at load time.

    Execution times (CSS_PREVREL, CSS_EXTIME) follow the same pattern relative to the previous execution time-tagged command (R) or to the execution start of the sequence (A).12 Whether the release or the execution tags are used is decided by CSF_IFTT at load time; on-board time-tagged commands are wrapped in TC(11,4) as explained on Commanding in the MIB.8

    flowchart TD
    Q{"Element type"} -->|"command"| C{"CSS_RELTYPE"}
    Q -->|"nested sequence"| S{"CSS_RELTYPE"}
    C -->|"A"| CA["release = sequence start + RELTIME"]
    C -->|"R"| M{"CSS_MANDISP"}
    M -->|"Y"| CY["release = own dispatch + RELTIME"]
    M -->|"N"| CN["release = previous command's release + RELTIME<br/>(previous command of the expanded sequence)"]
    S -->|"A"| SA["start = containing sequence start + RELTIME"]
    S -->|"R"| SR["start = last command before it + RELTIME"]

    The flowchart restates the field description of CSS_RELTIME.12

    Groups and blocks¶

    A group is released as a batch that other command sources cannot interleave. A block goes further: its commands are aggregated into a single TC segment data field.13 Appendix C of the ICD adds that such an aggregated segment is transmitted to the spacecraft as a single frame and CLTU.27 Both need at least one S and one E entry, with a configurable maximum number of M entries between them, and only the first command may carry the manual dispatch flag or a release time-tag. A block may sit inside a group but not the reverse; a block must not exceed a mission limit on its length and must not contain high-priority commands (CCF_HIPRI = Y). Inside a group or block the interlock scopes G and L are allowed only on the last command.13 Segments and frames are described in TC Space Data Link Protocol.

    sdf: values of element parameters¶

    sdf has one record per editable parameter of an element and says where its value comes from when the sequence is loaded.14

    # Field Type Meaning and values Default
    1* SDF_SQNAME Char(8), M Sequence
    2* SDF_ENTRY Number(5), M Element (CSS_ENTRY), of type C or S
    3 SDF_ELEMID Char(8), M Element name (CSS_ELEMID)
    4* SDF_POS Number(4), M For a command: bit offset of the parameter (CDF_BIT), after expansion of repeated groups. For a nested sequence: position of the sequence parameter (CSP_FPNUM)
    5* SDF_PNAME Char(8), M Editable command parameter (CDF_PNAME with CDF_ELTYPE = E) or sequence parameter (CSP_FPNAME)
    6 SDF_FTYPE Char(1) F fixed once loaded; E editable on the stack E
    7 SDF_VTYPE Char(1), M Source of the value: R raw from SDF_VALUE; E engineering from SDF_VALUE (calibrated parameters); F from the formal parameter named in SDF_VALUE (not for group repeaters); P from the value set in SDF_VALSET; S from the nested sequence's CSP_DEFVAL; D from the command's CDF_VALUE (or CPC_DEFVAL, or telemetry for a dynamic default)
    8 SDF_VALUE Char The value, or the formal parameter name for F. Command ID parameters take a fully defined command, Parameter ID parameters a PCF_NAME with on-board ID. May be null only for D, P or S
    9 SDF_VALSET Char(8) Parameter value set (PSV_PVSID); mandatory for SDF_VTYPE = P
    10 SDF_REPPOS Number(4) Original CDF_BIT of a parameter shifted by group expansion; mandatory when SDF_POS differs from CDF_BIT

    151617

    Only parameters that are editable in the command definition may appear in sdf, and the importer rejects the invalid combinations:14

    CDF_ELTYPE SDF_FTYPE Result
    F F or E not allowed
    E F valid; parameter not editable in the sequence
    E E valid; parameter editable in the sequence
    F no sdf record valid; parameter not editable

    Since R4.2, commands with group repeaters can be sequence elements, provided every repeater value and every repeated parameter is defined in the database. One sdf record is needed per repeated instance; with a repeater value of 3, each repeated parameter needs three records, and SDF_REPPOS maps each shifted instance back to its CDF_BIT.1415

    csp: formal parameters¶

    csp has one record per formal parameter. Formal parameters are declared much like command parameters and use the same calibration and range tables; they can also be of the special kinds Command ID and Parameter ID.418

    # Field Type Meaning and values Default
    1* CSP_SQNAME Char(8), M Sequence
    2* CSP_FPNAME Char(8), M Name, unique within the sequence
    3 CSP_FPNUM Number(5), M Position, consecutive; 0–65535 since R5.0 (0–999 before)
    4 CSP_DESCR Char(24) Description
    5 CSP_PTC Number(2), M Parameter Type Code; must equal that of every element parameter mapped to it
    6 CSP_PFC Number(5), M Parameter Format Code; same rule
    7 CSP_DISPFMT Char(1) Engineering format A, I, U, R, T, D; same rule R
    8 CSP_RADIX Char(1) Default radix D, H, O; may differ from the element parameters D
    9 CSP_TYPE Char(1), M C command name, S sequence name (future extensions); P mapped to one or more element parameters
    10 CSP_VTYPE Char(1) Representation of the default: R raw, E engineering; required for type P with a default, null for C/S
    11 CSP_DEFVAL Char Default value; null means the operator must enter a value before loading
    12 CSP_CATEG Char(1) C numerical, T textual calibration, A Command ID, P Parameter ID, B both (future), N none; A/P only if every mapped element parameter is of the same kind N
    13 CSP_PRFREF Char(10) Range set; may differ from the element parameters, but should only be more restrictive
    14 CSP_CCAREF Char(10) Numerical curve; must be the same as that of the mapped element parameters
    15 CSP_PAFREF Char(10) Alias set; must be the same as that of the mapped element parameters
    16 CSP_UNIT Char(4) Unit, consistent with the element parameters

    181920

    At issue 7.0, formal parameters standing for a command or sequence name were still not supported by SCOS-2000.4 When a sequence is loaded, only the formal parameter values are checked against their range sets, unless SCOS-2000 is configured to check every parameter of every contained command.21 Range sets, calibrations and the PTC/PFC codes are described on Commanding in the MIB and MIB parameter types.

    What happens at load time¶

    Putting the rules together, loading a sequence on a manual stack goes roughly as follows.

    flowchart TD
    A["Operator selects CSF_NAME<br/>(CSF_EXEC = Y)"] --> B{"CSF_IFTT"}
    B -->|"B"| B1["choose on-board or ground time-tagging"]
    B -->|"Y"| B2["enter absolute reference time"]
    B -->|"N"| C
    B1 --> C["Enter formal parameter values<br/>(CSP defaults offered, null = mandatory)"]
    B2 --> C
    C --> D["Range-check formal parameters (prf/prv)"]
    D --> E["Expand css in CSS_ENTRY order,<br/>nested sequences expanded recursively"]
    E --> F["Resolve each sdf value:<br/>R / E / F / S / D / P"]
    F --> G["Compute release and execution times,<br/>apply groups, blocks, interlocks, PTV/CEV overrides"]
    G --> H["Individual command requests on the stack<br/>(still editable, subject to FTYPE)"]

    Inference

    The order of the steps in this flowchart is this wiki's reconstruction from the field descriptions of csf, css, sdf, csp and prf. The ICD describes what each field means, not the algorithm of the command sources, which is specified in documents that are not among the available sources.17

    Parameter sets: pst, psv, cps, pvs, psm¶

    A parameter set is a named collection of command or sequence parameters. A parameter value set is a named combination of values for the parameters of one set. Applying a value set in real time fills all its parameters at once under one high-level mnemonic. Sets and value sets can be defined for commands and for sequences.22

    Table # Field Type Meaning Default
    pst 1* PST_NAME Char(8), M Unique name of the parameter set
    2 PST_DESCR Char(24) Description
    psv 1 PSV_NAME Char(8), M Parameter set (PST_NAME)
    2* PSV_PVSID Char(8), M Unique name of the value set
    3 PSV_DESCR Char(24) Description
    cps 1* CPS_NAME Char(8), M Parameter set
    2 CPS_PAR Char(8), M Command parameter (CDF_PNAME) or formal parameter (CSP_FPNAME) in the set
    3* CPS_BIT Number(4), M CDF_BIT of a command parameter, or CSP_FPNUM of a sequence parameter
    pvs 1* PVS_ID Char(8), M Value set (PSV_PVSID)
    2 PVS_PSID Char(8), M Parameter set (PST_NAME)
    3 PVS_PNAME Char(8), M Parameter given a value
    4 PVS_INTER Char(1) R raw, E engineering (calibrated parameters only) R
    5 PVS_VALS Char The value; null leaves the current value unchanged
    6* PVS_BIT Number(4), M CDF_BIT or CSP_FPNUM, for unique identification
    psm 1* PSM_NAME Char(8), M Command (CCF_CNAME) or sequence (CSF_NAME)
    2* PSM_TYPE Char(1), M C command, S sequence
    3* PSM_PARSET Char(8), M Parameter set (PST_NAME)

    222324

    A few rules tie the tables together:2324

    • cps is not used by SCOS-2000, which takes set membership from pst; the off-line database can use it to check that value sets are complete.
    • If a command parameter and a sequence parameter with the same name are both used in parameter sets, they must share PTC and display format.
    • One parameter set cannot serve both a command and a sequence, because PVS_BIT would have to be a bit offset for one and a parameter position for the other.

    Commands and sequences reference a default value set through CCF_DEFSET and CSF_DEFSET, and a sequence element can take its values from a set with SDF_VTYPE = P and SDF_VALSET.917

    Solar Orbiter: sequences in practice¶

    Overall numbers¶

    The September 2025 Solar Orbiter MIB holds 3,404 sequences with 13,879 elements, 50,014 element parameter values and 10,981 formal parameters. The April 2020 release had 2,701 sequences, 9,089 elements, 30,985 values and 5,598 formal parameters.3536

    Field Values found
    CSS_TYPE C 12,629; S 1,250; no comments or formal-parameter elements
    Elements per sequence 1 element: 1,773 sequences; 2: 533; 3: 263; up to 312 (AIPF981A "PHI copy cal data v06")
    CSF_IFTT B 3,354; N 50
    CSF_PLAN N 2,029; S (SOC) 1,177; F (flight dynamics) 195; A 3
    CSF_CRITICAL, CSF_EXEC N and Y in every record
    CSF_SUBSCHEDID set in every record (33 distinct values); CSF_SUBSYS null in 2,633
    CSF_DEFSET never used
    CSF_DOCNAME every sequence names its source document: xx-FCP-nnn 2,243, xx-CRP-nnn 1,091, xx-SEQ-nnn 70
    CSF_DATE issue dates from 2016 to 2025; 1,481 sequences carry a 2019 date
    Formal parameters 1,575 sequences declare at least one (CSF_NFPARS > 0) and 1,573 have csp records; maximum 217; CSF_NFPARS disagrees with csp for 3 sequences (APWC508A, APWC508B, ATCC011C)

    35

    Nesting is used but shallow: 467 sequences contain nested sequences, 321 distinct sequences are used as elements, and the deepest chain has three levels, for example ATCC010A "DUP_TCL_RAM_P1 v02" → ATCC007A → ATCC008A → ADMF013F.35

    Inference: naming convention

    Every Solar Orbiter sequence name starts with A, followed by a two-letter subsystem code, a letter for the kind of procedure (F, C or S) matching FCP, CRP or SEQ in CSF_DOCNAME, a three-digit procedure number and a variant letter: ADMF521B comes from DM-FCP-521. The only exception is ADUMMYSQ (document SY-CRP-501). 1,072 of the 1,177 SOC-plannable sequences have a second letter I, which appears to denote the instruments, and 138 of the 195 flight-dynamics-plannable sequences belong to the AC subsystem, apparently AOCS. The convention is deduced from the data; it is not documented in the available sources.35 Naming conventions in general are discussed on Mission tailoring of the MIB.

    Timing, dispatch and overrides¶

    Field Values found (elements)
    CSS_MANDISP Y for 12,199 of the 12,629 command elements; N for 430 and for all nested sequences
    CSS_RELTYPE / CSS_PREVREL always equal: R 10,475; A 3,404
    CSS_RELTIME most common 00.00.01 (6,658), 00.00.00 (3,181), 00.00.01.000 (962), 00.00.02 (927), 00.00.05 (714)
    CSS_EXTIME same pattern; null in 95
    CSS_ILSCOPE / CSS_ILSTAGE N / C for 12,494 commands; N / null for 6; null (taken from ccf) for 129 commands and all sequences
    CSS_DYNPTV, CSS_STAPTV never overridden
    CSS_CEV Y in 17 elements of two TC-file definition sequences

    35

    The 3,404 elements with A are exactly the first entries of the 3,404 sequences: every Solar Orbiter sequence anchors its first element to the sequence start and times all others relative to the previous command.35 1,107 release times (962 of them 00.00.01.000) are written with milliseconds, always .000 and always in the same elements as a millisecond execution time; this is a 12-character form that the ICD gives for CSS_EXTIME but not for CSS_RELTIME, whose documented format is hh.mm.ss in a Char(8) field; 44 release times are null.3512 The ICD says that a field longer than its declared length is truncated on import, with a warning.25

    Inference

    Truncating 00.00.01.000 to 8 characters gives 00.00.01, so these values would most likely still import as the intended whole-second offsets. Whether the Solar Orbiter importer or the XML conversion for the FARC truncates them, accepts them or rejects them is not stated in the available sources.

    The elements with CSS_CEV = Y are discussed on Command verification in the MIB.

    Groups and blocks¶

    Blocks appear in 29 sequences and groups in 23, covering 76 elements in total.35 ADMC403A "Set RM A Program Set v11" blocks four TC(6,2) memory loads (entries 2 to 5) between two high-priority CPDU commands, ZBC04010 "RM A Disable" and ZBC04009 "RM A Enable", which stay outside the block as the ICD requires for high-priority commands.3513 ATTF100A "DST full Power mode v08" puts all six of its commands in one group that contains three blocks of two commands, the "block inside a group" case the ICD allows.3513

    Entry Command Description CSS_GROUP CSS_BLOCK CSS_MANDISP

    2 ZCSD3403 Dst-Tx Set Clamp ON-OFF M E N
    3 ZCS2Z0AF Set DST TX A Output Pwr Sel PFM M S N

    5 ZCS2Z0AL Set DST TX B Output Pwr Sel FM1 M S N

    Worked example: ADMF521B, a sequence with nesting and formal parameters¶

    ADMF521B "SSMM ChngPsPrioDump v05" comes from procedure DM-FCP-521, issue 5 of 04/10/2024. It has four elements, three formal parameters, CSF_IFTT = B, is not plannable and defaults to sub-schedule 1.38

    CSS_ENTRY Type Element Comment CSS_MANDISP Release Execution
    1 S ADMF517A SSMM Stop PS read v02 N A 00.00.00 A 00.00.00
    2 C ZSM00235 SSMM Change PS Default Priority, TC(15,139) Y R 00.00.01 R 00.00.01
    3 C ZSM00185 SSMM Rep Catalogues Select Pkt Store, TC(15,12) Y R 00.00.01 R 00.00.01
    4 S ADMF525A SSMM unbound PS dump v01 N R 00.00.01 R 00.00.01

    The nested sequences each contain one command: ADMF517A releases ZSM00215 "SSMM Stop Downln Pkt Store" TC(15,135) and ADMF525A releases ZSM00256 "SSMM Unbounded DWL PS" TC(15,145), both with their own sdf mapping to their formal parameters.38 One value typed for XF521B02 thus lands in two command parameters directly and in a third through the nested sequence, which is the mechanism of the ICD's SQ1/SQ2 example applied to real procedures.5

    ZSM00185 contains a group repeater: PSM00226 at bit 8 repeats the next two elements. Because the sequence fixes it to 1, the command can be a sequence element, and no position shifts, so SDF_POS equals CDF_BIT.3814

    With CSF_IFTT = B, the operator decides at load time whether the four commands are released with the ground release offsets (the first command at the sequence start, each later one 1 s after the previous command or after its own manual dispatch) or executed on board at times derived from the execution offsets.81238

    Expanded result (illustrative values)

    With XF521B01 = 205, XF521B02 = 5 and XF521B03 = 2, chosen by this wiki for illustration and within the range sets, loading produces four command requests: ZSM00215 (PSM00245 = 205), ZSM00235 (PSM00230 = 5, PSM00268 = 2), ZSM00185 (PSM00226 = 1, PSM00230 = 5) and ZSM00256 (PSM00245 = 205, PSM00230 = 5, plus the fixed and default values of ADMF525A). Element parameters marked E in SDF_FTYPE remain editable on the stack; PSM00226 does not.38

    Worked example: repeated groups inside a sequence¶

    AACC250B "Exit OCM after RWMai v05" uses ZCA08E01 "Enable Functional Monitoring", TC(142,1), at entry 2. In cdf, ZCA08E01 has a 16-bit counter PCD8E011 "Nb FMONs to process" at bit 0 with group size 1, followed by the 32-bit PCD8E012 "FMON Id to process" at bit 16.38

    SDF_POS SDF_PNAME SDF_FTYPE / SDF_VTYPE SDF_VALUE SDF_REPPOS
    0 PCD8E011 F / R 4 0
    16 PCD8E012 E / R 161 16
    48 PCD8E012 E / R 162 16
    80 PCD8E012 E / R 163 16
    112 PCD8E012 E / R 164 16

    38

    The counter is fixed to 4 and there is one sdf record per repeated FMON ID, at the expanded bit offsets 16, 48, 80 and 112; SDF_REPPOS = 16 maps each instance back to the single cdf definition, exactly the rule of the ICD.141538 Functional monitoring is Service 142, a Solar Orbiter private service, and TC(142,1) "Enable Functional Monitoring" is defined in the Solar Orbiter TM/TC ICD;26 see How Solar Orbiter uses PUS.

    Parameter sets on Solar Orbiter and elsewhere¶

    All five parameter set tables are empty in the 2020 and 2025 Solar Orbiter releases and in the SWA instrument database, and no command or sequence names a default value set.353637 The SWA database also has no sequences at all.37 The Herschel/Planck System database (HPSDB), which ingested and generated MIB files both for the SCOS-2000 based instrument EGSE and for the Central Checkout System (CCS), marked csf, css, sdf and all parameter set tables as not supported by CCS ("do not use") and left csp "to be written", while HPSDB itself could still load them, for the sequence tables "in order to interface with MOIS for operations".34 MOIS itself, the procedure preparation tool, is described on operations preparation.

    Inference

    Parameter sets solve a problem that Solar Orbiter's large sequence library handles differently: preset combinations are expressed as separate sequences (variant letters such as ADMC403A/ADMC403B) or as formal parameters with defaults. That this is a deliberate design choice is this wiki's reading of the data, not a statement of the sources.

    SQL used

    Queries ran with sqlite3 -readonly on this wiki's SQLite copy of the Solar Orbiter MIB (solo-2025-09-16.sqlite; solo-2020-04-16.sqlite and swa-idb.sqlite for comparisons). All columns are stored as text, so counts and comparisons use cast(... as int).

    SELECT count(*) FROM csf; SELECT count(*) FROM css; SELECT count(*) FROM sdf; SELECT count(*) FROM csp;
SELECT CSF_IFTT, count(*) FROM csf GROUP BY 1;
SELECT CSF_PLAN, substr(CSF_NAME, 2, 2), count(*) FROM csf GROUP BY 1, 2;
SELECT substr(CSF_DOCNAME, 4, 3), count(*) FROM csf GROUP BY 1;
SELECT n, count(*) FROM (SELECT CSS_SQNAME, count(*) AS n FROM css GROUP BY 1) GROUP BY n;
-- consistency of the counters
SELECT sum(cast(CSF_ELEMS AS int) <> (SELECT count(*) FROM css WHERE CSS_SQNAME = CSF_NAME)),
       sum(cast(CSF_NFPARS AS int) <> (SELECT count(*) FROM csp WHERE CSP_SQNAME = CSF_NAME)) FROM csf;
-- nesting depth
WITH RECURSIVE r(top, cur, depth) AS (
  SELECT CSF_NAME, CSF_NAME, 0 FROM csf
  UNION ALL SELECT r.top, s.CSS_ELEMID, r.depth + 1 FROM r
    JOIN css s ON s.CSS_SQNAME = r.cur AND s.CSS_TYPE = 'S' WHERE r.depth < 10)
SELECT max(depth) FROM r;
-- timing, groups, blocks, overrides
SELECT CSS_MANDISP, CSS_RELTYPE, CSS_PREVREL, count(*) FROM css GROUP BY 1, 2, 3;
SELECT CSS_RELTIME, count(*) FROM css GROUP BY 1 ORDER BY 2 DESC;
SELECT CSS_GROUP, CSS_BLOCK, count(*) FROM css GROUP BY 1, 2;
-- value sources by element type
SELECT s.SDF_VTYPE, e.CSS_TYPE, count(*) FROM sdf s
  JOIN css e ON e.CSS_SQNAME = s.SDF_SQNAME AND e.CSS_ENTRY = s.SDF_ENTRY GROUP BY 1, 2;
SELECT d.CDF_ELTYPE, s.SDF_FTYPE, count(*) FROM sdf s
  JOIN css e ON e.CSS_SQNAME = s.SDF_SQNAME AND e.CSS_ENTRY = s.SDF_ENTRY AND e.CSS_TYPE = 'C'
  JOIN cdf d ON d.CDF_CNAME = s.SDF_ELEMID AND d.CDF_PNAME = s.SDF_PNAME AND d.CDF_BIT = s.SDF_REPPOS
 GROUP BY 1, 2;
-- worked examples
SELECT * FROM css WHERE CSS_SQNAME = 'ADMF521B' ORDER BY cast(CSS_ENTRY AS int);
SELECT * FROM sdf WHERE SDF_SQNAME = 'ADMF521B' ORDER BY cast(SDF_ENTRY AS int), cast(SDF_POS AS int);
SELECT * FROM csp WHERE CSP_SQNAME IN ('ADMF521B', 'ADMF525A') ORDER BY 1, cast(CSP_FPNUM AS int);
SELECT * FROM sdf WHERE SDF_SQNAME = 'AACC250B' AND SDF_ELEMID = 'ZCA08E01';
-- parameter sets
SELECT (SELECT count(*) FROM pst), (SELECT count(*) FROM psv), (SELECT count(*) FROM cps),
       (SELECT count(*) FROM pvs), (SELECT count(*) FROM psm);
