    Commanding in the MIB: commands and their parameters¶

    A telecommand in SCOS-2000 is never typed bit by bit. The operator picks a mnemonic such as ZPW04604 from a command stack. The system looks the mnemonic up in the Mission Information Base (MIB) and builds the packet from three kinds of definition: a reusable packet header template, the command's own structure (an ordered list of fixed areas and parameters), and the characteristics of each parameter (type, calibration, allowed range, default value). This page goes through every commanding table of the SCOS-2000 Database Import ICD (EGOS-MCS-S2K-ICD-0001, issue 7.0) field by field, explains why each field exists, and shows how the real Solar Orbiter MIB uses it. Verification of executed commands is covered in Command verification in the MIB. Command sequences and parameter sets are covered in Command sequences and parameter sets.137

    The commanding tables at a glance¶

    The ICD groups the commanding data into packet headers, commands, sequences, verification, parameter sets, (de-)calibrations and range checks. The command definition (ccf) is the central entity, and many-to-many relationships are resolved with mapping tables (cdf maps commands to parameters, cvp maps commands to verification stages, psm maps commands to parameter sets).12

    From mnemonic to packet¶

    The packet header is the first portion of the encoded TC packet and is followed by the application data field defined through cpc and cdf. Header fields are not edited by the operator: the command source or command handler fills them in, taking APID, type and subtype from ccf, computing the packet length (including repeated groups), and maintaining the source sequence counter per APID.4 Only command parameter values, not fixed areas, appear in the command history; fixed areas survive only in the hex dump of the packet.5

    Maximum command size¶

    The size of a command is capped by the configuration variable CMDP_MAX_BLOCK_SIZE, which defaults to 248 bytes. Parameters must share what is left after the header (the sum of its PCDF_LEN values), the CRC (CMD_CRC_SIZE, default 2 bytes) and, for execution time-tagged commands, the parameters of the TC(11,4) wrapper named in CMD_LOAD_TT_NAME (default 20 bytes if that command is not found). The ICD's own example: with a 10-byte header and no CRC or time tag, a single parameter can be up to 238 bytes; with default time tagging and CRC it shrinks to 216 bytes.6 Because the wrapper is added on top of CMDP_MAX_BLOCK_SIZE, the ICD advises setting that variable to the mission's maximum CLTU size minus the length of the wrapper parameters.6

    For Solar Orbiter the spacecraft TM/TC ICD caps the TC packet data field at 242 octets: 4 octets of data field header, 236 octets of application data and 2 octets of packet error control.50 With the 6-octet primary header that is a 248-octet packet, the same figure as the SCOS-2000 default.

    Inference

    The match between the Solar Orbiter maximum packet (6 + 242 = 248 octets) and the SCOS-2000 default CMDP_MAX_BLOCK_SIZE of 248 bytes is arithmetic done by this wiki. The value actually configured in the Solar Orbiter mission control system is not stated in the available sources.

    The Solar Orbiter headers¶

    The Solar Orbiter MIB (release 25925PFM, comment 20250916-CSW3.1.2_MAS7.33) defines four headers. NOM_TC is used by 5,318 commands, HPC1_TC by 125, NOS2KHDR ("NIS Throw Events") by 6 and NO_HDR ("TCP Header for CF/CS") by 5. Only NOM_TC (13 rows) and HPC1_TC (7 rows) have a layout in pcdf; NO_HDR and NOS2KHDR have no pcdf rows at all. Of the seven pcpc parameters, PH_APID, PH_SSC and PH_LEN are used by both of those headers, while DFH_ACK, DFH_TYPE, DFH_STPE and DFH_SRC are used by NOM_TC only.40

    The diagram is drawn from the 13 pcdf rows of NOM_TC.40 It matches the Solar Orbiter TM/TC ICD: version 000, type 1, data field header present on every command except CPDU commands, the APID split into a 7-bit process ID and a 4-bit packet category fixed to 12, sequence flags 11 (stand-alone), and a 4-octet data field header with the secondary header flag set to 0, PUS version 1, the Ack field, the service type and the subtype. The remaining octet holds the Source ID, which the TN defines in its Annex 8.4955 The 1-bit secondary header flag and 3-bit PUS version follow the PUS-A (ECSS-E-70-41A) layout; ECSS-E-ST-70-41C uses a 4-bit version field set to 2 and a 16-bit source ID instead.5657 See PUS packet structures and PUS-A vs PUS-C.

    HPC1_TC carries only the 6-octet primary header, with the data field header flag fixed to 0. All 125 commands that use it have APID 44, which is process ID 2, the OBC hardware function that receives high-priority commands for the Command Pulse Distribution Unit (CPDU) on MAP ID 0.405452

    A header type the ICD does not define

    In NOM_TC the Source ID element has PCDF_TYPE = O, a value not among the six types listed in ICD 7.0 (F, A, T, S, K, P), nor in issues 6.7 and 6.9.440 The Solar Orbiter SWA instrument database instead defines the same 8-bit field as a fixed area (F) with value 0x78 (120).41 The April 2020 release of the Solar Orbiter MIB also had the Source ID as a fixed area (F, value 0) and no DFH_SRC parameter in pcpc, so type O and DFH_SRC were introduced between the two releases.38 The Solar Orbiter TM/TC ICD reserves Source ID 120 for "Direct commands" from ground, and 110 to 113 for the mission timeline, TC sequences, recovery actions and the back-up timeline.55

    Inference

    PCDF_TYPE = O is most likely a mission-specific extension that lets the Solar Orbiter control system set the Source ID according to the origin of each command (manual stack, timeline, sequence), instead of using one fixed value. This is not documented in the available sources.

    Special command types (CCF_CTYPE)¶

    For missions that follow the ESA Packet Telecommand Standard, five values of CCF_CTYPE mark special commands:9

    Value Meaning What pcdf/cdf describe
    R Control segment, also called "Reset Map Command" The frame data field, not a packet
    F Control frame (BC frame, for example Unlock and Set V(R)) The frame data field
    S Command packet without the Packet Error Control field; the releaser does not append the 16-bit CRC. Typically used by EGSE for non-spacecraft commands Header and application data
    T SLE throw event, sent to the SLE service provider but not uplinked Event ID and following fields of the SLE forward service ICD
    N NIS throw event, executed by the NIS and not forwarded to the station Event ID and following fields of the NIS throw events ICD

    The ICD strongly recommends that BC frames (F) carry a global interlock (CCF_ILSCOPE = G) waiting at least for the uplink stage (U), so that no further command is released before the AD mode set-up is complete.9 Throw events cannot be blocked with other entries of a sequence or command source.7 Frame-level directives are explained in COP-1; throw events in SLE FCLTU and NCTRS, NIS and the ground station interface.

    Solar Orbiter uses all of these mechanisms except S and T. Its five NO_HDR commands are UNLOCK and SETVR (CCF_CTYPE = F, FARM directives) and RESET, REIN_TTR and TC_ONLY (R). Its six NIS throw events (N, header NOS2KHDR, type 251, subtype 1, APID 1964) open and close the session, the TC link and the TM link, for example ESESIONO "OPEN SESSION".42 The cdf rows of the two FARM directives hold the frame data field exactly as CCSDS defines the control commands: UNLOCK is one fixed octet 0x00, and SETVR is the fixed area 0x8200 followed by an editable 8-bit VR parameter.4439

    The APIDs decode with the Solar Orbiter allocation (APID = 16 × process ID + category 12): 172 is process ID 10 (OBC central software, data management), 236 is 14 (system control), 188 is 11 (AOCS), and 1532 is 95 (SWA).5442 No command declares a default interlock, so any interlock must be chosen on the stack. 205 normal-priority commands still carry a MAP ID (1 or 54), which the ICD says is ignored when CCF_HIPRI is not Y.1142

    Observed oddities

    • CCF_ILSTAGE = N on the five frame directives is not one of the ICD values (R, U, O, A, C).1042
    • The NIS throw events use APID 1964, which lies in the spacecraft range 0–2047 although they are never uplinked; 1964 is process ID 122, inside the EGSE range 112–127 of the Solar Orbiter allocation.85442

    The acknowledgement field (CCF_ACK)¶

    CCF_ACK is the decimal value of the complete 4-bit Ack field of the data field header. Since SCOS-2000 R4.0 the operator can change the flags when loading the command.12 In ECSS-E-ST-70-41C, bit 3 of the field (the last transmitted) requests successful acceptance reports, bit 2 start of execution, bit 1 progress and bit 0 (the first transmitted) completion; PUS-A assigns the bits the same way.5756

    Solar Orbiter restricts the field to 0000, 0001 (acceptance), 1000 (execution) and 1001 (both); the start and progress bits must be zero.51 In the MIB, 5,225 commands default to 9 (1001), 78 to 1 (acceptance only) and 21 to 0.42 In the PUS, failure reports are generated whatever the flags say; the flags only request the success reports.5658 The Solar Orbiter TM/TC ICD words its four settings differently: 0001 asks for the acceptance report (success or failure) and no TM(1,7) or TM(1,8) is generated, 1000 asks for the execution report (success or failure) and no TM(1,1) or TM(1,2) is generated, and only for 0000 does it state that failures are still reported.51 How these reports are matched to verification stages is the subject of Command verification in the MIB and ST[01] Request verification.

    Command routing: dst¶

    dst is optional and was, at issue 7.0, only used by SCOS-2000 based EGSE. It has at most one record per APID; commands whose APID is absent go to the default destination, the NCTRS.13

    1* DST_APID Number(5), M Command APID, 0–65535

    Repeated groups¶

    PUS requests often contain a counter N followed by N repetitions of a group of fields, sometimes nested. SCOS-2000 models this with one number per element: if CDF_GRPSIZE is greater than zero, the element is a counter and the value says how many following elements form the group.19 The ICD's own examples are the PUS-A Distribute On/Off command (2,1), where an address repeats N times (counter with group size 1), and the Disable Transmission of Telemetry Source Packets request (14,2), where N1, TYPE, N2, SUB-TYPE has N1 with group size 3 and N2 with group size 1.19

    flowchart LR
    N1["N1<br/>GRPSIZE 3<br/>bit 0"] --> T["TYPE<br/>bit 8"] --> N2["N2<br/>GRPSIZE 1<br/>bit 16"] --> ST["SUB-TYPE<br/>bit 24"]
    ST -.->|"repeated N2 times"| ST
    N2 -.->|"TYPE..SUB-TYPE block repeated N1 times"| T

    At load time the command is expanded from left to right: the operator is asked for N1 (unless it is fixed), the next three elements are generated N1 times, then each N2 is asked for and its subtype repeated.19 A counter can also be fixed in the database: with group size 0 it is just a fixed value and the repeated elements must be defined explicitly; with a fixed value and a group size above 0 the expansion happens without prompting. Since R4.2 commands with repeaters may be used in sequences, but only if every repeated value is fixed in the database.20

    In the Solar Orbiter MIB, 569 elements in 512 commands are group repeaters.44 A typical case is ZCA00C05, TC(12,5) "Add parameters to Monitoring list": its first element PCD0C051 "Nb PMONs to add" (unsigned 8 bits) has CDF_GRPSIZE = 15, so the following 15 elements (monitoring ID, two Parameter ID parameters, intervals, limits, event IDs, mask and expected value) repeat once per monitor.48 On-board monitoring itself is described in ST[12].

    Default values and dynamic defaults¶

    A parameter can receive a default at three levels: the parameter (CPC_DEFVAL), the command (CDF_VALUE) and the sequence element (SDF_VALUE). Option D (CDF_INTER, SDF_VTYPE) makes a level inherit the value of the level below, so a value maintained once in cpc propagates to every command and sequence. Conversely CDF_ELTYPE = F or SDF_FTYPE = F freezes the value at that level.14

    flowchart LR
    A["cpc<br/>CPC_DEFVAL"] -->|"CDF_INTER = D"| B["cdf<br/>CDF_VALUE"]
    B -->|"SDF_VTYPE = D"| C["sdf<br/>SDF_VALUE"]
    T["Telemetry<br/>CDF_TMID"] -.->|"CDF_INTER = T<br/>after loading"| B
    C --> S["Value on the stack<br/>(editable unless F)"]

    A dynamic default replaces the static default with the current value of a monitoring parameter, for example to initialise part of a command from the on-board state, or to steer a routing parameter used by many commands centrally through a User Defined Constant. The static raw default is still needed so the command can be loaded; the telemetry value takes over only after loading, and stops being tracked as soon as the operator types an explicit value.21

    The Solar Orbiter MIB never uses dynamic defaults: CDF_TMID is empty in all 47,609 cdf records.44

    Special PUS parameter kinds¶

    SCOS-2000 offers three special kinds of command parameter to make PUS requests easier to build:1431

    • Command ID (CPC_CATEG = A, PTC 7, PFC 0): the operator gives a command name and SCOS-2000 encodes the raw packet of that command as a variable octet string. This serves requests that carry other requests, such as TC(19,1). The referenced command must be fully encodable without input.
    • Parameter ID (CPC_CATEG = P, PTC 3): the operator gives a monitoring parameter name and SCOS-2000 encodes its on-board identifier (PCF_PID). This serves requests such as TC(4,6) or TC(12,1).
    • Deduced (PTC 11, since R5): the type, width and calibration come from the TM parameter named by the first Parameter ID parameter within the same (repeated) array of the command; PFC above 0 forces the width.

    Appendix C of the ICD adds a caveat for Service 19: the packet embedded through a Command ID parameter is encoded with fixed header values, for example for the sequence counter.34

    The Solar Orbiter MIB has two Command ID parameters and 152 Parameter ID parameters, and no Deduced parameter.45 ZCSX0031 "Define P_OFF_EPD S19" is a TC(19,1) whose last element PCD13013 "TC to send upon event" is a fixed Command ID with value ZCSX0023, the TC(11,2) "P_OFF_EPD SSID". The Parameter ID parameters appear in TC(3,1), (3,2), (3,138), (12,5), (18,140) and several private services (130, 131, 139, 142), for example PCD03014 "Datapool parameter ID" (unsigned 32 bits) in ZCA00C05.48 See ST[19] Event-action and ST[11] Time-based scheduling.

    Parameter types¶

    The PTC/PFC pairs follow Appendix A of the ICD, which in turn follows the PUS. Unsigned and signed integers are limited to 32 bits (PFC 15 and 16, 48 and 64 bits, are not supported); PTC 5 PFC 4, the 48-bit MIL-STD-1750A real, is supported for command parameters only; variable-length octet strings (PTC 7, PFC 0) and character strings (PTC 8, PFC 0) exist only on the commanding side; absolute time with a p-field (PTC 9, PFC 0) is not supported; CDS time without microseconds (9,1) is supported from R5.0, and (9,30) is a Unix-style time not defined in PUS.3031 For variable strings the command source derives the length from the value it is given, and since R4.0 SCOS-2000 can be configured to insert the PUS length field automatically.30 Details are on MIB parameter types and PUS parameter types.

    In the Solar Orbiter MIB the 7,155 command parameters are dominated by unsigned integers of 16 bits (PTC 3, PFC 12: 1,540), 8 bits (3,4: 1,120) and 32 bits (3,14: 984), IEEE single-precision reals (5,1: 630), and 1-bit and 8-bit enumerations (2,1: 598; 2,8: 364).45

    De-calibration of command parameters¶

    Command calibrations work in both directions: engineering to raw for encoding, raw to engineering for display. Only parameters whose raw representation is numerical (no strings or times) can be calibrated, and the ICD warns that every command curve must be one-to-one, otherwise an engineering value would map to more than one raw value.26 Monitoring calibrations, which only go from raw to engineering, are described in Calibration in the MIB.

    A time-tag wrapper: TC(11,4)¶

    To load execution time-tagged commands, the command used as wrapper ("Insert Telecommands in the Command Schedule", (11,4)) must itself exist in ccf and cdf; its name, type, subtype and parameters are set by the CMD_LOAD_TT* configuration variables. SCOS-2000 then encapsulates each time-tagged command in one (11,4) packet; several blocked time-tagged commands become several (11,4) packets aggregated in one TC segment, never one (11,4) with several commands.533

    High-priority commands and CPDU¶

    The CPDU in the Solar Orbiter on-board computer can generate command pulses directly from ground commands, without the central software, so vital units can be switched even when the software is down. These ground commands are called HPC-1 and travel on MAP ID 0; normal commands use MAP ID 1.52 In the MIB the 125 HPC1_TC commands all have CCF_HIPRI = Y, CCF_MAPID = 0 and no Ack field, and their application data is two fixed areas: an HPC line ID and a pulse length. For example ZBC04001 "Select PM A EEPROM Image 1" has line ID 2 and pulse length 1.48 The ICD notes that SCOS-2000 can prevent CPDU commands from being included in TC(11,4) commands or aggregated with other commands in one segment, and that aggregation in general happens only at segment level, never inside one packet.3211

    Import-time checks and pitfalls¶

    The SCOS-2000 importer only catches the most dangerous inconsistencies; the ICD leaves full consistency to the off-line database system. On import:35

    • every field is checked against its declared characteristics; too-long fields are truncated with a warning, which matters for anything but descriptions;
    • a null mandatory field produces a warning and becomes 0 or an empty string;
    • a record that breaks relational integrity (for example a reference to a missing parameter) is not imported;
    • command and sequence parameter values are syntax-checked against Appendix A; a bad value becomes 0, an empty string, or 1970.001.00.00.00 for absolute times.

    Names must be unique without regard to case, and the importer gives no warning when two names differ only in case.3 The ICD also checks CCF_ILSTAGE against the verification profile: if it asks for an execution stage (A or C) that the command's cvp/cvs definition does not have, the importer lowers it to the highest applicable level.10
