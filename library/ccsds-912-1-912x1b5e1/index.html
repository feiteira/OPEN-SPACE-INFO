    Summary¶

    The CCSDS Recommended Standard for the Forward Communications Link Transmission Unit (FCLTU) service, the Space Link Extension transfer service through which a mission control centre sends CLTUs to a ground station for radiation to a spacecraft. The provider radiates each CLTU bit for bit in the order submitted. It may check the length but never interprets the content, so any octet-aligned bit pattern can be uplinked. The service is online-only. The wiki page is SLE forward service: FCLTU.

    Section 2 describes the model. The Forward TC Space Link Processing SLE Functional Group in the SLE Complex extracts the CLTUs and radiates them, production status moves through configured, operational, interrupted and halted, and the CLCW from a return channel (clcw-global-VCID, clcw-physical-channel) can gate radiation through the bit-lock and RF-available flags. The section also covers buffering and security. Section 3 specifies the operations with parameter tables and diagnostics: CLTU-BIND (version number '6'), UNBIND, START (first-cltu-identification, start/stop production time), STOP, TRANSFER-DATA (monotonically increasing cltu-identification, earliest and latest radiation time, delay-time, report request, data; the return gives cltu-buffer-available), ASYNC-NOTIFY ('cltu radiated', 'sldu expired', production interrupted/halted/operational, 'buffer empty', action-list results), SCHEDULE-STATUS-REPORT, STATUS-REPORT, GET-PARAMETER (for example plop-in-effect PLOP-1/PLOP-2, maximum-cltu-length, modulation index and frequency, acquisition and idle sequence lengths), THROW-EVENT (management events such as an uplink bit-rate change) and PEER-ABORT. Section 4 gives the provider state machine. Annex A has the ASN.1 modules, Annex B the production status model, and Annex F example throw events for low-rate commanding.

    Key points¶

    • Issue 5 (July 2023) adds support for USLP Transfer Frames. Issues B-1 (2002), B-2 (2004), B-3 (2010) and B-4 (2016) are superseded. EC 1 (October 2024) corrects a figure font. (PDF p. 6)
    • FCLTU is an SLE transfer service that enables a mission to send CLTUs to a spacecraft. (PDF p. 10)
    • The provider transmits CLTUs in submission order and bit for bit. It may check constraints such as the maximum length but never interprets or modifies the content, so any octet-aligned bit pattern can be uplinked. The service exists only in the online delivery mode. (PDF p. 23)
    • The version-number value of the FCLTU service defined by this issue is '6'. (PDF p. 53)
    • The CLTU-START invocation carries first-cltu-identification. The return carries the conditional start-production-time and stop-production-time. (PDF p. 59)
    • The CLTU-TRANSFER-DATA invocation carries invoker-credentials, invoke-ID, cltu-identification, earliest-radiation-time, latest-radiation-time, delay-time, report and data. The return carries performer-credentials, cltu-identification, cltu-buffer-available, result and diagnostic. (PDF p. 66)
    • cltu-identification is a monotonically increasing sequence number. The return carries the value expected in the next invocation: one more than the accepted value, or the expected value after a rejection. (PDF p. 67)
    • The CLTU-ASYNC-NOTIFY types are 'cltu radiated', 'sldu expired', 'production interrupted', 'production halted', 'production operational', 'buffer empty', 'action list completed', 'action list not completed' and 'event condition evaluated to false'. (PDF p. 74)
    • Configuration parameters readable through GET-PARAMETER include acquisition-sequence-length, bit-lock-required, clcw-global-VCID, clcw-physical-channel, delivery-mode ('fwd online'), maximum-cltu-length, minimum-delay-time, modulation-frequency, modulation-index, notification-mode, plop-1-idle-sequence-length, plop-in-effect ('PLOP-1' or 'PLOP-2'), protocol-abort-mode, rf-available-required and subcarrier-to-bit-rate-ratio. (PDF p. 92)
    • CLTU-THROW-EVENT forwards an event to SLE Complex Management, for example an uplink bit-rate change after the spacecraft has been commanded to the new rate. Its outcome is reported later through CLTU-ASYNC-NOTIFY. (PDF p. 95)
    • Production status transitions run between Configured, Operational, Interrupted and Halted. Reaching 'operational' typically involves the uplink sweep and the acquisition sequence, and it can optionally require bit lock and/or RF available. (PDF p. 141)
    • The example throw events assume low-rate commanding on a 16 kHz subcarrier (maximum 4000 bit/s): Set Mod on/off, Change Rate (7.8125-4000 bit/s), Change Index (1-1570 mrad) and Change Rate/Index. (PDF p. 152)

    Notes

    The slug's 'e1' stands for Editorial Change 1 (October 2024). The Document Control footer reads 'July 2024 / October 2023'. The running page header omits 'CCSDS' ('RECOMMENDED STANDARD FOR SLE FCLTU SERVICE'), unlike the RAF, RCF and ROCF books. PDF pages 1-2 are duplicate covers. The extracted text has 155 form-feed pages (registry: 154); the last one is empty. Figure B-1, the production status transition diagram, survives only as four state names. The TM, AOS and USLP references are there because the CLCW is taken from a return-link channel. No individual authors are named. The registry copy was taken from ccsds.org on 2026-11-12.
