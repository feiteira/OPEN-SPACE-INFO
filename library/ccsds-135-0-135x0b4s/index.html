    Summary¶

    A historical (Silver Book) issue of the CCSDS Recommended Standard that catalogues the identifiers used by the CCSDS space link protocols, says how each is managed, and lists the values CCSDS has defined or reserved. Its stated goal is to manage identifier values independently of the protocol specifications. It is the ancestor of the registries now held by SANA and a handy one-stop reference for older missions; see space link identifiers.

    Section 2 introduces three management methods. Values may be defined by CCSDS in the protocol specification, assigned by CCSDS on request through a separate procedure (for example Spacecraft IDs under CCSDS 320.0), or managed by projects, with some values reserved. Sections 3 to 7 then tabulate the identifiers protocol by protocol:

    • CFDP Entity ID and the SCPS-TP Connection Identifier, both managed by projects;
    • the Space Packet APID, with reserved values 2040 to 2047 (2045 CFDP, 2046 ISO 8473, 2047 Idle Packet);
    • the SCPS-NP identifiers;
    • the data link identifiers: Transfer Frame Version Number, SCID, VCID (AOS VCID 63 reserved for idle frames), TM Frame Secondary Header Version, MAP ID, Proximity-1 Port ID, CLCW Version, Packet Version Number (Space Packet 000, SCPS-NP 001, Encapsulation Packet 111) and the Encapsulation Protocol Identifier with its extension mechanism.

    Annex A (normative) specifies the IP Extension (IPE) header. This is a variable-length, odd-valued shim after the Encapsulation Packet header that identifies IPv4 (33), IPv6 (87) and the IP header-compression formats. Annex D gives the bit position and meaning of the length field of each CCSDS packet type, which the data link protocols use to extract packets from frames.

    Key points¶

    • The document is a CCSDS Historical Document: no longer current, either replaced by a newer issue or withdrawn as obsolete. (PDF p. 1)
    • Issue 4 (October 2009) added the IPE specification (annex A) and direct multiplexing of IPv4 in transfer frames; issue 2 added Proximity-1 Port IDs and issue 3 the security subsection and the IPv4/Encapsulation Protocol IDs. (PDF p. 8)
    • Lossless Data Compression, SCPS-FP and the TM and TC Synchronization and Channel Coding standards are left out because they use no identifiers. (PDF p. 15)
    • Each identifier is managed in one of three ways: defined by CCSDS in the protocol specification, assigned by CCSDS on Agency request under a separate procedure, or managed by individual projects (possibly with CCSDS-reserved values). (PDF p. 15)
    • The CFDP Entity ID and the SCPS-TP Connection Identifier are managed by projects, with no reserved values. (PDF p. 18)
    • The APID is managed by projects; CCSDS reserves APIDs 2040-2044 for future use, 2045 for CFDP, 2046 for ISO 8473 and 2047 for the Idle Packet. (PDF p. 20)
    • The SCPS-NP Domain Identifier is 'Assigned by CCSDS' but no assignment procedure exists; one must be developed if SCPS-NP is used globally. (PDF p. 21)
    • The SCID is assigned by CCSDS (procedure in CCSDS 320.0-B-5); the VCID and the TC MAP ID are managed by projects; the Transfer Frame, Frame Secondary Header, CLCW and Packet version numbers and the Proximity-1 Port ID are defined by CCSDS. (PDF p. 22)
    • Transfer Frame Version Numbers: TM and TC frames are both version 1 (binary 00), distinguished by the ASM or the CLTU Start Sequence; AOS is version 2 (01); Proximity-1 is version 3 (10). (PDF p. 23)
    • Only one VCID is reserved: binary 111111 (63) for AOS Idle Transfer Frames; no VCID is reserved for the other data link protocols. (PDF p. 23)
    • Packet Version Numbers: 1 (000) Space Packet, 2 (001) SCPS-NP, 8 (111) Encapsulation Packet; the binary-encoded value goes in the packet header. (PDF p. 25)
    • Encapsulation Protocol IDs (3 bits): 000 Fill, 010 IPE, 011 CFDP, 110 Extended Protocol ID (4-bit field, all 16 values reserved), 111 arbitrary aggregations of octets; 001, 100 and 101 are reserved. (PDF p. 26)
    • Proximity-1 Port IDs: 000 Bitstream and 010 Packets on both links; 001 Hardware Commands on the forward link only; all other values are reserved. (PDF p. 27)
    • The IPE header is one or more octets after the Encapsulation Packet header; the LSB of every octet except the last is 0 and the last octet's LSB is 1, so all valid values are odd. (PDF p. 31)
    • IPE header values include 33 for IPv4, 35 for Frame Relay IP Header Compression Control Protocol, 87 for IPv6, and 97 to 113 for RFC 2507/2508 compressed-header formats. (PDF p. 32)
    • Packet length fields: Space Packet bits 32-47 (data field octets minus 1, add 7 for the total); SCPS-NP bits 3-16 (total octets); Encapsulation Packet bits 8-15, 16-31 or 32-63 (total octets including header). (PDF p. 37)

    Notes

    File name suffix 's' = CCSDS Silver Book (historical). PDF p. 1 is the inserted historical-status notice, and PDF pp. 2 and 3 are duplicate covers; the extraction has 38 PDF pages (registry: 37), the last one blank. Numbering inconsistencies as printed: the table of contents lists 1.7 as References, but the body has 1.7 Conventions and 1.8 References; the security subsection points to 'References subsection (1.7)'; the Foreword cites the change-control document as '[B1]' although the informative reference is [C1]; Annex D's text introduces 'Table C-1' but the table is D-1. Reference [19] prints the author 'B. Nordgren' twice. All cited protocol issues are of 2003-2009 vintage (for example SPP 133.0-B-1, TM SDLP 132.0-B-1, Encapsulation Service 133.1-B-2, SCID procedures 320.0-B-5); the library holds much newer issues of these (ccsds-133-0-133x0b2e2, ccsds-132-0-132x0b3, ccsds-133-1-133x1b3e1, ccsds-320-0-320x0m7c1). The registries in this document are maintained today by SANA, as the newer library items reference (for example ccsds-130-3-130x3g1 cites SANA registries for Packet Version Numbers and Protocol IDs). No individual authors are named.
