## Summary

A CCSDS Magenta Book that adds the **Forward Space Packet (FSP)**-specific part of the SLE Application Program Interface. The generic C++ API (component model, service instances, operation objects, proxies) is defined in the API core specification [CCSDS 914.0-M-2](../library/ccsds-914-0-914x0m2c1.md). This book adds what an implementation needs to provide or use the [SLE FSP service](../ccsds/sle/fsp.md), which carries telecommand Space Packets to a ground station that runs [COP-1](../ccsds/cop-1.md) on its behalf. It is the FSP counterpart of the RAF API book [CCSDS 915.1-M-2](../library/ccsds-915-1-915x1m2.md). See also [SLE over TCP/IP and the SLE API](../ccsds/sle/isp1-and-api.md).

Section 1 states that two FSP generations are supported: Generation 2 (BIND version 1, FSP B-1) and Generation 3 (BIND version 4, FSP B-2). There is no Generation 1. Section 2 extends the API model with FSP SI User and FSP SI Provider classes. The provider exports three interfaces. IFSP_SIAdmin holds the configuration (APID list, MAP list, virtual channel, maximum frame and packet length, blocking and multiplexing settings, packet buffer size). IFSP_FOPMonitor holds the FOP-1 parameters (sliding window, timer, transmission limit, V(S), FOP state). IFSP_SIUpdate receives the production events (packet started, radiated or acknowledged, buffer empty, production status change, VC aborted, directive completed). Table 2-1 maps each event to the status parameters it updates and the FSP-ASYNC-NOTIFY it triggers. A long subsection explains which checks are left to the application in multi-threaded designs: production status, blocked state, time windows, and APID/version/type checks on the opaque packet data. It also explains the special return handling for TRANSFER-DATA, INVOKE-DIRECTIVE and THROW-EVENT. Section 3 gives the normative component behaviour and diagnostic ordering, and Annex A (about 90 pages) gives the C++ types, operation objects and service instance interfaces.


## Key points

- The book specifies only the FSP-specific extensions to the SLE API core: functionality, interfaces and externally visible behaviour. It does not cover implementations, internal design or communications technology. *(PDF p. 10)*
- Two FSP generations are supported: Generation 2 (BIND version 1, FSP 912.3-B-1) and Generation 3 (BIND version 4, FSP 912.3-B-2). Generation 1 does not apply because the first FSP issue was written as part of Generation 2. Generation 2 support is for backward compatibility for a limited time. *(PDF p. 11)*
- The FSP SI Provider exports IFSP_SIAdmin (configuration), IFSP_FOPMonitor (FOP parameters, used only to answer GET-PARAMETER) and IFSP_SIUpdate (production events). The application must keep the FOP parameters updated, whatever the service instance state. *(PDF p. 20)*
- IFSP_SIUpdate methods are PacketStarted, PacketRadiated, PacketAcknowledged, BufferEmpty, PacketNotStarted, ProductionStatusChange, VCAborted, NoDirectiveCapability, DirectiveCapabilityOnline, DirectiveCompleted and EventProcCompleted. Each updates status parameters and may trigger an FSP-ASYNC-NOTIFY. *(PDF p. 22)*
- Configuration parameters include apid-list, blocking-timeout-period, blocking-usage, directive-invocation-enabled, map-list, maximum-frame-length, maximum-packet-length, segment-header, VC multiplexing control and scheme, virtual-channel and maximum-packet-buffer-size. Generation 3 adds bit-lock-required and rf-available-required. *(PDF p. 26)*
- The FOP parameters handled are fop-sliding-window, timeout-type, timer-initial, transmission-limit, transmitter-frame-sequence-number, fop-state, and MAP multiplexing control and scheme. *(PDF p. 27)*
- Status counters are kept separately for AD (sequence-controlled) and BD (expedited) packets received, processed and radiated, plus number-of-packets-acknowledged and packet-buffer-available. *(PDF p. 28)*
- Production status 'halted' rejects both BIND and START. 'Interrupted' accepts BIND but rejects START. 'Configured' and 'operational' accept both. *(PDF p. 30)*
- Several TRANSFER-DATA invocations can be in transit. When a check fails, the service element may therefore pass the operation to the application, which inserts the next expected packet identification and buffer size. INVOKE-DIRECTIVE and THROW-EVENT are handled the same way. *(PDF p. 31)*
- When a packet cannot be processed (non-operational production or expired latest start time), the service instance becomes blocked until the user sends FSP-STOP and then FSP-START. A blocked AD mode is cleared by a TRANSFER-DATA with mode 'sequence controlled and unblock AD'. *(PDF p. 32)*
- The API treats packets as opaque, so the service element is not required to check APID, packet version or packet type. These checks are left to the application. *(PDF p. 33)*
