## Summary

The CCSDS Recommended Standard that defines the standard binary and ASCII **time code formats** used to time-tag data in space data systems. Its formats appear everywhere in telemetry and telecommand: in the [Space Packet](../ccsds/space-packet.md) secondary header, in the [PUS](../ecss/pus/packets.md) packet time fields (SCOS-2000 TM packets usually carry a CUC on-board time), in time correlation and in ground files. The standard defines formats only, not timing accuracy or stability.

Section 1 defines four levels of interpretability: Level 1 is fully self-defined with a CCSDS epoch, Level 2 has an agency-defined epoch, Level 3 only guarantees monotonic increase and Level 4 only gives the length. It also sets the CCSDS bit numbering, where bit 0 is transmitted first and is the MSB. Section 2 (new in issue 4) discusses security: time codes can be critical, so integrity, authentication or confidentiality must come from other layers.

Section 3 is the specification. Each code is an optional **P-field** (preamble: extension flag, 3-bit code ID, detail bits) followed by a **T-field**:

* **CUC**: a binary count of seconds and binary fractions from 1958 January 1 TAI (ID '001') or an agency epoch (ID '010'), with 1 to 4 coarse and 0 to 3 fine octets, and more through the new second P-field octet. It is not UTC-based.
* **CDS**: a day count (16 or 24 bits) plus milliseconds of day (32 bits) plus optional microseconds or picoseconds. It is UTC-based.
* **CCS**: a BCD calendar code in month/day or day-of-year form with up to 10^-12 s resolution.
* **ASCII A and B**: YYYY-MM-DDThh:mm:ss.d...Z and YYYY-DDDThh:mm:ss.d...Z.
* **Agency-defined codes** (ID '110').

The annexes give the counter ranges (normative), the rationale and comparison of the codes, a glossary of time terms, the TAI-UTC leap-second relation and table, and NASA PB-5J as an example of an agency-defined code.


## Key points

- Issue 4 (November 2010) defines a second P-field octet for CUC, adds a new section on security and updates editorial elements; EC 1 (February 2014) corrects page v. *(PDF p. 7)*
- Four recommended codes (one unsegmented, three segmented) use the SI second; each is a P-field (preamble, explicit or implicit) plus a T-field (time). *(PDF p. 9)*
- Four levels: Level 1 complete unambiguous interpretation (CCSDS epoch), Level 2 partial (agency epoch), Level 3 only monotonic increase, Level 4 only code length. *(PDF p. 9)*
- Security services for critical time codes (integrity, authentication, confidentiality) are out of scope and must come from other OSI layers. *(PDF p. 12)*
- P-field octet 1: bit 0 extension flag, bits 1-3 time code identification, bits 4-7 code-specific detail; IDs 000, 011 and 111 are reserved. ASCII codes have no P-field. *(PDF p. 14)*
- CUC: binary count from 1958 January 1 TAI (ID '001', Level 1) or an agency-defined epoch (ID '010', Level 2); P-field bits 4-5 give coarse octets minus one, bits 6-7 the fine octets; it is not UTC-based and leap seconds do not apply. *(PDF p. 15)*
- The optional CUC P-field octet 2 adds up to 3 more coarse octets (bits 1-2) and up to 7 more fine octets (bits 3-5); bits 6-7 are reserved for mission definition. *(PDF p. 15)*
- CDS (ID '100'): a 16 or 24-bit day count from 1958 January 1 (or an agency epoch), 32-bit milliseconds of day and optional 16-bit microseconds or 32-bit picoseconds; it is UTC-based and needs leap-second correction. *(PDF p. 16)*
- CCS (ID '101'): BCD calendar code, 16-bit year plus month/day or day-of-year, then hour, minute and second, with up to six optional subsecond segments down to 10^-12 s. *(PDF p. 17)*
- ASCII Time Code A is YYYY-MM-DDThh:mm:ss.d...Z and Code B is YYYY-DDDThh:mm:ss.d...Z; the 'Z' terminator is optional; example 1988-01-18T17:20:43.123456Z. *(PDF p. 19)*
- Agency-defined codes use ID '110'; P-field bits 4-7 give the T-field length minus one (1 to 16 octets); a monotonic code is Level 3, otherwise Level 4. *(PDF p. 22)*
- Comparison: CUC is computer-efficient but not UTC-compatible; CDS is UTC-compatible and computer-efficient; CCS and ASCII are UTC-compatible and human-readable (Table B-1). *(PDF p. 26)*
- The CCSDS epoch 1958 January 1 is Julian date 2436203.5 and lies exactly 2922.0 days after 1950 January 1. *(PDF p. 29)*
- TAI = UTC + accumulated leap seconds; the table in Annex D runs from 10 s (1972) to 34 s (from 2009 January 1). *(PDF p. 39)*
