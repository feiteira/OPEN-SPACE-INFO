## Summary

The CCSDS Recommended Standard for the **Space Packet Protocol (SPP)**, which defines the Space Packet. This is the variable-length, self-delimiting data unit that on-board applications use for telemetry and telecommand, and that [PUS](../ecss/pus/packets.md) builds on. The Space Packet is the unit that [SCOS-2000](../scos2000/index.md) and its [MIB](../mib/index.md) identify by APID. It travels in the packet services of the [TM](../ccsds/tm-sdlp.md), [TC](../ccsds/tc-sdlp.md), [AOS](../ccsds/aos.md), Proximity-1 and [USLP](../ccsds/uslp.md) data link protocols, or over the DTN Bundle Protocol.

Section 2 explains the concept. The APID names a managed data path inside one naming domain (usually one spacecraft). The protocol itself does no routing, segmentation, retransmission or flow control, and its services are preconfigured, unidirectional, asynchronous, unconfirmed, incomplete and not sequence-preserving. There are two services: the Packet Service (the user supplies ready-made packets) and the Octet String Service (the provider wraps user octets into packets). Section 3 gives their parameters and primitives.

Section 4 specifies the packet bit by bit. The 6-octet primary header holds a 3-bit version ('000'), Packet Type (0 = telemetry, 1 = telecommand), Secondary Header Flag, 11-bit APID (all ones = Idle Packet), 2-bit Sequence Flags, a 14-bit Packet Sequence Count (or Packet Name for telecommand) and the 16-bit Packet Data Length (data field length minus one). The packet data field may hold an optional secondary header (a CCSDS [time code](../ccsds/time-codes.md), ancillary data, or both) and user data, giving packets of 7 to 65542 octets. Section 5 lists the managed parameters. The annexes contain the PICS proforma, the new APID and Secondary Header Format SANA registries, and the informative references.


## Key points

- Issue 2 (June 2020) removes the networking-type terminology and implied functionality of issue 1 (2003); EC 2 (September 2024) changes the page size to A4. *(PDF p. 7)*
- SPP itself defines no path, network or routing functionality; the APID names a managed data path whose meaning and configuration are entirely mission-specific. *(PDF p. 16)*
- Missions with several processors or spacecraft must sub-allocate the single APID naming domain or extend it with mission-specific secondary-header fields. *(PDF p. 17)*
- SPP services are preconfigured, unidirectional, asynchronous, unconfirmed, incomplete and non-sequence-preserving; the protocol does no segmentation, retransmission or flow control. *(PDF p. 19)*
- Two services, both addressed by APID: the Packet Service (user-formatted Space Packets) and the Octet String Service (the provider formats octet strings into packets). *(PDF p. 20)*
- A Space Packet is a 6-octet Primary Header plus a 1 to 65536-octet Packet Data Field, so 7 to 65542 octets in total. *(PDF p. 31)*
- Primary header: Packet Version Number (3 bits, '000'), Packet Type (1 bit), Secondary Header Flag (1 bit), APID (11 bits), Sequence Flags (2 bits), Packet Sequence Count or Packet Name (14 bits) and Packet Data Length (16 bits). *(PDF p. 32)*
- Packet Type is '0' for telemetry (reporting) and '1' for telecommand (requesting); the Secondary Header Flag is static per APID and is '0' for Idle Packets. *(PDF p. 33)*
- The Idle Packet APID is all ones ('11111111111', 2047); the reserved APIDs for CFDP and LTP of issue 1 were removed, so it is now the only reserved value. *(PDF p. 34)*
- Sequence Flags: '00' continuation segment, '01' first segment, '10' last segment, '11' unsegmented; they must be '11' when the Octet String service is used. *(PDF p. 34)*
- The Packet Sequence Count is per APID and modulo-16384; the Packet Name alternative is allowed only in telecommand packets. *(PDF p. 35)*
- Packet Data Length C = number of octets in the Packet Data Field minus 1. *(PDF p. 36)*
- The optional secondary header is a Time Code Field (a CCSDS time code from 301.0-B-4), an Ancillary Data Field, or both, and stays fixed for a managed data path; it is mandatory if there is no User Data Field. *(PDF p. 37)*
- Managed parameters: Maximum Packet Length, Packet Multiplexing Scheme, Service Type per APID, and Packet Secondary Header Contents. *(PDF p. 42)*
- SANA APID registry policy: 0-2046 unmanaged, 2047 reserved by the CCSDS Blue Book; a new registry records Secondary Header Format documents. *(PDF p. 48)*
