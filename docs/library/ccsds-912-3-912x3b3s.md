## Summary

The CCSDS Recommended Standard for the **SLE Forward Space Packet (FSP) service**. This SLE transfer service lets a mission control centre hand individual Space Packets to a ground station's SLE provider. The provider segments them into TC frames, runs COP-1 (FOP-1) on the virtual channel, and radiates them in sequence-controlled (AD) or expedited (BD) mode. The wiki page is [SLE FSP](../ccsds/sle/fsp.md). This issue only covers Space Packets sent through the telecommand stack ([TC SDLP](../ccsds/tc-sdlp.md), [COP-1](../ccsds/cop-1.md), [CLTU coding](../ccsds/tc-coding-cltu.md)). The AOS forward use foreseen in the [reference model](../library/ccsds-910-4-910x4b2e1s.md) is out of scope, and only online delivery is defined.

Section 2 places FSP in the forward telecommand functional groups. TC VC Data Insertion builds and buffers TC frames and acts on CLCWs. CLTU Generation randomises, BCH-encodes and adds start and tail sequences. TC Space Link Processing radiates the result. Section 2 also covers scheduling and configuration through service packages, the three provider states (unbound, ready, active) and the security aspects. Section 3 specifies the thirteen operations: BIND, UNBIND, START, STOP, TRANSFER-DATA (with packet-identification, production time window, transmission mode, MAP-identifier, blocking and radiated or acknowledged notifications), ASYNC-NOTIFY, SCHEDULE-STATUS-REPORT, STATUS-REPORT, GET-PARAMETER, THROW-EVENT, INVOKE-DIRECTIVE (the COP-1 directives such as Initiate AD Service or Set V(S)) and PEER-ABORT. Section 4 gives the provider state tables. The normative annexes define the ASN.1 data types, the queue and MAP/VC multiplexing model (FIFO, absolute priority, polling vector), production status and the conformance matrix. For context see [SLE](../ccsds/sle/index.md) and the ESA ground-station interface in [NCTRS and NIS](../scos2000/nctrs-nis.md).


## Key points

- FSP is an SLE transfer service that lets a mission send Space Packets to a spacecraft in sequence-controlled or expedited mode. *(PDF p. 12)*
- This version handles only Space Packets (CCSDS 133.0-B) sent through the telecommand stack. Use with the AOS stack is out of scope, and only the online delivery mode is defined (offline is for further study). *(PDF p. 12)*
- The underlying communications service must deliver invocations and returns in sequence, completely, without duplication, with flow control that signals backpressure, and with notification of disruptions. *(PDF p. 13)*
- No Forward TC Frame Recommended Standard exists, so the Forward CLTU Generation and Forward TC VC Data Insertion functional groups must be in the same Complex. *(PDF p. 30)*
- The Forward TC VC Data Insertion SLE-FG blocks or segments packets into TC frames. For sequence-controlled frames it sets the Frame Sequence Number and keeps a copy, then retransmits or deletes the copy according to the CLCW from Type-0 OCF channels. *(PDF p. 31)*
- This version does not support applying SDLS to the TC frames, because a user generally does not want to disclose its security configuration to the FSP provider. *(PDF p. 31)*
- Service packages set the production parameters: the TC VC, the MAP and frame multiplexing schemes, maximum packet and TC frame lengths, and the CLTU and space link processing configuration. *(PDF p. 35)*
- There are thirteen operations, from FSP-BIND to FSP-PEER-ABORT. ASYNC-NOTIFY, STATUS-REPORT and PEER-ABORT are unconfirmed, and all the others are confirmed. *(PDF p. 36)*
- The provider states are 1 'unbound', 2 'ready' and 3 'active'. Packets may be transferred only in state 3, and FSP-STOP discards packets not yet passed to the segment queues. *(PDF p. 37)*
- After an association ends, accounting information, notification references and COP parameters set by directives persist for the service instance provision period. *(PDF p. 38)*
- FSP-TRANSFER-DATA carries packet-identification, earliest and latest production time, delay-time, transmission-mode, MAP-identifier, blocking, three notification flags and the data. Its return reports packet-buffer-available. *(PDF p. 75)*
- packet-identification is a monotonically increasing sequence number that starts at the first-packet-identification given in FSP-START. The provider returns the value it expects next. *(PDF p. 74)*
- At most one FSP service instance per TC VC may invoke directives. The supported directives are Initiate AD Service (without CLCW check, with CLCW check, with Unlock, with Set V(R)), Terminate AD, Resume AD, Set V(S) to V*(S), Set FOP_Sliding_Window_Width, Set T1_Initial, Set Transmission_Limit, Set Timeout_Type and Abort VC. *(PDF p. 124)*
- Two levels of multiplexing are defined: MAP multiplexing of Frame Data Units and VC multiplexing of TC frames. Each can use FIFO, absolute priority or a polling vector, and only one service type (FSP or TC VCA) is allowed on a VC. *(PDF p. 173)*
- The queue model has an FSP requests queue per service instance, a packets queue per instance (or per permitted MAP), a segments queue per packets queue, and at most one directives queue per VC. *(PDF p. 174)*
