## Summary

A Thales Alenia Space technical note that specifies the on-board control procedures (OBCPs) the Herschel/Planck CDMS on-board software runs on behalf of the scientific instruments. It also defines the Event/Action Table (EAT) entries that tie instrument or platform event reports to those OBCPs. OBCPs that ground needs for nominal payload operations are out of scope.

Section 3 sets the framework. It covers instrument-internal FDIR (the instrument raises a PUS service 5 event and the CDMS starts an OBCP through an EAT entry), spacecraft FDIR that affects the payload (1553B bus DLL, TFL TC and TFL TM failures, science data monitoring through the service 12 monitoring table, and Class B heater-loop failures), and the five spacecraft modes. On any transition to Sun or Earth Acquisition Mode the CDMS starts one 'mother' OBCP per spacecraft (DB_H_PL_SC_MODE_OBCP or DB_P_PL_SC_MODE_OBCP), which calls the instrument OBCPs.

Sections 4 (Herschel: SPIRE, PACS, HIFI) and 5 (Planck: HFI, LFI, sorption cooler SCE) repeat the same structure per instrument. Each gives the triggering event reports with APIDs and event IDs, the EAT entries (APID, event ID, TC(18,3) start-OBCP packet, action handling ID, parameter-passing and action status), and a specification table per OBCP. That table gives its ID, trigger, time-out and parameters, and the PUS telecommands it sends, such as TC(18,4) stop procedure, TC(19,5) disable actions, TC(11,2) disable sub-schedule release and TC(8,4,112,3) PCDU unit off. Section 6 lists the data-pool IDs the OBCPs use, and section 7 lists open issues on verification reports, TC rate and FDIR hierarchy. For an engineer it is a detailed real example of PUS services 5, 11, 12, 18 and 19 working together for payload FDIR.


## Key points

- Purpose: specify the OBCPs needed for Herschel/Planck payload management in the CDMS OBSW and the Event/Action Table entries linking payload event reports to nominal or recovery actions. *(PDF p. 10)*
- EAT entries for instrument-internal FDIR use Action Handling ID 0b01 (disabled in AFS, enabled in AFO), action status enabled by default and parameter passing usually disabled; an instrument with separate nominal and redundant APIDs needs two EAT entries per failure case. *(PDF p. 12)*
- EAT entries for spacecraft 1553B bus FDIR (DLL, TFL TC, TFL TM events generated by the CDMU BSW) use Action Handling ID 0b11, enabled in both AFS and AFO; the OBCP to start is HPSDB- and flight-configurable through the EAT. *(PDF p. 13)*
- The hard-coded TFL TM FDIR triggers when the CDMU receives no more than 1 TM packet from an instrument in 90 s (SDB_FDIR_TFL_TM_PERIOD_&lt;Instrument&gt;_VALUE = 90 s, SDB_FDIR_TFL_TM_MIN_&lt;Instrument&gt;_VALUE = 1); the service 12 monitoring-table-based science data monitoring allows thresholds to be changed in flight. *(PDF p. 13)*
- A Class B heater loop failure generates event TM(5,4,114,5) and a switch to redundant heaters; only HIFI uses Class B loops and requests no extra action. *(PDF p. 14)*
- There are five spacecraft modes: Launch, Sun Acquisition (SAM), Earth Acquisition (EAM), Nominal (NOM) and Survival (SM); transitions are commanded by ground (direct TC, MTL or OBCP) or autonomously on separation or CDMS/ACMS level 3/4 alarms. *(PDF p. 14)*
- Because only one OBCP is started during a mode transition, a 'mother' payload OBCP per spacecraft (DB_H/P_PL_SC_MODE_OBCP) calls the instrument OBCPs; the survival-mode OBCP is a placeholder because instruments are switched off by the reconfiguration module after a level 4 alarm. *(PDF p. 18)*
- SPIRE event reports use APIDs 0x0500 (prime) and 0x0501 (redundant), so each SPIRE failure case needs two EAT entries. *(PDF p. 21)*
- Spacecraft 1553B bus FDIR events (for example 152 DLL, 171 TFL TC, 185 TFL TM for SPIRE) come from CDMS APID 0x0010. *(PDF p. 23)*
- PACS event reports use APIDs 0x0480 (prime) and 0x0481 (redundant). *(PDF p. 40)*
- LFI event reports use a single APID, 0x0600, for prime and redundant. *(PDF p. 97)*
- SCE event reports use APIDs 0x0680 (prime) and 0x0681 (redundant). *(PDF p. 109)*
- SPIRE internal FDIR events (TM(5,2)) 0xC000 (DRCU anomaly), 0xC010 (DPU power anomaly), 0xC100 (operations anomaly) and 0xC110 (operations resume) start the DRCU_OFF, OFF, OPE_STOP and OPE_RESUME OBCPs via TC(18,3). *(PDF p. 21)*
- Example OBCP DB_OBCP_H_SPIRE_DRCU_OFF (ID 0x1102, time-out 600 s TBC) stops conflicting OBCPs with TC(18,4), disables EAT entries with TC(19,5), disables SPIRE sub-schedule releases with TC(11,2), and switches off the SPIRE HSFCU LCLs with TC(8,4,112,3). *(PDF p. 27)*
- OBCP IDs are grouped by instrument, for example SPIRE 0x1102-0x1107, PACS 0x1208-0x120C and HIFI 0x130D-0x130E; the Herschel mode-transition mother OBCP DB_H_PL_SC_MODE_OBCP has ID 0x0001. *(PDF p. 81)*
- Planck OBCP IDs continue the scheme: HFI 0x2102-0x2103, LFI 0x2204-0x2205, SCE 0x2306-0x2308, and DB_P_PL_SC_MODE_OBCP is also 0x0001 (time-out 30 s TBC; all Planck instruments 'do nothing'). *(PDF p. 122)*
- HIFI requests no CDMS support for internal failures; for 1553B bus FDIR events 151, 170 and 184 it requests a reset (DB_OBCP_H_HIFI_RESET). *(PDF p. 71)*
- Section 6 maps the OBCP parameters (sub-schedule IDs, payload side, restart indices, temporary outputs) to data pool IDs DID_OBCP_32_OFFSET_000 to _110. *(PDF p. 123)*
- Open issues: which verification reports OBCP-generated TCs should request (including TM(1,9)), and a suggested limit of one TC per second per OBCP to reduce TM(1,x) load. *(PDF p. 123)*
