## Summary

The CCSDS Recommended Standard for the **Data Link Layer of [Proximity-1](../ccsds/proximity-1.md)**. Proximity-1 is the bi-directional protocol for short-range links among landers, rovers, orbiters and relays, characterised by short delays, moderate signals and short, independent sessions. The C&S sublayer (211.2-B) and the Physical Layer (211.1-B) are specified in separate books. This book defines the Frame, Medium Access Control (MAC), Data Services and Input/Output sublayers, the timing services and the COP-P reliability procedure.

Section 3 specifies the **Version-3 Transfer Frame**: a 5-octet header plus up to 2043 octets of data. The header fields are the Version Number `10`, QoS indicator, PDU Type ID, Data Field Construction ID, 10-bit SCID, PCID, Port ID, Source-or-Destination ID, Frame Length and Frame Sequence Number. U-frames carry user data and P-frames carry supervisory PDUs (directives, the PLCW, time distribution and status reports). Issue 6 lets the Version-4 (USLP) frame replace it. Section 4 describes the sublayers: MAC persistence (hailing, COMM_CHANGE, resynchronisation), the Sequence Controlled (go-back-n ARQ) and Expedited qualities of service, and port-based delivery. Section 5 specifies time-tag recording at the ASM trailing edge and the transfer of time to a remote asset. Section 6 gives the full-duplex, half-duplex and simplex state tables. Section 7 gives the FOP-P and FARM-P with their modulo-256 variables. Section 8 covers I/O operations.

The annexes contain:

* a PICS proforma;
* the SPDU directive formats (SET TRANSMITTER/CONTROL/RECEIVER PARAMETERS, SET V(R) and others);
* the Management Information Base parameters;
* the vehicle-controller notifications;
* security and SANA notes;
* Mars Odyssey and MRO (Electra) compatibility notes;
* a data-format hierarchy.


## Key points

- Issue 6 (July 2020) adds the use of the Version-4 (USLP) Transfer Frame; Editorial Change 1 (September 2024) fixes heading numbering in sections 2 and 6. *(PDF p. 7)*
- Proximity links are short-range, bi-directional, fixed or mobile radio links among probes, landers, rovers, orbiting constellations and relays, with short delays, moderate signals and short, independent sessions. *(PDF p. 12)*
- The Data Link Layer has five sublayers: Coding and Synchronization (specified in 211.2-B), Frame, Medium Access Control, Data Services (which contains COP-P) and Input/Output. *(PDF p. 22)*
- Addressing uses a triad: the SCID (source or destination, according to the Source-or-Destination Identifier), the PCID (selects one of two redundant receivers) and the Port ID (routes user data to logical or physical ports, including hardware command decoders). *(PDF p. 25)*
- The PLTU uses a 24-bit ASM and a CRC-32; idle data between variable-length PLTUs maintains symbol synchronisation. *(PDF p. 25)*
- Two data transfer services exist: packet delivery (packets with a CCSDS-authorised PVN, segmented and reassembled if needed) and user-defined data delivery (octets, not reassembled), plus timing services. *(PDF p. 26)*
- Sequence Controlled service is a go-back-n ARQ using the PLCW report and guarantees no loss, duplication or misordering within a session; Expedited service has no ARQ and suits upper layers with their own retransmission or spacecraft recovery. *(PDF p. 27)*
- A Version-3 Transfer Frame is a 5-octet header plus a data field of up to 2043 octets; the header holds Version (2 bits, value '10'), QoS (1), PDU Type ID (1), DFC ID (2), SCID (10), PCID (1), Port ID (3), Source-or-Destination ID (1), Frame Length (11) and Frame Sequence Number (8). *(PDF p. 30)*
- QoS '0' marks Sequence Controlled and '1' Expedited frames; PDU Type '0' is a U-frame (user data) and '1' a P-frame (SPDUs). *(PDF p. 32)*
- U-frame DFC ID: '00' integer number of unsegmented packets, '01' segment data, '10' reserved, '11' user-defined data. *(PDF p. 33)*
- Segmented packets carry an 8-bit segment header: 2 sequence flags ('01' first, '00' continuing, '10' last, '11' unsegmented) and a 6-bit pseudo packet ID; only complete packets are delivered. *(PDF p. 38)*
- SPDU types: Type 1 (directives, reports, PLCW), Type 2 (time distribution), Type 3 (enterprise-specific status reports of 0 to 15 octets). *(PDF p. 43)*
- The Version-4 (USLP) Transfer Frame may replace the Version-3 frame over the Proximity-1 C&S sublayer, with USLP taking over the Frame Sublayer functions. *(PDF p. 44)*
- MAC persistent activities (hailing, COMM_CHANGE and resynchronisation) repeat a directive until the expected RESPONSE arrives within a WAITING_PERIOD; their parameters come from the MIB. *(PDF p. 47)*
- Time tags are recorded at the trailing edge of the last ASM bit of every incoming and outgoing frame; collection is triggered by a SET CONTROL PARAMETERS directive, and time correlation itself is outside the standard's scope. *(PDF p. 55)*
- COP-P uses modulo-256 single-octet variables, with FOP-P variables VE(S), V(S), VV(S), N(R) and NN(R), and a SYNCH_TIMER that triggers resynchronisation when no valid PLCW arrives. *(PDF p. 96)*
- A Type 1 SPDU holds up to seven 16-bit self-identifying directives (Directive Type in bits 13-15, kept for compatibility with Mars Odyssey). *(PDF p. 119)*
- Annex C lists the Management Information Base parameters (for example Hail_Lifetime, Carrier_Only_Duration, Comm_Change_Waiting_Period) with the sublayer that uses each. *(PDF p. 141)*
- Security is left to layers above or below; SANA action is not required, and no patents are known to apply. *(PDF p. 148)*
- Mars Odyssey's convolutional code lacks the G2 inversion; its UHF CW beacon frequencies are 437.1000, 440.7425, 444.3850 and 448.0275 MHz, with 401.585625 MHz for the lander. *(PDF p. 149)*
- For symbol rates above 512 ks/s, projects interoperating with MRO's Electra radio should consider NRZ-L instead of Bi-Phase-L. *(PDF p. 157)*
