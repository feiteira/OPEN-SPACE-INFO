## Summary

A short CCSDS Magenta Book that adds the **Return All Frames (RAF)**-specific part of the SLE Application Program Interface. The generic C++ API (component model, service instances, operation objects, proxies) is defined in the API core specification [CCSDS 914.0-M-2](../library/ccsds-914-0-914x0m2c1.md). This book adds only the RAF-specific classes, interfaces, checks and status handling needed to build RAF users and providers on top of it. The service itself is specified in the RAF Blue Book, cited here as issue 3 (the library holds [issue 5](../library/ccsds-911-1-911x1b5e1.md)). The wiki pages are [SLE over TCP/IP and the SLE API](../ccsds/sle/isp1-and-api.md) and [SLE return services](../ccsds/sle/return-services.md).

Section 1 states that the API supports three RAF generations, identified by BIND version numbers 1, 2 and 4. Generation 1 interoperates through ESOC's earlier TCP/IP proxy specification, and Generations 2 and 3 through the ISP1 transport mapping (CCSDS 913.1-B-2). Section 2 extends the API model. RAF SI User and RAF SI Provider classes are added, and the provider exports the IRAF_SIAdmin (configuration: delivery-mode, latency-limit, transfer-buffer-size) and IRAF_SIUpdate (lock statuses, production status) interfaces. Five RAF operation objects are added (START, TRANSFER-DATA, SYNC-NOTIFY, STATUS-REPORT, GET-PARAMETER), and a security section covers privacy, integrity, authentication levels and threats. Section 3 gives the normative behaviour: configuration rules, how frame counters and requested-frame-quality are maintained, the START time-window checks per delivery mode, and SYNC-NOTIFY restrictions. Annex A gives the C++ type definitions and interfaces.


## Key points

- The API core specification (CCSDS 914.0-M-2) defines a C++ API for SLE transfer services at a generic level. Each service needs a supplementary Recommended Practice, and this one covers RAF. *(PDF p. 9)*
- The API supports three RAF generations: Generation 1 (BIND version 1, draft RAF 911.1-R-1.7), Generation 2 (version 2, RAF B-2) and Generation 3 (version 4, RAF B-3). Support for Generations 1 and 2 is for backward compatibility for a limited time. *(PDF p. 10)*
- Generation 1 implementations interoperate with peers that follow ESOC's 'Specification of a SLE API Proxy for TCP/IP and ASN.1' (SLES-SW-API-0002-TOS-GCI, Issue 1.1, February 2001). Generations 2 and 3 use the ISP1 transport mapping layer. *(PDF p. 10)*
- The RAF SI Provider class exports IRAF_SIAdmin for RAF configuration parameters and IRAF_SIUpdate for dynamic status. It answers RAF-GET-PARAMETER and generates RAF-STATUS-REPORT autonomously. *(PDF p. 17)*
- The RAF configuration parameters are delivery-mode, latency-limit (for the timely and complete online modes) and transfer-buffer-size, which is the maximum number of TRANSFER-DATA and SYNC-NOTIFY invocations per transfer buffer PDU. *(PDF p. 28)*
- The status information comprises number-of-error-free-frames-delivered, number-of-frames-delivered, requested-frame-quality, the frame-sync, symbol-sync, subcarrier and carrier lock statuses, and the production-status. *(PDF p. 21)*
- RAF-specific operation objects are IRAF_Start, IRAF_TransferData, IRAF_SyncNotify, IRAF_StatusReport and IRAF_GetParameter. BIND, UNBIND, STOP, SCHEDULE-STATUS-REPORT, PEER-ABORT and the TRANSFER-BUFFER pseudo-operation use the common SLE operation objects. *(PDF p. 22)*
- SLE transfer authentication can be set to one of three levels: every invocation and return, only BIND, or none. *(PDF p. 25)*
- Frame counters are incremented when a TRANSFER-BUFFER PDU is sent to the user. Frames in a discarded buffer are not counted. *(PDF p. 30)*
- For RAF-START in offline mode, the start and stop times must not be null and the stop time must be in the past. In online mode, the times must lie within the scheduled provision period. *(PDF p. 32)*
- In offline mode, RAF-SYNC-NOTIFY may not report loss of frame sync, a production status change or data discarded for excessive backlog. In timely online mode, data discard for excessive backlog is not allowed. *(PDF p. 33)*
