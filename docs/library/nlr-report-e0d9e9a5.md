## Summary

An NLR technical publication, a reprint of SpaceOps 2006 paper AIAA-2006-590, on how Dutch Space built and used a DOORS-based **ACMS Operations Database** for the Attitude Control and Measurement System of [Herschel and Planck](../missions/herschel-planck.md). The paper covers the missions and the industrial team: Terma wrote the application software (ASW) and the [SCOS-2000](../scos2000/index.md)-based Herschel/Planck Central Checkout System (HPCCS), and GMV built the Herschel/Planck System Data Base (HPSDB). It then describes the [PUS](../ecss/pus/index.md) services most relevant to the ACMS: [service 3](../ecss/pus/st03-housekeeping.md) housekeeping built on a datapool, [service 5](../ecss/pus/st05-event-reporting.md) events and [service 8](../ecss/pus/st08-function-management.md) function management.

The database was created in phase B. The reasons given are that the telemetry definition document had become unmaintainable, the HPSDB was immature, and using SCOS-2000 in the ACMS test equipment ([SCOS-2000 as EGSE](../scos2000/egse.md)) required every TM/TC detail to be defined. The SCOS-2000 MS Access database editor was rejected because it supports only one mission and has no object-level configuration control. The DOORS module architecture deliberately mirrors the SCOS-2000 [MIB tables](../mib/data-model.md). There are parameter modules (parameter types with [PTC/PFC](../mib/parameter-types.md), units, enumerations, numerical conversions), TC modules (command characteristics, packet structures, datapool identifiers) and TM modules (packet identification criteria, packet identifiers, packet structures, alphanumeric displays), mapped onto CCF, CDF, PCF, PID, PLF, PIC, TPCF, CAF, MCF, TXF and other tables. Operational identifiers are built from HPSDB box numbers, for example AESMG002 for Herschel and AESMG003 for Planck.

Each object carries spacecraft, software and from/to version attributes. This lets per-version SCOS-2000 `.dat` files and HPSDB XML be generated from one source, with exports kept in CVS instead of DOORS baselines. The paper also describes generating Tcl test code and checking HPSDB-generated `.dat` files against the AIT ones with a 'ccsdiff' script. It ends with lessons learned, including a call for a standardised database design for operations and test data.


## Key points

- The ACMS Test Equipment uses the SCOS-2000 based Herschel/Planck Central Checkout System, giving commonality between tools and data in subsystem and system testing and in operations. *(PDF p. 1)*
- AAS-F is prime for both satellites, AAS-I is Service Module responsible, Dutch Space (with Sener and Analyticon) is responsible for the ACMS; Terma (Denmark) develops the ASW, Saab Ericsson Space the Basic Software, Terma (Netherlands) the HPCCS and GMV (Spain) the HPSDB. *(PDF p. 9)*
- Herschel/Planck TM/TC are based on the ESA PUS; the services most relevant for ACMS operations are service 3 (housekeeping, generated by the BSW from a datapool), service 5 (events from ASW and BSW) and service 8 (function management, mostly ASW). *(PDF p. 10)*
- The ASW On-Board DataBase (OBDB) holds descriptions and values of over 3000 parameters; the ASW Specification exceeds 500 pages generated from DOORS. *(PDF p. 10)*
- A later datapool interface let the ASW define its own 16/32/64-bit datapool entries and identifiers independently of the BSW; the ASW datapool definition is exported from the ACMS Operations Database. *(PDF p. 11)*
- The HPSDB defines data at element, subsystem, model and generic levels, with theoretical and real 'boxes' and logical and physical instantiation; Dutch Space supplied ACMS input in HPSDB-compatible XML instead of using the HPSDB directly. *(PDF p. 11)*
- EuroSim in the ACMS Test Equipment is commanded and monitored by the HPCCS using Remote Messages and Remote Commands (RM/RC) that have the same format as spacecraft TM/TC. *(PDF p. 12)*
- The SCOS-2000 MS Access database was rejected: it supports a single mission only (not two missions plus common data), lacks object-level configuration control and cannot relate ASW TM/TC to the ASW Specification. *(PDF p. 12)*
- The 'Parameter types' module stores for each type a short identification (e.g. uint16, enum8), number of bits and the PTC/PFC; parameter units are limited to four characters in SCOS-2000. *(PDF p. 13)*
- The DOORS modules map onto SCOS-2000 MIB tables such as CCF, CDF, PCF, PID, PLF, PIC, TPCF, TXP, TXF, PAS, PAF, CAF, CAP, CCA, CCS, CPC and MCF (Fig. 2). *(PDF p. 13)*
- Operational identifiers are constructed from HPSDB box numbers: ACMS mode parameters start with 'AESMG', and the Herschel and Planck ASW box numbers 002 and 003 give AESMG002 and AESMG003. *(PDF p. 14)*
- Every object carries S/C (Herschel, Planck or Common), VersionSW, VersionFrom and VersionTo attributes, used to build version-specific SCOS-2000 and HPSDB files from the same CSV exports; formal exports are kept in CVS rather than DOORS baselines. *(PDF p. 17)*
- SCOS-2000/HPCCS .dat files generated by the HPSDB are compared with those used during ACMS AIT using Dutch Space's 'ccsdiff' script. *(PDF p. 18)*
- Recommendations include integrating the database with specifications, ICDs and test development, keeping identifiers independent but traceable across activities, versioning every object, using inheritance and instantiation, and standardising a database design for operations and test data. *(PDF p. 18)*
