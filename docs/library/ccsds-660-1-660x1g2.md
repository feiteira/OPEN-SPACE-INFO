## Summary

A 270-page CCSDS Green Book that explains, element by element, how to use the **XTCE 1.2** XML schema adopted by [CCSDS 660.0-B-2](../library/ccsds-660-0-660x0b2.md). It expands the terse annotations of the OMG schema without contradicting them, and it is the companion of the high-level introduction CCSDS 660.2-G-2. The page [XTCE](../ccsds/xtce.md) uses it.

Section 2 describes what an XTCE mission database holds: parameters and their ParameterTypes (link encoding, alarms, calibration), containers built by inheritance, and commands with arguments. It also lists the changes from XTCE 1.1 to 1.2, such as local array dimension sizes, byte-order options, a new numeric alarm, XInclude and time association in container entries. Section 3 covers the core mechanics: NameReference path rules, NameDescriptionType, comparisons, BooleanExpression, MatchCriteria, ParameterInstanceRef and size-related elements. Section 4 is the reference body. It goes through SpaceSystem and Header, then the ten ParameterTypes (string, enumerated, binary, boolean, integer, float, absolute/relative time, array, aggregate) with their encodings, calibrators and alarms, with recommended encoding tables for IEEE754 and MIL-STD-1750A. It then covers ParameterSet, SequenceContainer EntryList and BaseContainer inheritance, Message/Stream/Algorithm sets, MetaCommand (arguments, CommandContainer, constraints, verifiers) and ServiceSet. Sections 5-7 give advanced topics and patterns: abstract and concrete containers, dynamic matching, MetaCommand inheritance, pseudo-parameters, and packet and command patterns with optional secondary headers. Section 8 is a JAXB data-binding case study, and section 9 and Annex A give a complete telemetry and command example. For SCOS-2000 users, the closest equivalents are the [MIB data model](../mib/data-model.md) and its [packet identification](../mib/monitoring.md).


## Key points

- Issue 2 (August 2021) is current and supersedes 660.1-G-1 (May 2012). It updates the report from XTCE 1.1 to XTCE 1.2 and accompanies the introduction CCSDS 660.2-G-2. *(PDF p. 6)*
- XTCE 1.0 was published in 2006 and XTCE 1.1 later in 2006, after a CCSDS review; XTCE 1.2 followed in 2019. *(PDF p. 19)*
- In XTCE 1.2, array dimensions and their sizes are declared in the ArrayParameterType. In 1.1, only the number of dimensions was declared there, and the sizes were given where the array was used in a container. *(PDF p. 19)*
- Other changes in 1.2 include new byte-order options, integer exponents, a revised string length specification, a new numeric alarm, an inside/outside alarm flag, XInclude support, and time association moved to the container entry. *(PDF p. 19)*
- The top-level structure is SpaceSystem, containing TelemetryMetaData, CommandMetaData and optional recursive child SpaceSystems. *(PDF p. 21)*
- A NameReference without a path looks in the local SpaceSystem first and then in each ancestor SpaceSystem. A qualified NameReference uses a Unix-like SpaceSystem path. *(PDF p. 22)*
- There are ten ParameterTypes: the scalar String, Enumerated, Binary, Boolean, Integer, Float and time types, and the complex Array and Aggregate ('struct') types. *(PDF p. 109)*
- Members of an aggregate are referenced as 'AggregateName.MemberName'. *(PDF p. 154)*
- FloatDataEncoding supports the IEEE754_1985 and MILSTD_1750A formats. The recommendation tables show how to encode 32-, 64- and 128-bit values. *(PDF p. 157)*
- The basic telemetry pattern is one abstract 'Generic Packet' header container with every specific packet derived from it through RestrictionCriteria. An optional secondary header can be added through a container entry reference (printed 'ContainerEntryRef') with an IncludeCondition. *(PDF p. 259)*
- There are three command patterns. In the simple one, the MetaCommand's CommandContainer uses FixedValueEntry for opcodes. In the complex one, an abstract mission command template is specialised. In the generic one, there is an extra level of template inheritance. *(PDF p. 262)*
- Annex B gives corrected schema keys that enforce XTCE 1.2's @name uniqueness policy. Many of the XTCE 1.1 keys were broken. *(PDF p. 284)*
