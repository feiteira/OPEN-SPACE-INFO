## Summary

The CCSDS Green Book that explains the concepts behind the [TM Synchronization and Channel Coding](../ccsds/tm-coding.md) Blue Book and the rationale for its choices. It is a tutorial and performance reference, not a specification. Section 2 places channel coding in the layered CCSDS telemetry model: packets go into fixed-length [TM Transfer Frames](../ccsds/tm-sdlp.md), an Attached Sync Marker precedes each frame or codeblock, and coding protects the frames. Section 3 introduces the recommended code families and the BER, WER and FER performance measures on the AWGN channel, with Shannon capacity and sphere-packing bounds for comparison.

One chapter covers each code family:

* **Convolutional codes**: the (7,1/2) code, its punctured rates (2/3, 3/4, 5/6, 7/8), Viterbi decoding, soft quantisation and truncation length.
* **Reed-Solomon codes**: the (255,223) E=16 and (255,239) E=8 codes over GF(2^8), symbol interleaving, virtual fill and shortening, and hard algebraic decoding.
* **Concatenated RS + convolutional coding**, including frame lengths for each interleaving depth.
* **Turbo codes**: the encoder, the iterative decoder, performance for rates 1/2 to 1/6, error floors and burst erasures.
* **LDPC codes**: the near-Earth C2 code and the deep-space AR4JA family, their encoders and decoders.

Chapter 9 covers the ancillary functions an implementer of a ground decoder or frame synchroniser needs: the pseudo-randomiser (h(x) = x^8+x^7+x^5+x^3+1) and its spectral problems at high data rates, frame synchronisation for each code, the CCSDS CRC-16 used as the FECF, code transparency and NRZ-L/NRZ-M conversion. Annexes give a glossary, soft-decision quantisation strategies and the rationale for the turbo-code parameters. The 72-entry bibliography is the classic coding literature behind the standard.


## Key points

- The report is informational only; in case of conflict the TM Synchronization and Channel Coding Recommended Standard (CCSDS 131.0-B-3, its reference [3]) prevails. *(PDF p. 13)*
- The TM Transfer Frame is fixed-length to ease synchronisation on weak space-ground signals and to suit block-oriented codes; an Attached Synchronization Marker signals the start of each frame. *(PDF p. 23)*
- Recommended codes: the constraint-length-7 rate-1/2 convolutional code and its punctured versions; the (255,223) and (255,239) Reed-Solomon codes and their shortenings; RS+convolutional concatenations; and families of Turbo and LDPC codes. *(PDF p. 26)*
- Code performance is reported on the AWGN channel against Eb/N0 using three measures: BER, WER (codeword error rate) and FER. *(PDF p. 27)*
- The (7,1/2) convolutional code achieves free distance dfree = 10, which no other rate-1/2 code with K &lt;= 7 matches. *(PDF p. 32)*
- Both RS codes use the field generator polynomial F(x) = x^8+x^7+x^2+x+1; their code generator polynomials are self-reciprocal, which simplifies the encoder. *(PDF p. 47)*
- Frame lengths for RS interleaving depths I = 1, 2, 3, 4, 5 and 8 are 1784 to 14272 bits for E=16 and 1912 to 15296 bits for E=8 (Table 6-1). *(PDF p. 58)*
- Turbo-code performance is shown for rates 1/2, 1/3, 1/4 and 1/6 with information block lengths 1784, 3568, 7136 and 8920 bits (10 decoder iterations). *(PDF p. 74)*
- Two LDPC sets were chosen: a quasi-cyclic high-rate code (C2, a modified regular (4,32) code) for near-Earth links and nine AR4JA codes (rates 1/2, 2/3, 4/5; k = 1024, 4096, 16384) for deep space. *(PDF p. 84)*
- The pseudo-randomiser uses h(x) = x^8+x^7+x^5+x^3+1, repeats every 255 bits and is reset to all ones at the start of each codeblock, codeword or frame; its first 40 bits are 1111 1111 0100 1000 0000 1110 1100 0000 1001 1010. *(PDF p. 98)*
- At high data rates, the short (N = 255) standard randomiser applied to zero-filled idle frames can produce spectral spurs that break ITU power-flux-density limits, so a longer LFSR may be needed. *(PDF p. 98)*
- The CCSDS CRC-16 used for the Frame Error Control Field has generator polynomial G(X) = X^16 + X^12 + X^5 + 1. *(PDF p. 111)*
- Optional NRZ-L to NRZ-M conversion at the transmitter (and its inverse at the receiver) resolves phase ambiguity: NRZ-M represents a '1' by a change of level. *(PDF p. 116)*
