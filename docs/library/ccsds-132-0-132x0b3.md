## Summary

The CCSDS Recommended Standard for the **TM Space Data Link Protocol**, the data link protocol that carries telemetry on almost every ESA and NASA science mission. It defines the fixed-length TM Transfer Frame and the services built on it. The frame is cut into Virtual Channels and Master Channels, and it carries [Space Packets](../ccsds/space-packet.md) or [Encapsulation Packets](../ccsds/encapsulation.md). Each frame is coded and synchronised by the [TM Synchronization and Channel Coding](../ccsds/tm-coding.md) sublayer below it.

Section 2 explains the concepts: Physical, Master and Virtual Channels, GVCID addressing, and the asynchronous, synchronous and periodic service types. Its tables summarise the eight services (VCP, VCA, VC_FSH, VC_OCF, VCF, MC_FSH, MC_OCF, MCF) and the [SDLS](../ccsds/sdls.md) protection each one can get. Section 3 defines each service's parameters and primitives.

Section 4 is the core for anyone writing a frame decoder. It defines the 6-octet primary header (version '00', 10-bit SCID, 3-bit VCID, OCF flag, 8-bit MC and VC frame counts, and the data field status with the secondary-header flag, sync flag, packet order flag, segment length ID and 11-bit First Header Pointer). It also covers the optional secondary header of up to 64 octets, packet packing and spanning across frames, Only Idle Data frames filled with a 32-bit LFSR pattern, the 4-octet Operational Control Field (Type-1 for the [COP-1](../ccsds/cop-1.md) CLCW, Type-2 for project use or SDLS Frame Security Reports) and the CRC-16 Frame Error Control Field. The sending-end and receiving-end functions are modelled as packet processing, VC generation and multiplexing, MC generation and multiplexing, and all-frames generation. Section 5 lists the managed parameters per Physical Channel, Master Channel, Virtual Channel and packet transfer. Section 6 specifies the frame with SDLS security header and trailer, and the annexes give the PICS proforma and the OID randomizer logic.


## Key points

- Issue 3 (October 2021) adds support for the SDLS Extended Procedures (355.1-B-1), a normative PICS proforma (annex A) and informative OID randomization options (annex D). *(PDF p. 7)*
- TM Transfer Frames are fixed-length on a Physical Channel during a Mission Phase, which keeps synchronization simple and robust on weak, noisy links. *(PDF p. 18)*
- Eight services: VCP (asynchronous, SAP = GVCID + PVN), VCA, VC_FSH, VC_OCF, VCF, MC_FSH, MC_OCF and MCF; the MC services are addressed by MCID, the VC services by GVCID (Table 2-1). *(PDF p. 23)*
- Frame structure: Primary Header (6 octets), optional Secondary Header (up to 64 octets), Data Field, optional Operational Control Field (4 octets) and optional Frame Error Control Field (2 octets). *(PDF p. 60)*
- Primary header layout: Version (2 bits, '00'), SCID (10 bits), VCID (3 bits), OCF Flag (1 bit), MC Frame Count (8 bits), VC Frame Count (8 bits) and Transfer Frame Data Field Status (16 bits). *(PDF p. 61)*
- TM and TC frames share version number '00' and are told apart by the ASM (TM) or the Start Sequence (TC). *(PDF p. 62)*
- MC and VC Frame Counts are modulo-256 counts that should not be reset before reaching 255 unless unavoidable; a reset makes the completeness of the frame sequence undeterminable. *(PDF p. 63)*
- Data Field Status: Secondary Header Flag, Synchronization Flag ('0' for packets or idle data, '1' for a VCA_SDU), Packet Order Flag, Segment Length Identifier (set to '11' when the sync flag is '0') and an 11-bit First Header Pointer. *(PDF p. 64)*
- First Header Pointer: offset of the first packet that starts in the data field; '11111111111' if no packet starts in the frame; '11111111110' for an Only Idle Data (OID) frame. *(PDF p. 66)*
- OID frame data fields are filled with a PN sequence from a 32-cell LFSR, D0 + D1 + D2 + D22 + D32, that is never restarted; the first bytes are FF FF FF FF 6D B6 D8 61 45 1F. *(PDF p. 69)*
- OCF Type Flag (bit 0): '0' means a Type-1 report holding a CLCW; '1' means a Type-2 report, where bit 1 selects project-specific content ('0') or an SDLS Frame Security Report ('1'). *(PDF p. 71)*
- The FECF is a 16-bit CRC appended as the last 16 bits of the frame; its presence is set by management for the whole Physical Channel during a Mission Phase. *(PDF p. 71)*
- Managed parameters per Physical Channel include the frame length, TFVN (1), valid SCIDs, MC multiplexing scheme and FECF presence; valid VCIDs are 0 to 7 and MC_FSH length is 2 to 64 octets. *(PDF p. 88)*
- With SDLS, a Security Header and Security Trailer surround the Data Field on Virtual Channels where a managed parameter says SDLS is in use; the primary and secondary headers are unchanged. *(PDF p. 91)*
