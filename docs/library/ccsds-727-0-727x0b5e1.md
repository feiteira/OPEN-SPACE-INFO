## Summary

The CCSDS Recommended Standard for the **CCSDS File Delivery Protocol (CFDP)**. CFDP transfers files between filestores on spacecraft and on the ground, and between spacecraft. It runs over any packet delivery service, which the standard abstracts as the Unitdata Transfer (UT) layer. That layer can be CCSDS TC and TM packet services, AOS, Space Packets, Encapsulation packets, the Bundle Protocol or ground networks. CFDP is described on the wiki page [CFDP](../ccsds/cfdp.md). For on-board file handling in PUS, see also [ST[23] File management](../ecss/pus/st23-file-management.md); this standard itself does not mention PUS.

Issue 5 restructures the protocol. It removes the Extended Procedures and the service classes 3 and 4. It moves Store and Forward Overlay operations to normative Annex B. It adds large files (64-bit offsets), multi-segment records with per-segment metadata, and a choice of checksum algorithm from a SANA registry. Section 2 gives the architecture: entities, users, transactions, the virtual filestore and the Copy, Put and Proxy-Put interaction sequences. Section 3 defines the service primitives, such as Put.request and the indications. Section 4 specifies the procedures: the optional PDU CRC (the TC CRC), the 32-bit file checksum (modular, null or registry algorithms), Copy File procedures with NAKs, positive acknowledgement, fault handling, filestore actions, inactivity monitoring and link-state changes. Section 5 gives the bit-exact PDU formats: the fixed header, the file directive PDUs (EOF, Finished, ACK, Metadata, NAK, Prompt, Keep Alive), File Data PDUs and the TLV parameters. Section 6 defines user operations carried in reserved messages: proxy, directory listing, remote status report, suspend and resume. Section 7 defines Class 1 (unreliable) and Class 2 (reliable) transfer. Section 8 lists the CFDP Management Information Base, which is not the SCOS-2000 MIB. Annex A is the PICS and Annex F works a modular checksum example.


## Key points

- Issue 5 (July 2020) moves Store and Forward Overlay to normative Annex B, removes the Extended Procedures, adds large files, multi-segment records and per-segment metadata, and adds a choice of checksum from a new SANA registry. EC 1 (September 2024) fixes the heading numbering under 7.2.3. *(PDF p. 7)*
- CFDP is intended for CCSDS packet telecommand, packet telemetry and the AOS Path service, and also for ground networks. It works space-to-ground, ground-to-space and space-to-space. Service classes 3 and 4 have been deleted together with the Extended Procedures. *(PDF p. 12)*
- The fixed PDU header has these fields: Version (3 bits, '001' for the second protocol version), PDU type (directive/data), Direction, Transmission Mode (acknowledged/unacknowledged), CRC flag, Large File flag, PDU Data field length (16 bits), Segmentation control, Length of entity IDs (3 bits, octets minus one), Segment metadata flag, Length of Transaction sequence number (3 bits), then the variable-length source entity ID, transaction sequence number and destination entity ID. *(PDF p. 75)*
- A transaction is uniquely identified by the source entity ID together with the transaction sequence number. *(PDF p. 75)*
- File-Size Sensitive (FSS) fields, such as offsets and file size, are 32 bits when the Large File flag is 0 and 64 bits when it is 1. Files whose size cannot be held in an unsigned 32-bit integer, and all files of unbounded size, must be flagged 'large'. *(PDF p. 77)*
- Directive codes (hex): 04 EOF, 05 Finished, 06 ACK, 07 Metadata, 08 NAK, 09 Prompt, 0C Keep Alive; 00-03 and 0D-FF are reserved. *(PDF p. 78)*
- The 4-bit condition codes include 0000 No error, 0001 Positive ACK limit reached, 0101 File checksum failure, 0111 NAK limit reached, 1000 Inactivity detected, 1011 Unsupported checksum type, 1110 Suspend.request received and 1111 Cancel.request received. *(PDF p. 79)*
- The optional PDU CRC uses the standard CCSDS Telecommand CRC algorithm of the TC Space Data Link Protocol and covers the PDU from the first header octet up to the CRC. *(PDF p. 49)*
- Every file carries a 32-bit checksum. The modular checksum (type 0) and the null checksum (type 15) are mandatory; types 1-14 from the SANA Checksum Identifiers registry are optional. If the preferred type is unsupported, an Unsupported Checksum Type fault is raised. *(PDF p. 50)*
- There are two service classes: Class 1, Unreliable Transfer, and Class 2, Reliable Transfer. The state tables are in the CFDP Implementers Guide (720.2-G). *(PDF p. 108)*
- The CFDP MIB holds the local entity configuration (entity ID, which indications are required, default fault handlers) and, per remote entity, items such as the UT address, ACK/NAK/keep-alive timers, the default transmission mode, the check limit, the default checksum type, the maximum file segment length and the inactivity limit. *(PDF p. 116)*
- CFDP has no security mechanisms of its own; the UT-layer stack must provide them. The initial SANA checksum registry has 0 Modular, 1 Proximity-1 CRC32, 2 CRC-32c, 3 IEEE 802.3 FCS and 15 NULL. *(PDF p. 145)*
