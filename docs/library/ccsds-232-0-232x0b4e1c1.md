## Summary

The CCSDS Recommended Standard for the **TC Space Data Link Protocol**, the telecommand data link protocol used on the uplink of most ESA missions. It defines the variable-length TC Transfer Frame, the Communications Link Control Word (CLCW) that reports acceptance status back to the ground, and the services for sending [Space Packets](../ccsds/space-packet.md) and private data units on Virtual Channels and MAP channels. Retransmission is handled by [COP-1](../ccsds/cop-1.md) (CCSDS 232.1), and frames are coded into CLTUs by [TC Synchronization and Channel Coding](../ccsds/tc-coding-cltu.md).

Section 2 covers the channel tree (Physical, Master, Virtual and MAP channels), the Type-A (sequence-controlled) and Type-B (expedited) service types, and six data services: MAP Packet, VC Packet, MAP Access, VC Access, VC Frame and MC Frame. A COP Management service controls the FOP. Section 3 gives each service's primitives.

Section 4 specifies the PDUs. The 5-octet primary header holds the version ('00'), Bypass Flag, Control Command Flag, 2 spare bits, 10-bit SCID, 6-bit VCID, 10-bit Frame Length (total length minus one, so at most 1024 octets) and 8-bit Frame Sequence Number. The flag combinations give Type-AD, Type-BD and Type-BC frames. The optional Segment Header holds Sequence Flags and a 6-bit MAP ID for segmentation. The section also defines the Unlock and Set V(R) control commands and the CRC-16 FECF. The 32-bit CLCW carries COP in Effect, VCID, the No RF Available, No Bit Lock, Lockout, Wait and Retransmit flags, the FARM-B counter and the Report Value N(R). Section 4 then models the sending functions (MAP packet processing, MAP generation and multiplexing, VC generation and multiplexing, MC multiplexing, all-frames generation) and the matching receiving functions. Section 5 lists the managed parameters, and section 6 adds the [SDLS](../ccsds/sdls.md) security header and trailer and the order of processing between TC, COP-1 and SDLS.


## Key points

- Technical Corrigendum 1 (October 2023) expands and clarifies 6.5.2, the order of processing between TC, COP-1 and SDLS; this copy includes it. *(PDF p. 7)*
- Six data transfer services: MAP Packet (SAP = GMAP ID + PVN), VC Packet (GVCID + PVN), MAP Access, VC Access (all Type-A or Type-B), VC Frame and MC Frame; a COP Management service controls COP retransmission per Virtual Channel. *(PDF p. 24)*
- TC Transfer Frame = 5-octet Primary Header + Data Field (up to 1019 octets, or 1017 with FECF) + optional 2-octet Frame Error Control Field. *(PDF p. 69)*
- Primary header: Version (2 bits), Bypass Flag (1), Control Command Flag (1), Reserved Spare (2), SCID (10), VCID (6), Frame Length (10) and Frame Sequence Number (8). *(PDF p. 70)*
- Bypass/Control Command flags 0/0 = Type-AD (sequence-controlled data), 1/0 = Type-BD (expedited data), 1/1 = Type-BC (control commands); 0/1 is reserved. *(PDF p. 72)*
- Frame Length holds total frame octets minus one; the 10-bit field limits a TC frame to 1024 octets. *(PDF p. 73)*
- The Segment Header (Sequence Flags 2 bits + MAP ID 6 bits) is required on any VC with more than one MAP or carrying SDUs larger than one frame; it must not be present in frames carrying control commands. *(PDF p. 74)*
- Control commands: Unlock is a single all-zero octet; Set V(R) is three octets 10000010 00000000 followed by the new V(R) value. *(PDF p. 77)*
- The CLCW is 32 bits: Control Word Type '0', Version '00', Status Field (3), COP in Effect ('01' for COP-1), VCID (6), spare (2), the No RF Available, No Bit Lock, Lockout, Wait and Retransmit flags, FARM-B Counter (2), spare (1) and Report Value (8). *(PDF p. 81)*
- The CLCW is the only reporting mechanism of the protocol and is usually carried in the OCF of TM or AOS frames; each Virtual Channel in use has its own CLCW reporting. *(PDF p. 80)*
- Physical Channel managed parameters include the maximum frame length, TFVN 1, valid SCIDs, FECF presence, maximum frames per coding-sublayer data unit, maximum bit rate and maximum Repetitions. *(PDF p. 107)*
- Virtual Channel managed parameters include VCID 0 to 63, COP in Effect, CLCW reporting rate, Segment Header presence, valid MAP IDs 0 to 63, blocking, and the Repetitions values for Type-A data and for COP control commands. *(PDF p. 109)*
- At the receiving end with SDLS, FARM-1 runs first, then SDLS ProcessSecurity, then the rest of the Virtual Channel Reception Function (6.5.2, as amended by Cor. 1). *(PDF p. 120)*
