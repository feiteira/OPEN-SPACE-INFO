## Summary

A seven-page conference paper by D. Comi and R. Sala (Intecs SpA) and F. Insinga (Thales Alenia Space Italia) on the SRDB Translator, a tool that imports a SCOS-2000 MIB-format Satellite Reference Database (SRDB) into the database of ECHO, the TAS-I central checkout (EGSE) system.

The paper starts from the observation that SCOS-2000 has become the standard ESA mission control system and that SRDBs are therefore almost always based on the SCOS-2000 runtime database, while industrial checkout systems keep their own data models. It compares the two databases at the level of logical entities (monitoring parameters and calibrations, TM packets, displays, commands, verification and checks), explains why a one-to-one table mapping does not work, and classifies each item into data present in both, only in the SRDB, or only in ECHO. Two tables give concrete conversion rules: TC verification checks (stages not imported, verification window converted to milliseconds, raw-value checks discarded) and numerical calibration (10-character curve identifiers mapped to integers, radix conversion, point limits, polynomial boundaries, logarithmic curves, number of curves per parameter).

It then describes the tool: a utility of the ECHO Database Manager (MTGP) on MS SQL Server, compliant with SCOS-2000 ICD issue 6.1, with a two-step import (raw copy into staging tables, then stored procedures), merging with locally defined EGSE data and a result log. Applications are Galileo GIOVE-B, Sentinel-1 and BepiColombo (with OBC and SSMM database metrics). Limits (strict column matching across ICD issues) and future work (bidirectional transfer and an XML-based standard database exchange language) close the paper.


## Key points

- Because SCOS-2000 has become standard in ESA missions for control centres and in most cases EGSE, the Satellite Reference Database (SRDB) is almost always based on the SCOS-2000 run-time database. *(PDF p. 1)*
- The input SRDB covers monitoring data, TM packets (fixed and variable), displays and reports, command packets and sequences, and commanding data (verification, de-calibration, range checks); both databases base TM/TC packet definitions on the ECSS PUS. *(PDF p. 2)*
- A 1-to-1 mapping from one source table to one destination table is described as almost inapplicable; the comparison is made on logical entities. *(PDF p. 2)*
- TC verification conversion: SCOS-2000 verification stages are not imported, the SCOS-2000 window (start time and duration in seconds) becomes an ECHO maximum elapsed time in milliseconds computed as (start + interval) x 1000, and checks expressed as raw values are discarded. *(PDF p. 3)*
- Numerical calibration conversion: SCOS-2000 curve identifiers are Char(10) while ECHO uses Int 1..9999; hex and octal raw values are converted to decimal; ECHO point-by-point curves need 2 to 1000 points; the number of curves per parameter was extended from 4 to 99. *(PDF p. 4)*
- The current SRDB Translator is compliant with SCOS-2000 ICD Issue 6.1 and runs as a utility of the ECHO Database Manager (MTGP) on MS SQL Server. *(PDF p. 5)*
- The import first copies SCOS-2000 tables unchanged into staging tables, then converts them with stored procedures; a missing expected column aborts the whole import, as happened with BepiColombo databases built to an earlier ICD issue. *(PDF p. 6)*
- The first version was developed for Galileo GIOVE-B, whose SCOS-2000 database was delivered as a single MS Access 2000 file; an enhanced version was made for Sentinel-1 and reused on BepiColombo. *(PDF p. 6)*
- BepiColombo database metrics: OBC 3745 parameters, 521 TM packets, 399 TC packets; SSMM 1947 parameters, 1921 TM packets, 535 TC packets (about 10000 records each). *(PDF p. 6)*
- The authors propose a standard satellite-database exchange interface, for example an XML-based mark-up language, to ease data exchange among EGSE systems. *(PDF p. 7)*
