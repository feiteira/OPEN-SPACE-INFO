## Summary

The CCSDS Recommended Standard for the **Advanced Orbiting Systems (AOS) Space Data Link Protocol**. AOS is a Data Link Layer protocol with fixed-length frames that carries packets, bitstreams and other data over space-to-ground, ground-to-space and space-to-space links, mostly for high-rate return links. It sits beside the [TM](../ccsds/tm-sdlp.md) and [TC](../ccsds/tc-sdlp.md) protocols and below the [Space Packet](../ccsds/space-packet.md) and [Encapsulation](../ccsds/encapsulation.md) protocols. Frame length and synchronisation come from the [TM Synchronization and Channel Coding](../ccsds/tm-coding.md) sublayer (or FACM or DVB-S2). The wiki page is [AOS](../ccsds/aos.md).

Section 2 gives an overview of the protocol: Physical, Master and Virtual Channels, the services and the functions. Section 3 defines the seven services: Virtual Channel Packet (VCP), Bitstream, Virtual Channel Access (VCA), VC Operational Control Field (VC_OCF), Virtual Channel Frame (VCF), Master Channel Frame (MCF) and Insert. Section 4 specifies the AOS Version 2 Transfer Frame. Its 6- or 8-octet Primary Header carries a 2-bit Version '01', an 8-bit SCID, a 6-bit VCID, a 24-bit VC Frame Count, a Signaling Field (Replay Flag, VC Frame Count Cycle) and an optional RS(10,6) Frame Header Error Control. The frame also has an optional Insert Zone, a Data Field holding an M_PDU (11-bit First Header Pointer), a B_PDU (14-bit Bitstream Data Pointer) or a VCA_SDU, an optional 4-octet OCF and an optional 2-octet FECF. Section 4 then gives the sending and receiving procedures (multiplexing, idle data, OID frames on VCID 63). Section 5 tabulates the managed parameters, and section 6 restates the frame, procedures and parameters with the [SDLS](../ccsds/sdls.md) Security Header and Trailer.


## Key points

- The protocol provides seven services: Virtual Channel Packet, Bitstream, Virtual Channel Access, VC_OCF, Virtual Channel Frame, Master Channel Frame and Insert. *(PDF p. 22)*
- Issue 4 (October 2021) is current. It adds support for the SDLS Extended Procedures, a PICS proforma (Annex A) and OID frame randomization examples (Annex D). Issues B-1 (2003), B-2 (2006) and B-3 (2015) are superseded. *(PDF p. 7)*
- An AOS Transfer Frame consists of a Primary Header (6 or 8 octets), an optional Insert Zone, the Data Field, an optional 4-octet Operational Control Field and an optional 2-octet Frame Error Control Field. Its length is constant for a mission phase on a Physical Channel. *(PDF p. 56)*
- The Primary Header holds the Master Channel ID (2-bit Transfer Frame Version Number plus 8-bit Spacecraft ID), a 6-bit VCID, a 24-bit VC Frame Count, an 8-bit Signaling Field and an optional 2-octet Frame Header Error Control. *(PDF p. 57)*
- The Transfer Frame Version Number is '01', which denotes the AOS Version 2 Transfer Frame. SANA assigns the 8-bit Spacecraft ID according to CCSDS 320.0-M. *(PDF p. 58)*
- VCID 'all ones' (63) is reserved for Only Idle Data (OID) Transfer Frames. The valid user VCIDs are 0-62 and need not be consecutive. *(PDF p. 58)*
- The VC Frame Count is a 24-bit sequential count, modulo 16,777,216, of frames on each Virtual Channel. It must not be reset early unless that is unavoidable. *(PDF p. 59)*
- In the Signaling Field, the Replay Flag (bit 40) is 0 for realtime and 1 for replay frames. The VC Frame Count Cycle Use Flag and the 4-bit VC Frame Count Cycle extend the frame count. *(PDF p. 60)*
- The optional Frame Header Error Control (bits 48-63) is a shortened Reed-Solomon (10,6) code with 4-bit symbols and E=2 symbol-correction capability that can protect the 10-bit MCID, the 6-bit VCID and the 8-bit Signaling Field. *(PDF p. 62)*
- M_PDU header: bits 0-4 are a reserved spare and bits 5-15 are the First Header Pointer. 'All ones' means no packet starts in the frame, and 'all ones minus one' means idle data only. *(PDF p. 66)*
- B_PDU header: bits 0-1 are a reserved spare and bits 2-15 are the Bitstream Data Pointer. 'All ones' means the frame is full of valid data, and 'all ones minus one' means idle data only. *(PDF p. 68)*
- Managed parameters of a Physical Channel include the Transfer Frame Length, Version Number 2, the valid SCIDs, the MC multiplexing scheme, and the presence of FHEC, Insert Zone (with its length) and FECF. *(PDF p. 88)*
- The Data Field Content of each Virtual Channel is managed as one of M_PDU, B_PDU, VCA_SDU or Idle Data. The presence of the VC_OCF is also managed per Virtual Channel. *(PDF p. 89)*
- With SDLS, a managed parameter per Virtual Channel indicates the presence of the Security Header. The Security Header and Trailer surround the Data Field and shorten it. *(PDF p. 91)*
- The OID randomizer LFSR (Fibonacci or Galois form) is initialised only at device start-up, not per frame, and generates the pattern FF FF FF FF 6D B6 D8 61 45 1F ... *(PDF p. 112)*
