## Summary

A two-page fax sent on 27 March 2003 by the Alcatel Space Industries Herschel/Planck project office in Cannes to the five Herschel and Planck instrument teams (HIFI, SPIRE, PACS, HFI and LFI), with copies to ESTEC and ESOC. It follows up the January 2003 fax on the same subject (its REF3, library item `alc-scos-fax-2003-01-27`) and adds two further constraints that the instrument teams must respect when they build their SCOS-2000 Mission Information Base (MIB) files, so that instrument-level databases can be carried forward to module-level testing (the 'smooth transition').

The first rule concerns the `pid` table: each packet's `PID_SPID` must equal its `PID_TPSD`. The stated reason is the mapping between the Herschel/Planck System Database (HPSDB) and the SCOS 'bridge' files: different SCOS packets (SPIDs) will no longer be able to address the same variable packet structure definition (VPSD). The second rule concerns the `pcf` table: the width field (printed 'PCF-WIDTH') must not be null, because it is considered indirectly redundant with `VPD_OFFSET` and the HPSDB will only support `VPD_OFFSET`.

For an engineer the fax is a compact, real example of how a prime contractor tailored the generic SCOS-2000 Database Import ICD (issue 5.1, REF1) and the project naming convention (REF2) for a multi-instrument programme, and of the constraints that a central system database imposes on instrument MIBs. It asks the teams to report if the new requirements are incompatible with their implementation.


## Key points

- Purpose: support the 'smooth transition' from instrument test level to module test level; the requirements are additional to those listed in REF3 (H-P-ASP-LT-2607). *(PDF p. 1)*
- Requirement 5: in table 'pid' the fields PID_SPID and PID_TPSD shall be such that PID_SPID = PID_TPSD. *(PDF p. 1)*
- Justification 5: only to facilitate the mapping between HPSDB and the SCOS bridge files; different SCOS packets (SPID) will no longer be able to address the same variable packet structure definition (VPSD). *(PDF p. 2)*
- Requirement 6: in table 'pcf' the field 'PCF-WIDTH' shall not be set to 'Null'. *(PDF p. 1)*
- Justification 6: the field (printed 'PCF_WIDFT') is (indirectly) redundant with VPD_OFFSET, and HPSDB will only support VPD_OFFSET. *(PDF p. 2)*
- REF1 is the SCOS-2000 Data base import ICD S2K-MCS-ICD-0001-TOS-GCI issue 5.1; REF2 is the naming convention specification H-P-1-ASPI-SP-0141 issue 01/02. *(PDF p. 1)*
- Addressed to HIFI (K. Wafelbakker), SPIRE (K. King), PACS (O. Bauer), HFI (J. Charra) and LFI (C. Butler), with external copies to ESTEC and ESOC. *(PDF p. 1)*
- Document impact: REF2 will be updated accordingly. *(PDF p. 2)*
