## Summary

The CCSDS Recommended Standard for the **Return Channel Frames (RCF)** service of the [Space Link Extension](../ccsds/sle/index.md). RCF delivers to a mission user the telemetry frames of **one Master Channel or one Virtual Channel**, selected by a global VCID made of TFVN, SCID and VCID. The frames can be TM (TFVN '00'), AOS ('01') or, new in this issue, USLP ('1100'). RCF replaces the separate 'Return MC Frames' and 'Return VC Frames' services of the SLE Reference Model. It is the companion of [RAF](../library/ccsds-911-1-911x1b5e1.md) and is described on [SLE return services](../ccsds/sle/return-services.md).

Section 2 describes production. The Return Frame Processing functional group (RFP-FG) consumes a RAF data channel, discards every frame whose quality is not 'good' (Reed-Solomon/LDPC codewords valid, or FECF correct, or the USLP validation checks passed), demultiplexes by MC and VC, and annotates each SLE-SDU with the ERT, the antenna ID, the data-link continuity and an optional private annotation. Section 2 also covers service management, the timely online, complete online and offline delivery modes, buffering and security. Section 3 specifies the operations with their parameter tables and diagnostics: RCF-BIND (version number '6' for this issue, with version negotiation), UNBIND, START (start and stop time, requested-global-VCID), STOP, TRANSFER-DATA, SYNC-NOTIFY (loss of frame synchronization, production status change, data discarded due to excessive backlog, end of data), SCHEDULE-STATUS-REPORT, STATUS-REPORT, GET-PARAMETER and PEER-ABORT. Section 4 gives the provider state machine (unbound, ready, active). Annex A holds the seven ASN.1 modules, Annex B the production-status model and Annex C the conformance matrix. See [NCTRS/NIS](../scos2000/nctrs-nis.md) for how ESA's control centres connect to ground stations; this document does not name any ESA system.


## Key points

- Issue 4 (July 2023) adds support for USLP Transfer Frames; issues B-1 (2004), B-2 (2010) and B-3 (2016) are superseded; EC 1 (October 2024) repairs figure 2-3. *(PDF p. 6)*
- RCF delivers to a mission user all telemetry frames from one Master Channel or one Virtual Channel. It replaces the separate Return MC Frames and Return VC Frames services defined in the SLE Reference Model. *(PDF p. 9)*
- The communications service underneath RCF must deliver invocations and returns in sequence, complete, with integrity, without duplication, with flow control, and with notification of disruption. *(PDF p. 10)*
- The RFP-FG consumes one RAF data channel, discards every frame whose quality is not 'good', demultiplexes it into Master and Virtual Channels, and can store data for offline delivery. *(PDF p. 28)*
- A frame is 'good' if it contains only valid Reed-Solomon or LDPC codewords or, for uncoded frames, if its FECF decodes successfully. A USLP frame is 'good' if it passes the USLP Frame Validation Check Procedure, apart from the checks in 4.3.10.3.4 c). *(PDF p. 29)*
- Delivery modes: timely online, complete online or offline. Each service instance supports only one mode, which service management sets. *(PDF p. 27)*
- The version-number value for the RCF service defined by this issue is '6'. A responder that supports version negotiation may propose a lower version; otherwise the diagnostic is 'version not supported'. *(PDF p. 64)*
- The RCF-START parameters are invoker-credentials, performer-credentials, invoke-ID, start-time, stop-time and requested-global-VCID, plus result and diagnostic in the return. *(PDF p. 72)*
- requested-global-VCID is made of TFVN, SCID and VCID. The valid TFVNs are '00' (TM), '01' (AOS) and '1100' (USLP). The physical channel is selected through the service package, not through RCF. *(PDF p. 73)*
- RCF-TRANSFER-DATA carries invoker-credentials, earth-receive-time, antenna-ID, data-link-continuity, private-annotation and data. Unlike RAF, it has no delivered-frame-quality parameter. *(PDF p. 79)*
- earth-receive-time is the UTC time at which the leading edge of the first bit of the start sequence preceding the frame was at the phase centre of the receiving antenna. *(PDF p. 80)*
- SYNC-NOTIFY 'loss of frame synchronization' is sent once per lock-status observation period. There is no explicit notification when lock is regained, and it is never sent in offline mode. *(PDF p. 84)*
- The parameters readable by GET-PARAMETER are delivery-mode, latency-limit, minimum-reporting-cycle, permitted-global-VCID-set, reporting-cycle, requested-global-VCID, return-timeout-period and transfer-buffer-size. *(PDF p. 96)*
- Annex A defines seven ASN.1 modules: CCSDS-SLE-TRANSFER-SERVICE-COMMON-TYPES, -BIND-TYPES, -COMMON-PDUS, -SERVICE-INSTANCE-ID, -RCF-STRUCTURES, -RCF-INCOMING-PDUS and -RCF-OUTGOING-PDUS. *(PDF p. 115)*
