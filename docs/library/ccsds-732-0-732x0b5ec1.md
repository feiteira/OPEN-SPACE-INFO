## Summary

Issue 5 (October 2025, with Editorial Change 1) of the CCSDS Recommended Standard for the **AOS Space Data Link Protocol**. AOS is a Data Link Layer protocol with fixed-length frames for space-to-ground, ground-to-space and space-to-space links. It carries packets, bitstreams and other data. The wiki page is [AOS](../ccsds/aos.md). The structure is the same as issue 4 ([CCSDS 732.0-B-4](../library/ccsds-732-0-732x0b4.md)): an overview (Physical, Master and Virtual Channels, addressing by TFVN + SCID + VCID); seven services (Virtual Channel Packet, Bitstream, Virtual Channel Access, VC_OCF, Virtual Channel Frame, Master Channel Frame and Insert); the Transfer Frame and its sending and receiving procedures; managed parameters; the [SDLS](../ccsds/sdls.md) variant; a PICS proforma; and OID randomizer examples.

An engineer will look here mainly for what changed in issue 5, because the changes break bit-level compatibility with older decoders. The Spacecraft ID grows from 8 to 10 bits. Its two new most significant bits go in bits 42-43 of the Primary Header, which were the reserved spare of the Signaling Field in issue 4, so the MCID becomes 12 bits. The M_PDU header loses its 5-bit spare, and the First Header Pointer becomes a full 16 bits, which allows frames of up to 65,536 octets. The optional Frame Header Error Control moves from RS(10,6) to a shortened RS(15,11) code over GF(2^4), which also protects the SCID MSBs and the VC Frame Count Cycle. The Bitstream Data Pointer stays at 14 bits, so frames carrying B_PDUs are still limited to 16,384 bits. VCID 63 remains reserved for Only Idle Data frames. For identifiers and SANA registries see [space link identifiers](../ccsds/space-link-identifiers.md).


## Key points

- Issue 5 extends the SCID field in the Transfer Frame Primary Header to 10 bits and the First Header Pointer in the M_PDU header to 16 bits, to accommodate frames of up to 65,536 octets. Editorial Change 1 changes the Frame Header Error Control to a Reed-Solomon (15,11) code. *(PDF p. 7)*
- The addressing identifiers are TFVN, SCID and VCID: MCID = TFVN + SCID, and GVCID = MCID + VCID. A Physical Channel may carry several Master Channels with the same TFVN. *(PDF p. 18)*
- An AOS Transfer Frame consists of a Primary Header (6 or 8 octets), an optional Insert Zone, the Data Field, an optional 4-octet OCF and an optional 2-octet Frame Error Control Field. Its length is constant for a Mission Phase on a Physical Channel. *(PDF p. 54)*
- The 12-bit MCID is made of three non-contiguous fields: the 2-bit Transfer Frame Version Number, the 2 SCID MSBs and the 8 SCID LSBs. It occupies bits 0-9 and 42-43 of the Primary Header. *(PDF p. 55)*
- Bits 0-1 hold the Transfer Frame Version Number '01' (AOS Version 2 frame). Bits 2-9 hold the 8 SCID LSBs, and bits 42-43 hold the 2 SCID MSBs. Missions using issue 4 or earlier have an 8-bit SCID and set bits 42-43 to '00'. *(PDF p. 57)*
- Bits 10-15 hold the VCID. 'All ones' (63) is reserved for Only Idle Data frames, and VCIDs need not be consecutive. *(PDF p. 57)*
- The VC Frame Count (bits 16-39) is a 24-bit count modulo 16,777,216 per Virtual Channel. When used, the 4-bit VC Frame Count Cycle (bits 44-47) extends it to 28 bits. *(PDF p. 58)*
- The Signaling Field is now 2 bits (bits 40-41): the Replay Flag (0 = realtime, 1 = replay) and the VC Frame Count Cycle Use Flag. *(PDF p. 59)*
- The optional Frame Header Error Control (bits 48-63) is a Reed-Solomon (15,11) code over GF(2^4), shortened by 5 symbols to a binary (40,24) code with E=2. It protects the 12-bit MCID, 6-bit VCID, 2-bit Signaling Field and 4-bit VC Frame Count Cycle, but not the VC Frame Count. *(PDF p. 60)*
- OID Transfer Frames are filled with a pseudo-noise sequence from a 32-cell LFSR with polynomial D0 + D1 + D2 + D22 + D32. The LFSR is initialised only at device start-up and is never restarted. *(PDF p. 64)*
- The M_PDU header is now just the 16-bit First Header Pointer, with no spare bits. 'All ones' means no packet starts in the frame, and 'all ones minus one' means idle data only. *(PDF p. 64)*
- The B_PDU header keeps a 2-bit spare and a 14-bit Bitstream Data Pointer, so the frame size with the Bitstream Service is limited to 16,384 bits. *(PDF p. 68)*
- The OCF Type Flag (bit 0) is '0' for a Type-1 report (CLCW) and '1' for a Type-2 report. In a Type-2 report, bit 1 = '1' means an SDLS Frame Security Report. *(PDF p. 68)*
- The FECF is a CRC with generator X^16 + X^12 + X^5 + 1 and the shift register preset to all ones. *(PDF p. 70)*
- Valid user VCIDs are 0-62, with 63 always valid for OID frames. Data Field Content per VC is managed as M_PDU, B_PDU, VCA_SDU or Idle Data. *(PDF p. 88)*
- The PICS adds item AOS-47.1 'SCID Length' (4.1.2.2.3) as a mandatory feature. *(PDF p. 103)*
- The OID data pattern starts FF FF FF FF 6D B6 D8 61 45 1F 11 F1 97 16 72 3C BE 7E 00 B1 for both the Fibonacci and the Galois LFSR forms. *(PDF p. 110)*
