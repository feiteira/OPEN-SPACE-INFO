## Summary

This version of the CCSDS Recommended Standard for the **TC Synchronization and Channel Coding Sublayer** incorporates Technical Corrigendum 1 (July 2026). The sublayer sits below the [TC](../ccsds/tc-sdlp.md) and [USLP](../ccsds/uslp.md) data link protocols. It protects variable-length Transfer Frames with error-control coding, delimits them in a **Communications Link Transmission Unit (CLTU)** and drives the Physical Layer through a Physical Layer Operations Procedure (PLOP). The technical content is that of the library's [Issue 4 with EC 1](ccsds-231-0-231x0b4e1.md), except for the new LDPC tail sequence. It is the uplink counterpart of [TM coding](../ccsds/tm-coding.md) and the format behind [SLE FCLTU](../ccsds/sle/fcltu.md) and the [CLTU](../ccsds/tc-coding-cltu.md) page.

The standard specifies:

* four sublayer functions: error-control coding, synchronization, pseudo-randomizing and optional repeated transmissions (section 2);
* the modified (63,56) BCH code with g(x) = x^7+x^6+x^2+1, giving 64-bit codewords that can be decoded in error-detecting or error-correcting mode (section 3);
* the rate-1/2 (128,64) and (512,256) LDPC codes (section 4);
* the CLTU (section 5): the 16-bit `0xEB90` Start Sequence and `C5C5C5C5C5C5C579` Tail Sequence for BCH, the 64-bit `0x034776C7272895B0` Start Sequence for LDPC, an optional 128-bit Tail Sequence for LDPC (128,64), and the S1/S2/S3 receiver state machine;
* the 255-bit Bit Transition Generator randomizer, required with LDPC (section 6);
* the carrier modulation modes CMM-1 to CMM-4, PLOP-1 and PLOP-2 (section 7), and the managed parameters (section 8).

The corrigendum replaces the LDPC (128,64) Tail Sequence with `63A1ED72C6AC79E25555555555555555`. The pattern stops a decoder with probability of about 1-10^-4. A new note gives its derandomized form, which is what an LDPC decoder actually sees.


## Key points

- Technical Corrigendum 1 (July 2026) changes only 5.2.4.2: a revised LDPC (128,64) Tail Sequence, a new note 3 and decoding-probability details in the requirement and note 2. *(PDF p. 7)*
- The modified BCH code can be decoded in error-detecting or error-correcting mode, depending on mission requirements. *(PDF p. 19)*
- Repeated transmission is requested through an optional Repetitions parameter of the service primitive. *(PDF p. 20)*
- BCH codeword: 56 information bits, 7 parity bits from g(x) = x^7 + x^6 + x^2 + 1 and a final Filler Bit that is always zero, 64 bits (8 octets) in total. *(PDF p. 23)*
- Two rate-1/2 LDPC codes are specified, (n=128, k=64) and (n=512, k=256), with parity-check matrices built from M x M submatrices, M = k/4 = n/8. *(PDF p. 26)*
- The CLTU is Start Sequence + codewords + Tail Sequence; for BCH the Start Sequence is the 16-bit pattern 1110 1011 1001 0000 (0xEB90) and for LDPC the 64-bit pattern 0347 76C7 2728 95B0. *(PDF p. 30)*
- The BCH Tail Sequence is the 64-bit non-correctable pattern C5C5 C5C5 C5C5 C579, which stops the decoding process. *(PDF p. 30)*
- Corrigendum: the optional 128-bit LDPC (128,64) Tail Sequence is now 63A1 ED72 C6AC 79E2 5555 5555 5555 5555 and stops the decoder with probability of roughly 1-10^-4; its derandomized form, which the decoder fails on, is 9C987328 AE457F17 39DC7AF4 640B5D95. *(PDF p. 31)*
- No Tail Sequence is used with LDPC (512,256); a conventional decoder reliably fails to decode when it over-runs the end of the CLTU. *(PDF p. 31)*
- CLTU reception states are S1 INACTIVE, S2 SEARCH and S3 DECODE; events are E1 channel activation, E2 channel deactivation, E3 start sequence found, E4 codeword rejection and E5 tail sequence found (optional, LDPC 128,64). *(PDF p. 33)*
- In S2, no Start Sequence error is allowed in BCH error-detecting mode and one error in error-correcting mode. *(PDF p. 33)*
- Randomizer h(x) = x^8 + x^6 + x^4 + x^3 + x^2 + x + 1 (255-bit period, first bits 1111 1111 0011 1001 ...); always applied with LDPC, and required with BCH unless the designer verifies operation without it. *(PDF p. 35)*
- With BCH the BTG is preset to all ones at the start of the Transfer Frame(s); with LDPC it is preset at the start of each codeword and reset to all ones after each codeword. *(PDF p. 36)*
- PLOP-2 shall be used for missions whose planning began after September 2010; the preferred minimum Acquisition Sequence is 16 octets. *(PDF p. 38)*
- Carrier Modulation Modes: CMM-1 unmodulated carrier, CMM-2 carrier modulated with the acquisition sequence, CMM-3 carrier modulated with CLTUs, CMM-4 carrier modulated with the idle sequence. *(PDF p. 39)*
- Managed parameters: code type, maximum CLTU length, maximum Repetitions, PLOP-1 or PLOP-2; for BCH the decoding mode, allowed Start Sequence errors (0 or 1) and randomizer use; for LDPC the code length and use of the tail sequence. A maximum Repetitions value of 1 means repeated transmission is not available. *(PDF p. 42)*
- The service primitive is ChannelAccess.request (Frame(s), Repetitions); support for Repetitions is optional. *(PDF p. 45)*
