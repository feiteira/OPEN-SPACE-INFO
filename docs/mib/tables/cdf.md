# cdf.dat: Commands definition

<div class="osi-chips"><span class="osi-chip">ICD 7.0 §3.3.3.2.3</span><span class="osi-chip">47,609 rows in Solar Orbiter 2025-09-16</span></div>

The cdf table defines the structure of each command's application data field, one record per command element. An element is either a fixed area (constant bits, possibly padding or unused bits) or an instance of a command parameter from CPC, which may be fixed (non-editable) or editable. Elements are encoded back to back with no gaps, in the order of their bit offsets, so every bit of the raw command after the packet header must be covered. The table supports PUS variable-length commands through repeated groups: a counter parameter (e.g. N) with a non-zero group size precedes a group of following elements that is repeated N times when the command is loaded, nested groups being expanded left to right; a fixed counter with a non-zero group size forces the expansion without prompting the user. Each editable element may carry a static default and, optionally, a dynamic default taken from a monitoring parameter (for instance a User Defined Constant controlled from TM SPACON), which replaces the static value after loading until an explicit value is entered. Default values can also be inherited from CPC_DEFVAL. Since R4.2 commands with group repeaters can be used in sequences only if all repeated values are fixed in the database. The structure also serves on-board control directives and throw events (see CCF_CTYPE).[^icd]

**Key:** `CDF_CNAME`, `CDF_BIT`, `CDF_GRPSIZE`

## Relationships

- `CDF_CNAME` → [ccf.CCF_CNAME](ccf.md#ccf_cname): Command owning the element; CCF_NPARS should equal the number of CDF records.
- `CDF_PNAME` → [cpc.CPC_PNAME](cpc.md#cpc_pname): Parameter placed at the element position (for ELTYPE F/E).
- `CDF_TMID` → [pcf.PCF_NAME](pcf.md#pcf_name): Monitoring parameter supplying a dynamic default (CDF_INTER=T); must be in PLF or synthetic.
- `CDF_VALUE` → [ccf.CCF_CNAME](ccf.md#ccf_cname) / [pcf.PCF_NAME](pcf.md#pcf_name): Value of 'Command ID' / 'Parameter ID' parameters.
- `CDF_BIT` → [sdf.SDF_POS](sdf.md#sdf_pos) / [sdf.SDF_REPPOS](sdf.md#sdf_reppos): Sequence element parameters are located by the bit offset of the parameter in the command (SDF_REPPOS gives the original CDF_BIT when repeated groups shift the position).
- `CDF_BIT` → [pvs.PVS_BIT](pvs.md#pvs_bit): Parameter value sets locate command parameters by their bit offset.

## History across ICD issues

ICD 5.1 (2001, section 3.3.3.2.3, PDF p.70-73) has the same ten fields, but the key is only CDF_CNAME + CDF_BIT, CDF_VALUE is Char(17), and fixed areas and group repeaters both had to be hexadecimal. In ICD 6.7 Draft A (PDF p.141-148) and ICD 6.9 (PDF p.145-153) CDF_GRPSIZE is a key field (when non-zero). ICD 6.1 clarified that fixed areas must not be used for Service 11 elements processed for ground modelling and that 0 is allowed for group repeaters (Annex 1, PDF p.251); ICD 6.4 restricted dynamic defaults to parameters processed by the TM model (PDF p.254); ICD 6.6 defined the allowed CDF_ELTYPE/SDF_FTYPE combinations (S2K-SPR-3400, PDF p.257). In ICD 6.9 the 32-bit maximum (FFFF FFFF) was stated for CDF_VALUE as a whole; ICD 7.0 (PDF p.151-159) restricts it to fixed areas (S2K-8782, PDF p.263) and makes CDF_VALUE variable-length, bounded by the command size (S2K-8073, PDF p.261). pyscos2000 (ICD 7.2) has the same ten columns in the same order, mandatory CDF_CNAME, CDF_ELTYPE, CDF_ELLEN and CDF_BIT, and defaults 0 for CDF_GRPSIZE and R for CDF_INTER, but marks only CDF_CNAME as key.

!!! note "Notes from the extraction"
    Columns match between ICD 7.0, pyscos2000 and the Solar Orbiter cdf.dat (10 columns in all 47609 lines). Key discrepancy: ICD 7.0 keys on CDF_CNAME + CDF_BIT (+ CDF_GRPSIZE when non-zero), while pyscos2000 flags only CDF_CNAME as key (necessarily incomplete, since a command has many elements). The Herschel HCSS tailoring note (point 5.2.9, PDF p.13 of hcss-mib-clarification-tailoring-note) further assumed that CDF_CNAME + CDF_PNAME is unique, repeated groups being the way to repeat a parameter. Solar Orbiter 2025: no duplicate (CDF_CNAME, CDF_BIT, CDF_GRPSIZE); element types F 17681, A 16906, E 13022; 569 group repeaters (CDF_GRPSIZE from 1 to 48); 48 variable-length parameter instances (PTC 7 or 8 with PFC 0) all with CDF_ELLEN=0 as required. CDF_INTER is empty for 1614 fixed areas and 'R' for the other 15292 (irrelevant for fixed areas). Editable parameters: 4863 take the CPC default (D), 5876 raw, 2283 engineering; 4959 editable raw entries have no value, i.e. the operator must supply it. Dynamic defaults are never used (CDF_TMID always empty, no CDF_INTER='T'). CDF_GRPSIZE is empty in 33 records (import default 0). All CDF_CNAME and CDF_PNAME values resolve to CCF and CPC records. 44944 records in 2020.
