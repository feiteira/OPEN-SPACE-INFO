# sdf.dat: Command sequence element parameters

<div class="osi-chips"><span class="osi-chip">ICD 7.0 §3.3.3.3.3</span><span class="osi-chip">50,014 rows in Solar Orbiter 2025-09-16</span></div>

The sdf table assigns values to the editable parameters of sequence elements, one record per editable parameter of each command or nested sequence used in a sequence. For each such parameter it identifies the source of the value used when the sequence is loaded: an explicit raw or engineering value written in the record, the value of a formal parameter of the enclosing sequence (so the sequence acts as a template), an entry of a parameter value set, the default of the nested sequence's formal parameter (CSP_DEFVAL), or the default of the command definition (CDF_VALUE, itself possibly inherited from CPC_DEFVAL or extracted from telemetry). It also states whether the value may still be edited after loading. Parameters of commands are located by their bit offset in the command, parameters of nested sequences by the formal parameter number. Only parameters that are editable in the command definition (CDF_ELTYPE=E) may appear; the allowed combinations of CDF_ELTYPE and SDF_FTYPE (E/F valid but not editable in the sequence, E/E valid and editable, F with no SDF entry valid) are checked at import. Since R4.2, commands with group repeaters can be used if all repeater values and repeated parameters are defined, with one SDF entry per repeated instance and SDF_REPPOS mapping shifted offsets back to CDF_BIT. Since SCOS-2000 R5.0 these tables are converted on request into XML sequence definitions held in the FARC rather than the run-time MIB, imported as a delta without re-importing the TM/TC database.[^icd]

**Key:** `SDF_SQNAME`, `SDF_ENTRY`, `SDF_POS`, `SDF_PNAME`

## Relationships

- `SDF_SQNAME + SDF_ENTRY` → [css.CSS_SQNAME](css.md#css_sqname) + [css.CSS_ENTRY](css.md#css_entry): Element owning the parameter (must be of type C or S); SDF_ELEMID repeats CSS_ELEMID.
- `SDF_PNAME + SDF_POS` → [cdf.CDF_PNAME](cdf.md#cdf_pname) + [cdf.CDF_BIT](cdf.md#cdf_bit): For command elements; only editable (CDF_ELTYPE=E) parameters; SDF_REPPOS carries the original CDF_BIT when shifted.
- `SDF_PNAME + SDF_POS` → [csp.CSP_FPNAME](csp.md#csp_fpname) + [csp.CSP_FPNUM](csp.md#csp_fpnum): For nested-sequence elements (formal parameters of the nested sequence).
- `SDF_VALUE (VTYPE=F)` → [csp.CSP_FPNAME](csp.md#csp_fpname): Formal parameter of the current sequence (SDF_SQNAME) from which the value is inherited.
- `SDF_VALSET` → [psv.PSV_PVSID](psv.md#psv_pvsid): Parameter value set used when VTYPE=P; one SDF entry maps to one PVS value.

## History across ICD issues

ICD 5.1 (2001, section 3.3.3.3.3, PDF p.87-89) has 9 fields: the key is SDF_SQNAME + SDF_ENTRY + SDF_POS (SDF_PNAME not key) and SDF_VALUE is Char(17). ICD 6.5 added the optional field SDF_REPPOS and changed the SDF_POS description to support commands with group repeaters in sequences (R4.2, SPR-2904; Annex 1 of ICD 7.0, PDF p.255); ICD 6.4 clarified that only editable parameters may appear (PDF p.255) and ICD 6.6 fixed the allowed ELTYPE/FTYPE combinations (S2K-SPR-3400, PDF p.257). ICD 6.7 Draft A (PDF p.168-173) and ICD 6.9 (PDF p.172-176) have 10 fields with SDF_PNAME in the key. ICD 7.0 (PDF p.179-184) makes SDF_VALUE variable-length, bounded by the command size (S2K-8073, PDF p.261). pyscos2000 (ICD 7.2) has the same ten columns, keys (SDF_SQNAME, SDF_ENTRY, SDF_POS, SDF_PNAME), mandatory fields and default E for SDF_FTYPE.

!!! note "Notes from the extraction"
    No discrepancy in columns, order, keys or optionality between ICD 7.0, pyscos2000 and the Solar Orbiter sdf.dat (10 columns in all 50014 records of 2025; 30985 in 2020). SDF_REPPOS is filled in every record: for command elements it equals the CDF_BIT of the parameter (differing from SDF_POS in 11896 records, i.e. parameters of expanded repeated groups), for nested-sequence elements it is 0. Value sources: R 25683, F 11575 (formal parameters, all resolving to CSP records of the same sequence), E 10378, D 2328 (always with empty SDF_VALUE, command elements only) and S 50 (nested sequences only); P is never used and SDF_VALSET is always empty. SDF_FTYPE is E in 46251 and F in 3763 records. SDF_VALUE reaches 424 characters (hexadecimal octet-string data), far beyond the 17 characters of earlier ICD issues, which is allowed by the variable size of ICD 7.0.
