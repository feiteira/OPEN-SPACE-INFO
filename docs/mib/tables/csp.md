# csp.dat: Command sequence formal parameters

<div class="osi-chips"><span class="osi-chip">ICD 7.0 §3.3.3.3.4</span><span class="osi-chip">10,981 rows in Solar Orbiter 2025-09-16</span></div>

The csp table defines the formal parameters of command sequences, one record per formal parameter. A formal parameter is an argument of the sequence: a placeholder whose value the user provides (or accepts as default) when loading the sequence, and which is propagated to every element parameter mapped to it in SDF (SDF_VTYPE=F) - a command parameter or a parameter of a nested sequence. In this way one sequence works as a template, and fewer sequences need to be defined. Several element parameters may share one formal parameter if they have the same raw and engineering formats. The definition mirrors that of command parameters: type and length (PTC/PFC), display format and radix, calibration category with references to numeric (CCA) or textual (PAF) (de-)calibrations, a range set (PRF), unit and a default value with its representation; 'Command ID' and 'Parameter ID' types are supported. Formal parameters representing a command or sequence name are foreseen (CSP_TYPE C/S) but not supported by current SCOS-2000 versions. Formal parameter names need only be unique within their sequence. Since SCOS-2000 R5.0 these tables are converted on request into XML sequence definitions held in the FARC rather than the run-time MIB, imported as a delta without re-importing the TM/TC database.[^icd]

**Key:** `CSP_SQNAME`, `CSP_FPNAME`

## Relationships

- `CSP_SQNAME` → [csf.CSF_NAME](csf.md#csf_name): Owning sequence; CSF_NFPARS should equal the number of CSP records.
- `CSP_FPNAME` → [sdf.SDF_VALUE](sdf.md#sdf_value) (SDF_VTYPE=F): Element parameters of the same sequence inheriting the value.
- `CSP_FPNAME + CSP_FPNUM` → [sdf.SDF_PNAME](sdf.md#sdf_pname) + [sdf.SDF_POS](sdf.md#sdf_pos): When the sequence is nested, its formal parameters are addressed as element parameters of the parent.
- `CSP_FPNAME` → [css.CSS_ELEMID](css.md#css_elemid) (CSS_TYPE F/P): Formal parameter standing for an element (future extension).
- `CSP_PRFREF` → [prf.PRF_NUMBR](prf.md#prf_numbr): Range set.
- `CSP_CCAREF` → [cca.CCA_NUMBR](cca.md#cca_numbr): Numeric (de-)calibration.
- `CSP_PAFREF` → [paf.PAF_NUMBR](paf.md#paf_numbr): Textual (de-)calibration.

## History across ICD issues

ICD 5.1 (2001, section 3.3.3.3.4, PDF p.89-92) has the same 16 fields, but CSP_FPNUM is Number(3), CSP_PRFREF, CSP_CCAREF and CSP_PAFREF are Number(4), CSP_DEFVAL is Char(17), and the special categories A and P are absent. ICD 6.0 added the 'Command ID'/'Parameter ID' types (Annex 1, PDF p.249) and the identifiers became Char(10) (PDF p.247); ICD 6.5 extended CSP_FPNUM to 65535 for R5.0 (PDF p.256). ICD 6.7 Draft A (PDF p.173-179) and ICD 6.9 (PDF p.177-183) have CSP_FPNUM Number(5) and Char(10) references. ICD 7.0 (PDF p.184-191) makes CSP_DEFVAL variable-length (S2K-8073, PDF p.261). pyscos2000 (ICD 7.2) has the same 16 columns, keys (CSP_SQNAME, CSP_FPNAME), mandatory fields and defaults (R, D, N).

!!! note "Notes from the extraction"
    No discrepancy in columns, order, keys or optionality between ICD 7.0, pyscos2000 and the Solar Orbiter csp.dat (16 columns; 10981 records in 2025, 5598 in 2020). All formal parameters are of CSP_TYPE P; CSP_FPNUM runs consecutively from 1 (maximum 217) in every sequence, i.e. the value 0 is never used. CSP_VTYPE is filled in every record (R 9124, E 1857), including the 4515 records without default value where the ICD makes it optional. Categories: N 8864, T 1765 (all with DISPFMT A), C 312, P 38, A 2. CSP_DEFVAL reaches 40 characters. One reference does not resolve: CSP_PRFREF 'VSM00001' of formal parameter XC534C01 of sequence ADMC534C has no PRF record; all CSP_CCAREF and CSP_PAFREF values resolve.
