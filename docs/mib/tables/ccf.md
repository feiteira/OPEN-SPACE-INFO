# ccf.dat: Command characteristics

<div class="osi-chips"><span class="osi-chip">ICD 7.0 §3.3.3.2.1</span><span class="osi-chip">5,454 rows in Solar Orbiter 2025-09-16</span></div>

The ccf table is the master list of telecommands, one record per command, and is the central entity of the SCOS-2000 commanding data. A command may target the spacecraft or another control domain such as ground equipment, and since SCOS-2000 R5.0 it may also be an SLE or NIS throw event. The record gives the command name and descriptions, the packet header to use (CCF_PKTID), the values that fill the header placeholders (service type and subtype, APID, acknowledgement flags), special command types such as control frames, control segments or packets without error control, and the default operational attributes applied when the command is loaded on a command source: criticality, plannability by external sources, stand-alone loading, interlock scope and stage, high priority with forced MAP ID, default parameter value set, redundant APID and default on-board sub-schedule. The layout of the application data is given by CDF (elements) and CPC (parameters); static pre-transmission validation by PTV; verification stages through CVP/CVS/CVE; parameter sets through PSM. Only parameter values, not fixed areas, appear in the command history. Encoded commands are limited by the MISCconfig variable CMDP_MAX_BLOCK_SIZE (default 248 bytes), from which the header, the CRC (CMD_CRC_SIZE, default 2 bytes) and, for time-tagged commands, the TC(11,4) wrapper defined by CMD_LOAD_TT_NAME (default 20 bytes) are deducted; that wrapper command must itself be defined in CCF and CDF.[^icd]

**Key:** `CCF_CNAME`

## Relationships

- `CCF_PKTID` → [tcp.TCP_ID](tcp.md#tcp_id): Packet header used to encode the command; its PCDF elements of type A/T/S/K are filled from CCF_APID/CCF_TYPE/CCF_STYPE/CCF_ACK.
- `CCF_CNAME` → [cdf.CDF_CNAME](cdf.md#cdf_cname): Command structure: one CDF record per element; CDF maps the command to its CPC parameters (many-to-many).
- `CCF_CNAME` → [ptv.PTV_CNAME](ptv.md#ptv_cname): Static pre-transmission validation checks of the command (one-to-many, ANDed).
- `CCF_CNAME` → [cvp.CVP_TASK](cvp.md#cvp_task): Verification profile: CVP maps the command to shared CVS verification stages (many-to-many).
- `CCF_CNAME` → [psm.PSM_NAME](psm.md#psm_name): Parameter sets usable with the command (many-to-many through PSM).
- `CCF_CNAME` → [css.CSS_ELEMID](css.md#css_elemid): Use of the command as an element (CSS_TYPE=C) of command sequences.
- `CCF_DEFSET` → [psv.PSV_PVSID](psv.md#psv_pvsid): Default parameter value set.
- `CCF_APID` → [dst.DST_APID](dst.md#dst_apid): Optional routing of all commands with this APID; absent APIDs go to the NCTRS.
- `CCF_SUBSYS` → [ccf.CCF_SUBSCHEDID](ccf.md#ccf_subschedid): CCF_SUBSYS is the fallback default sub-schedule when CCF_SUBSCHEDID is empty.

## History across ICD issues

ICD 5.1 (2001, section 3.3.3.2.1, PDF p.62-66) defines the first 20 fields with the same names, sizes and defaults, but CCF_CTYPE only has the special values R, F and S and CCF_ILSCOPE only G, L, S, B, N. CCF_SUBSCHEDID (field 21) was added in ICD 6.0 together with CSF_SUBSCHEDID (Annex 1 of ICD 7.0, PDF p.249) and is present in ICD 6.7 Draft A (PDF p.124-131) and ICD 6.9 (PDF p.129-135). The throw-event types were added to CCF_CTYPE for R5.0: SLE throw events in ICD 6.4 and NIS throw events in ICD 6.5 (Annex 1, PDF p.254 and p.256). ICD 6.0 also documented that acknowledgement flags can be changed to disable report-based verification (PDF p.250); ICD 6.6 added that high-priority commands cannot be blocked (S2K-50-DCR-1023, PDF p.257). ICD 7.0 (PDF p.132-140) added options F and T to CCF_ILSCOPE, which the software already supported (S2K-8560, PDF p.262), and added the explanations of the maximum command size and of the TC(11,4) time-tag wrapper MISC variables (S2K-8063, S2K-8226, PDF p.262-263). pyscos2000 (ICD 7.2) has the same 21 columns in the same order, names the last one CCF_SUBSCHEDID, marks CCF_CNAME, CCF_DESCR and CCF_PKTID as mandatory and keeps the defaults N, N, Y, N, C and N for CCF_CRITICAL, CCF_PLAN, CCF_EXEC, CCF_ILSCOPE, CCF_ILSTAGE and CCF_HIPRI.

!!! note "Notes from the extraction"
    Columns of ICD 7.0, pyscos2000 (7.2) and the Solar Orbiter ccf.dat (21 tab-separated columns in all 5454 lines) match one to one; the only naming difference is that the ICD 7.0 PDF text splits the last name as 'CCF_SUBSCHED ID'. Observations on the 2025-09-16 Solar Orbiter data: (1) CCF_DESCR exceeds the ICD 7.0 size of 24 characters in 2876 records (up to 40 characters); according to ICD 7.0 section 2.4 (PDF p.23) the importer truncates over-long fields with a warning, so either the target system accepts longer descriptions or the text is truncated on import (not stated in the available sources). (2) CCF_ILSTAGE='N' appears in the 5 NO_HDR directives (UNLOCK, SETVR, RESET, REIN_TTR, TC_ONLY); 'N' is not an ICD 7.0 option for this field. (3) CCF_CTYPE is used only for 2 control frames ('F': UNLOCK, SETVR), 3 control segments ('R': RESET, REIN_TTR, TC_ONLY) and 6 NIS throw events ('N': link and session open/close, APID 1964, type 251 subtype 1, header NOS2KHDR); these 6 throw events leave CCF_CRITICAL, CCF_EXEC and CCF_ILSTAGE empty and are the only commands with CCF_PLAN='A'. (4) CCF_MAPID is filled in 205 records with CCF_HIPRI='N' (values 1 and 54), where the ICD says it is irrelevant; the 125 HPC1_TC commands are high priority with MAP ID 0 and have no type, subtype or ack (their header has no T/S/K elements). (5) CCF_SUBSCHEDID equals CCF_SUBSYS in every record. (6) CCF_DEFSET and CCF_RAPID are never used (PST/PSV are empty). (7) 443 commands have no CDF record, consistent with CCF_NPARS=0. In the 2020-04-16 release ccf has 5238 records.
