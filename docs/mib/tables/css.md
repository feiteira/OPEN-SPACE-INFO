# css.dat: Command sequences definition

<div class="osi-chips"><span class="osi-chip">ICD 7.0 §3.3.3.3.2</span><span class="osi-chip">13,879 rows in Solar Orbiter 2025-09-16</span></div>

The css table lists the elements of each command sequence, one record per element, in the order given by CSS_ENTRY (consecutive, without gaps). An element is a command, a nested sequence or (future extension) a formal parameter standing for a command or sequence chosen later. For each element the table defines the release timing - a delta release time relative either to the previous command of the expanded sequence (or to its manual dispatch time) or to the start of the sequence - and the execution time tag, relative either to the previous time-tagged command or to the execution start of the sequence; whether a command needs its own manual dispatch (ARM and GO) on the stack; grouping (commands released as an uninterrupted batch) and blocking (commands aggregated into a single segment); the interlock scope and stage, overriding the command defaults; and flags to override dynamic PTV, static PTV and CEV checks for individual commands. All these attributes are defaults: the command requests can still be edited on a manual stack after the sequence is loaded. CSS_NPARS gives the number of SDF entries holding the element's parameter values. Since SCOS-2000 R5.0 these tables are converted on request into XML sequence definitions held in the FARC rather than the run-time MIB, imported as a delta without re-importing the TM/TC database.[^icd]

**Key:** `CSS_SQNAME`, `CSS_ENTRY`

## Relationships

- `CSS_SQNAME` → [csf.CSF_NAME](csf.md#csf_name): Sequence owning the element.
- `CSS_ELEMID` → [ccf.CCF_CNAME](ccf.md#ccf_cname) (type C) / [csf.CSF_NAME](csf.md#csf_name) (type S) / [csp.CSP_FPNAME](csp.md#csp_fpname) (types F, P): Element identity depends on CSS_TYPE.
- `CSS_SQNAME + CSS_ENTRY` → [sdf.SDF_SQNAME](sdf.md#sdf_sqname) + [sdf.SDF_ENTRY](sdf.md#sdf_entry): Parameter values of the element; CSS_NPARS should equal the number of SDF records.
- `CSS_ILSCOPE / CSS_ILSTAGE` → [ccf.CCF_ILSCOPE](ccf.md#ccf_ilscope) / [ccf.CCF_ILSTAGE](ccf.md#ccf_ilstage): Overrides; empty means the command defaults apply.
- `CSS_ILSTAGE` → [cvp.CVP_CVSID](cvp.md#cvp_cvsid) / cvs: Requested CEV stages must exist in the command verification profile.
- `CSS_STAPTV` → ptv: Overrides the static PTV checks of the command.
- `CSS_BLOCK` → [ccf.CCF_HIPRI](ccf.md#ccf_hipri): High-priority commands cannot be blocked.

## History across ICD issues

ICD 5.1 (2001, section 3.3.3.3.2, PDF p.78-86) already defines the 18 fields with the same names and defaults (CSS_ILSCOPE including F and T), except that CSS_EXTIME is Char(16). ICD 6.7 Draft A (PDF p.157-168), ICD 6.9 (PDF p.161-171) and ICD 7.0 (PDF p.168-179) have CSS_EXTIME as Char(17). ICD 6.5 split the long CSS_RELTIME and CSS_EXTIME descriptions over two pages (Annex 1, PDF p.256) and the evolution-line changes clarified their input formats (Annex 1 item 8, PDF p.244). pyscos2000 (ICD 7.2) has 18 columns in the same order but names field 17 CSS_STATPTV, marks only CSS_SQNAME as key (not CSS_ENTRY), and treats CSS_NPARS as mandatory; defaults N, R, R, N, N, N for CSS_MANDISP, CSS_RELTYPE, CSS_PREVREL, CSS_DYNPTV, CSS_STATPTV and CSS_CEV match the ICD.

!!! note "Notes from the extraction"
    Name discrepancy: ICD 7.0 (and 5.1/6.7/6.9) field 17 is CSS_STAPTV, pyscos2000 and the Solar Orbiter SQLite use CSS_STATPTV. Optionality: CSS_NPARS carries no M in ICD 7.0 but is mandatory in pyscos2000. Key: pyscos2000 omits CSS_ENTRY from the key. Solar Orbiter 2025-09-16 (18 columns, 13879 records; 9089 in 2020): only types C (12629) and S (1250) are used; every sequence starts with entry 1 having CSS_RELTYPE='A' and CSS_PREVREL='A' and all other entries 'R'; entries are consecutive from 1 in every sequence and CSS_NPARS always matches the SDF count. CSS_RELTIME exceeds the declared Char(8) and the hh.mm.ss format in 1107 records, which carry milliseconds (e.g. '00.00.01.000'); CSS_EXTIME values use the same style and are never negative. CSS_COMM is filled in every record although the ICD marks it unsupported. 234 distinct commands containing group repeaters are used in 2467 sequence elements, which ICD 7.0 allows since R4.2 only for fully defined repeated groups although its CSS_ELEMID description still forbids them. In the 46 group/block members that are not the first (M or E), CSS_MANDISP is 'N' instead of empty and CSS_RELTIME is filled, contrary to the ICD rule. Groups (24) and blocks (34) never contain high-priority commands. CSS_ILSCOPE is 'N' or empty and CSS_ILSTAGE 'C' or empty; CSS_DYNPTV and CSS_STATPTV are always N, CSS_CEV is Y for 17 elements.
