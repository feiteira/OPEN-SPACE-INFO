# csf.dat: Command sequence characteristics

<div class="osi-chips"><span class="osi-chip">ICD 7.0 §3.3.3.3.1</span><span class="osi-chip">3,404 rows in Solar Orbiter 2025-09-16</span></div>

The csf table is the top level of the command sequence definitions: one record per sequence, giving its name, descriptions and global attributes. A sequence is an ordered list of elements (commands or other sequences, nested to any depth but never containing itself) whose release and execution times, grouping and interlocks are defined in CSS; the values of the element parameters are given in SDF and the sequence's own 'formal parameters' (placeholders that let one definition serve as a template) in CSP. CSF says whether the sequence carries execution time-tagged commands and how the user loads it, its criticality, which external sources may plan it, whether it may be loaded stand-alone, its subsystem, provenance information (generation time, source document, issue and date), a default parameter value set and a default on-board sub-schedule. A nested sequence is expanded like a macro-command when the parent is loaded on a command source. Since SCOS-2000 R5.0 these tables are converted on request into XML sequence definitions held in the FARC rather than the run-time MIB, imported as a delta without re-importing the TM/TC database.[^icd]

**Key:** `CSF_NAME`

## Relationships

- `CSF_NAME` → [css.CSS_SQNAME](css.md#css_sqname): Elements of the sequence (one-to-many); CSF_ELEMS should equal their number.
- `CSF_NAME` → [csp.CSP_SQNAME](csp.md#csp_sqname): Formal parameters of the sequence; CSF_NFPARS should equal their number.
- `CSF_NAME` → [sdf.SDF_SQNAME](sdf.md#sdf_sqname): Values of the element parameters of the sequence.
- `CSF_NAME` → [css.CSS_ELEMID](css.md#css_elemid): Use of this sequence as a nested element (CSS_TYPE=S) of other sequences.
- `CSF_NAME` → [psm.PSM_NAME](psm.md#psm_name): Parameter sets associated with the sequence (PSM_TYPE=S).
- `CSF_DEFSET` → [psv.PSV_PVSID](psv.md#psv_pvsid): Default parameter value set.
- `CSF_SUBSCHEDID` → [ccf.CCF_SUBSCHEDID](ccf.md#ccf_subschedid): If empty, each command uses its own CCF_SUBSCHEDID default.

## History across ICD issues

ICD 5.1 (2001, section 3.3.3.3.1, PDF p.77-78) has fields 1 to 15 with the same names, sizes and defaults. CSF_SUBSCHEDID was added in ICD 6.0 together with CCF_SUBSCHEDID (Annex 1 of ICD 7.0, PDF p.249) and appears in ICD 6.7 Draft A (PDF p.154-157) and ICD 6.9 (PDF p.158-161). In ICD 6.9 an empty CSF_SUBSCHEDID fell back to CSF_SUBSYS; ICD 7.0 (PDF p.165-168, change S2K-6680, PDF p.261) changed the fallback to each command's CCF_SUBSCHEDID. ICD 6.1 deleted the last sentence of option B of CSF_IFTT (PDF p.251). The move of sequences to XML files in the FARC dates from ICD 6.4 for R5.0 (PDF p.254). pyscos2000 (ICD 7.2) has the same 16 columns, mandatory CSF_NAME and CSF_DESC, defaults N (CSF_IFTT, CSF_CRITICAL, CSF_PLAN) and Y (CSF_EXEC).

!!! note "Notes from the extraction"
    No column discrepancy (16 columns in every line of the Solar Orbiter csf.dat). Solar Orbiter 2025-09-16 has 3404 sequences (2701 in 2020-04-16). CSF_IFTT is 'B' for 3354 and 'N' for 50; CSF_PLAN is N 2029, S 1177 (SOC), F 195 (flight dynamics) and A 3; CSF_CRITICAL is always N and CSF_EXEC always Y. CSF_GENTIME holds only a clock time such as '13:25:42' and CSF_DATE a date in dd/mm/yyyy form, while CSF_DOCNAME holds procedure identifiers such as 'DM-FCP-740'. CSF_SUBSCHEDID is filled in every record although CSF_SUBSYS is filled in only 771, and the two differ in 183 records. CSF_DEFSET is never used. CSF_ELEMS always equals the number of CSS records, but CSF_NFPARS disagrees with the CSP count for 3 sequences (APWC508A and APWC508B declare 1 formal parameter but have none; ATCC011C declares 11 but has 10).
