# ocp.dat: Monitoring checks definition

<div class="osi-chips"><span class="osi-chip">ICD 7.0 §3.3.2.3.2</span><span class="osi-chip">7,369 rows in Solar Orbiter 2025-09-16</span></div>

ocp lists the individual monitoring checks of each parameter declared in ocf, in the order SCOS-2000 applies them. Each check has a type, limit or expected values and an applicability criterion OCP_RLCHK = OCP_VALPAR that enables it. Supported types are soft and hard limit checks on a valid value's range, soft and hard status checks against lists of allowed discrete values, delta checks on the change between consecutive valid samples, and status-consistency checks against a reference value maintained from the predicted or detected effect of commands. Event checks ('E') raise no OOL; they generate a SCOS-2000 event with full ID 'BEHV::&lt;OCP_NAME&gt;' when the value leaves the range, which can trigger system actions. Search stops at the first applicable check or soft/hard pair unless MISCconfig BEHV_STOP_FIRST_SET says otherwise. Status-consistency and event checks must precede the others. Limit checks need numerical parameters and always come in low/high pairs; soft/hard pairs share one criterion, soft first. Several records of one type and criterion form one set of allowed status values. A value equal to a limit is not OOL, and the most critical violation is shown. The table must be sorted by OCP_NAME and OCP_POS.[^icd]

**Key:** `OCP_NAME`, `OCP_POS`

## Relationships

- `OCP_NAME` → [ocf.OCF_NAME](ocf.md#ocf_name): Up to 16 checks per ocf record (OCF_NBOOL).
- `OCP_RLCHK` → [pcf.PCF_NAME](pcf.md#pcf_name): Applicability parameter; one parameter may be reused by many criteria (section 3.3.2, p. 39).
- `OCP_TYPE` → [pcf.PCF_USCON](pcf.md#pcf_uscon): OCP_TYPE 'C' requires PCF_USCON = 'Y' for the parameter.
- `OCP_LVALU / OCP_HVALU` → [ocf.OCF_INTER](ocf.md#ocf_inter), [ocf.OCF_CODIN](ocf.md#ocf_codin): Raw/engineering view and data type of the limit values.

## History across ICD issues

ICD 5.1 (p. 36-38) has the same seven fields; OCP_POS is not marked mandatory there, OCP_TYPE has only 'S' Soft OOL, 'H' Hard OOL, 'C' and 'E', and the applicability parameter is described only as 'of type integer'. Delta checks ('D') and multiple sets of status checks with different applicability criteria were added in ICD 6.0 (ICD 7.0 Annex 1, p. 246 and 249). ICD 6.1 clarified that delta limits must be positive and apply in both directions (p. 251). ICD 6.4 restricted OCP_RLCHK to TM-model parameters, stated that limit checks always come in pairs and that checks of any severity may stand alone (p. 254-255). ICD 6.6 updated the OCP_TYPE description (S2K-50-DCR-755, p. 257). Field layout is unchanged in ICD 6.7 Draft A (p. 70-76), 6.9 (p. 73-79) and 7.0 (p. 75-81). pyscos2000 (ICD 7.2) matches: OCP_NAME, OCP_POS, OCP_TYPE mandatory, the rest optional, OCP_VALPAR default '1'.

!!! note "Notes from the extraction"
    No discrepancy between ICD 7.0 and pyscos2000. The ICD 7.0 value list for OCP_TYPE prints 'H' as 'Hard limit or soft status check' (p. 78), while the soft value 'S' is described only as 'Soft limit check'; the rules text (p. 77) describes soft and hard checks for both limit and status checks, so 'soft status' under 'H' is probably an editorial slip for 'hard status' (inference). Solar Orbiter 2025-09-16: 7,369 checks on 5,337 parameters: H 4,153, S 3,096, D 105, C 15; no event ('E') checks. OCP_POS values run from 0 to 15; 204 records use OCP_POS 0. All 15 'C' checks belong to parameters with PCF_USCON = 'Y' and leave OCP_LVALU empty, as required. Of the 105 delta checks, 102 use OCP_LVALU = OCP_HVALU = 0 (e.g. NIU01008) and 3 use 2048/2048; the effect of a 0/0 delta range is not explained in the ICD. Status checks give text values such as 'OK', 'TRUE' or 'DIS_UNCHECK'. 859 checks have an applicability parameter; 6 records give OCP_VALPAR without OCP_RLCHK (e.g. NCST5840), which the ICD does not discuss. A parameter has at most 15 checks (ICD limit 16).
