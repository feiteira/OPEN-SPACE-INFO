# pid.dat: Packets identification

<div class="osi-chips"><span class="osi-chip">ICD 7.0 §3.3.2.4.1</span><span class="osi-chip">11,150 rows in Solar Orbiter 2025-09-16</span></div>

pid maps the source packets produced by the spacecraft, or by ground systems, to SCOS-2000 telemetry packet identifiers. The telemetry packetiser recognises a packet by its APID, PUS type and subtype and up to two extra identification fields (PI1, PI2) whose position pic gives. It looks up pid with that 5-field key and then files and distributes the packet under the processing keys found there: the SPID, which selects the fixed layout in plf, and the TPSD, which selects the variable layout in vpd. One packet may be processed both ways. Packets identified by APID alone use 0 for the other key fields. Since R5.0 each distinct packet must have its own SPID. Duplicate keys are allowed only with PID_VALID selecting one valid record. Once archiving has started, the key-to-SPID allocation and the TPSD should not change and archived SPIDs must not be deleted, or retrieval services such as GDDS break. Internally generated packets (UDC, MISC, synthetic, system control) should also have pid and tpcf entries, with an unused type/subtype/APID combination. The table also sets the event packets raised on reception, the presence of a time field and of a checksum, and the period used for parameter expiry.[^icd]

**Key:** `PID_TYPE`, `PID_STYPE`, `PID_APID`, `PID_PI1_VAL`, `PID_PI2_VAL`, `PID_SPID`

## Relationships

- `PID_SPID` → [plf.PLF_SPID](plf.md#plf_spid), [tpcf.TPCF_SPID](tpcf.md#tpcf_spid), [grpk.GRPK_PKSPID](grpk.md#grpk_pkspid): SPID identifies the fixed packet layout (plf), its characteristics (tpcf) and packet-group membership.
- `PID_TPSD` → [vpd.VPD_TPSD](vpd.md#vpd_tpsd): Variable packet structure used by the Variable Packets Display.
- `PID_TYPE, PID_STYPE, PID_APID` → [pic.PIC_TYPE](pic.md#pic_type), [pic.PIC_STYPE](pic.md#pic_stype), [pic.PIC_APID](pic.md#pic_apid): pic tells the packetiser where to read PI1/PI2 before searching pid.
- `PID_INTER` → pcf (parameter expiry): Parameters in periodic packets expire after PID_INTER plus a global margin.

## History across ICD issues

ICD 5.1 (p. 38-42) already has the 16 fields in this order (its table misnumbers PID_EVID as 15). It allowed several keys to map to the same SPID, and PID_SPID also selected the history file. ICD 6.0 widened the PID_SPID range from 2^31-1 to 2^32-1 (DCR-2421, ICD 7.0 Annex 1, p. 246). ICD 6.1 updated the PID_PI1_VAL/PID_PI2_VAL descriptions (CRY-OG-655 / DCR 3398, p. 251). ICD 6.4 stated that packets without a data field header can be recognised by APID alone (p. 255). ICD 6.5 (R5.0) deprecated mapping different packets to the same SPID and clarified the use of pid fields (DCR-3398, p. 256-257). The layout is unchanged in ICD 6.7 Draft A (p. 77-85), 6.9 (p. 80-89) and 7.0 (p. 82-91). pyscos2000 (ICD 7.2) matches: the same 16 fields and defaults, with the 6 key fields PID_TYPE to PID_SPID.

!!! note "Notes from the extraction"
    No structural discrepancy between ICD 7.0 and pyscos2000. ICD 7.0 marks PID_SPID with '*' (key) although the text says the packetiser key is the first five fields, so the import key is effectively type/subtype/APID/PI1/PI2 plus SPID. Solar Orbiter 2025-09-16: 11,150 packets, SPID range 101 to 1,000,006, all SPIDs unique. PID_UNIT, PID_INTER and PID_EVID are never filled, so Solar Orbiter relies on no periodic-packet expiry and on default event IDs. PID_TIME is 'Y' for 11,141 packets. PID_CHECK is 1 for only 6 packets. PID_VALID is 'Y' or empty (default 'Y'). PID_EVENT: A 6,360, I 1,374, W 1,159, N 1,095, empty 1,162. 2,063 packets have a TPSD (each TPSD used by exactly one packet, all present in vpd) and DFHSIZE 16; packets with TPSD -1 have DFHSIZE 16, 6 or 0. A 16-byte DFHSIZE matches the 6-byte packet primary header plus a 10-byte PUS data field header (inference from the values; the header layout is not in this table). No packet is described in both plf and vpd, and 31 fixed packets have no plf entry. Eleven packets have type and subtype 0, including three ground frame-quality pseudo-packets 'Bad/Idle/Good complete transfer frame' (APID 1, SPIDs 1000002/3/6), all with the same key 0/0/1/0/0 and PID_VALID 'Y'. Per the ICD only the last imported of these would stay valid. APIDs 2048-2065 are used for internally generated 'LMS_NNO/CEB/MLG' packets (ground station telemetry, consistent with the reserved NNO/CEB/MLG names in pcf).
