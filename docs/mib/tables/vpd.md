# vpd.dat: Variable packet definition

<div class="osi-chips"><span class="osi-chip">ICD 7.0 §3.3.2.5.2</span><span class="osi-chip">19,863 rows in Solar Orbiter 2025-09-16</span></div>

vpd defines variable telemetry packets: any packet whose content follows the PUS structure rules, including repeated groups whose repetition count is read from the packet, nested repetitions, and parameters whose identity or type is given by an on-board parameter ID. It is used by the SCOS-2000 Variable Packets Display (VPD) and the related processing together with pcf, and has no relation to plf or to the dpf/gpf/spf display tables. A structure is identified by a TPSD, linked to packets through PID_TPSD, and its records are ordered by VPD_POS; parameter extraction starts PID_DFHSIZE bytes after the start of the source packet. Each parameter begins where the previous one ended, shifted by VPD_OFFSET: positive offsets create gaps, negative ones overlaps. Padding bits before a value are handled through PCF_WIDTH. vpd can also describe fixed packets just to show them in the VPD, one parameter per line with VPD_NEWLINE. Besides extraction, each record carries display attributes: column header, width, justification, new line, what to show and number format. Only packets defined in vpd show their parameters in full mode of the Packet History display. The table must be sorted by VPD_TPSD and VPD_POS.[^icd]

**Key:** `VPD_TPSD`, `VPD_POS`

## Relationships

- `VPD_TPSD` → [pid.PID_TPSD](pid.md#pid_tpsd): Structure used for packets whose PID_TPSD is not -1.
- `VPD_NAME` → [pcf.PCF_NAME](pcf.md#pcf_name): Parameter extracted/displayed; PCF_WIDTH (padding) and PCF_PTC (e.g. deduced 11) affect extraction.
- `VPD_PIDREF` → [pcf.PCF_PID](pcf.md#pcf_pid): Values of parameter-ID fields are resolved to parameter names.
- `VPD_CHOICE` → [vpd.VPD_TPSD](vpd.md#vpd_tpsd): A choice value selects another TPSD for the rest of the packet (not currently supported).

## History across ICD issues

ICD 5.1 (p. 45-48) already has the 14 fields in the same order; VPD_POS is not marked mandatory there. The ICD 7.0 Annex 1 list of changes for all evolution releases records that the VPD application supports nested repetitions (item 4, p. 244). ICD 6.2/6.3 updated the VPD_FORM description (p. 253). ICD 6.7 Draft A (p. 93-98) and 6.9 (p. 97-102) define VPD_FIXREP with values 0 and positive counts only (icd-6-9 p. 99); ICD 7.0 adds '-1' as a future extension (S2K-7750, p. 262). pyscos2000 (ICD 7.2) matches: key VPD_TPSD + VPD_POS, VPD_NAME and VPD_WIDTH mandatory, defaults GRPSIZE '0', FIXREP '0', CHOICE 'N', PIDREF 'N', JUSTIFY 'L', NEWLINE 'N', DCHAR '0', FORM 'N', OFFSET '0'.

!!! note "Notes from the extraction"
    No discrepancy between ICD 7.0 and pyscos2000. ICD typo: VPD_FIXREP's '-1' option refers to 'VPD_GRPSIZ'. Solar Orbiter 2025-09-16: 19,863 records describing 2,063 structures (one per TPSD-bearing packet), up to 610 positions in one structure. VPD_FIXREP is always 0 and VPD_CHOICE always 'N', consistent with choice structures being unsupported. VPD_DCHAR is always 0. 711 records are repeat counters (VPD_GRPSIZE &gt; 0, up to 130 for NSM00231 'STO Cat RN' in TPSD 80020). 1,449 records are parameter-ID fields (VPD_PIDREF = 'Y', e.g. NCD0C095 'OBCHP_Monitored Par ID'), and 2,886 records place deduced (PTC 11) parameters. VPD_WIDTH is 1 or 0 (1,983 hidden values). VPD_FORM is 'N', 'H' (613) or empty, VPD_JUSTIFY 'L', 'R' (71) or empty, and VPD_NEWLINE 'N' or empty. 389 records use a negative VPD_OFFSET to overlap the previous field, e.g. -32 for NCDD01S1 'CCSDS Sec Header'. VPD_DISDESC values are cut to the 16-character limit, sometimes keeping a trailing blank (e.g. 'OBCHP_Monitored ').
