    Solar Orbiter SWA instrument database¶

    SWA, the Solar Wind Analyser, is one of the ten Solar Orbiter instruments. Its Data Processing Unit (DPU) interface document describes a suite of four sensors - two Electron Analyser Systems (EAS1 and EAS2), a Proton Alpha Sensor (PAS) and a Heavy Ion Sensor (HIS) - each connected to the DPU by a 10 Mb/s SpaceWire link.1210 The 2007 Experiment Interface Document lists the same instrument as the "Solar Wind Plasma Analyzer"27, and planning documents refer to the sensors individually, for example the light-sensitive "SWA-EAS".2 The SWA/PAS team at IRAP (the DPU ICD cites IRAP documents for the PAS unit and its interface to the DPU)11 hosts the server from which this wiki copied the Solar Orbiter MIB, and the same server carries the SWA instrument database (IDB): the instrument's packets, parameters, calibrations and commands written as SCOS-2000 MIB tables, with release notes from Planetek Italia.37

    This page analyses two copied IDB versions - 6.3.4 (the file ASCII.zip) and 6.5.0 - reads the release notes against the data and against the SWA DPU Communications ICD, and checks, by name and by content, how much of each version is in the spacecraft database. The interface documents themselves are presented on Solar Orbiter instrument interfaces; the STIX instrument database is analysed the same way on Solar Orbiter STIX instrument database.

    The instrument behind the database¶

    The DPU is, in the words of its ICD, the "heart" of SWA: it provides power, control, temporary storage, communication and computing for the suite. Its hardware is a backplane with six SpaceWire splitters, two Data Processing Modules (each a communication and science data processing board plus a CPU board) and two Power Conditioning and Distribution Modules (PCDM), which also receive the spacecraft's high-power pulse commands and collect housekeeping.12 The application software receives telecommands, sends housekeeping, event and (when enabled) science telemetry, commands and powers the sensor heads (except HIS, which the spacecraft powers on a dedicated line), keeps five minutes of high-resolution EAS1, EAS2 and PAS data for transmission when an event trigger arrives, computes moments and compresses data, maintains time synchronisation, and exchanges data with the other instruments through PUS service 20.13

    The diagram follows §3 and §4 of the DPU ICD.1213 The software has three layers: the application software (the process control and TM/TC software PCMSW, and the science data processing software SDPSW), an application service layer with the PUS library, and a machine services layer with the VxWorks real-time kernel, the extended operating system EXOS and the board support package, all on a LEON2 processor. A boot software in PROM, which cannot be patched, tests the memories and loads the application from MRAM. The SDPSW compresses distributions losslessly with a CCSDS 121 compliant algorithm and computes the moments of order 0 (number density), 1 (number flux density vector), 2 (moment flux density tensor, as the ICD calls it) and, for EAS only, 3 (energy flux density vector).13

    Versions: the vdf table as a release history¶

    The ICD's vdf table normally holds a single record naming the database version; if several are present, the last one imported sets the name.29 The SWA IDB instead keeps all the versions it has been through, each with a release date in the comment and the major and minor numbers in VDF_RELEASE and VDF_ISSUE. Version 6.3.4 has 70 records:5

    MSSL, the source of the first version, is the Mullard Space Science Laboratory in the DPU ICD's acronym list.10 The records are not in chronological order inside each minor version (for example SWA_2.3.2 precedes SWA_2.3.1 and SWA_2.3.0), and SWA_6.3.4_beta, dated a day after SWA_6.3.4, is filed before SWA_6.3.0; by the ICD rule the effective name is the last record, SWA_6.3.4.529 67 of the 70 names are longer than the Char(8) of VDF_NAME, the longest having 14 characters; the ICD's importer truncates an over-long field and issues a warning.52931

    Version 6.5.0 does not record itself. Its vdf file holds the same 70 records with the same names and comments, but SWA_6.3.4 has moved up next to SWA_6.3.4_beta, before SWA_6.3.0, so the last record is now SWA_6.3.3_wa; none of the eight versions 6.4.0 to 6.5.0 has a record.6

    Inference

    Imported by the ICD rule, the 6.5.0 files would name the database after SWA_6.3.3_wa (and, truncated to 8 characters, SWA_6.3.), not 6.5.0. The folder name and the release notes are then the only places where the version appears. Whether the instrument team or the MOC renames the database on import is not stated in the available sources.

    The release notes¶

    IDB_relNotes.txt, inside the 6.5.0 zip, is headed "SWA IDB RELEASE NOTES", names Planetek Italia srl and one author, and carries a header date of 13/06/2016. It has 75 entries, from 2.0.0 (08/03/2016, "IDB version released with EGSE SW spacePTS v2.0") to 6.5.0 (17/06/2025), each with the version, date, change description and author.7 The IRAP directory also lists other SWA IDB versions (SWA_IDB_v5.1, v6.0.1, v6.3.3_wa, v6.3.4_beta2, v6.4.6), which were not copied.40

    Inference

    The DPU ICD lists Planetek ("PK") among its acronyms, has a Planetek address in its distribution list and carries the Planetek Italia logo in its page header next to those of TSD Space, Leonardo and SITAEL.10 This suggests that the IDB maintainer is part of the DPU team, but neither the ICD nor the release notes says so.

    Compared with the vdf records, the notes have no entries for the three earliest versions (00.2, 00.3 and 1.0), the vdf has none for 6.4.0 to 6.5.0, and three dates differ: 2.1.0 (notes 10/06/2016, vdf 09/06/2016), 5.1.0 (21/02/2018 against 12/02/2018) and 6.3.4_beta (03/12/2021 against 30/11/2021).76

    Inference

    The copy called 6.3.4 on this page appears to hold the 6.3.4_beta state. Its CIAT0068TC lacks the value 0 NOTHING, which the notes say 6.3.3 added and only 6.3.4_beta removed (the 6.3.4 entry itself reverts only PIA60352 and PIA60357), and its .dat files are dated 2021-12-03, the date that the notes give 6.3.4_beta.75 Because the SWA_6.3.4_beta record is filed before SWA_6.3.0, the ICD rule still names the database SWA_6.3.4.

    Parameters¶

    All 2 885 parameters are raw telemetry; 2 881 are named NIA... with PCF_SUBSYS = 109, and four ZZPAD008 to ZZPAD032 are 8-, 16-, 24- and 32-bit fillers.5 By name, 1 697 are NIA0..., 855 NIAD..., 286 NIAG... and 43 NIA1...; by description, 384 start with HIS, 218 with EAS1, 217 with EAS2, 72 with PAS and 33 with DPU.5 Types: 1 155 are 16-bit unsigned (PTC 3, PFC 12), 667 Booleans, 499 8-bit, 263 32-bit and 100 24-bit unsigned integers; 2 365 have a numerical and 520 a status category.5 The 855 NIAD parameters are exactly the "detail" side of the 855 rows of pcf_glob_det, which relate them to 166 container words.5 1 055 parameters appear in no plf or vpd entry; 206 have ground monitoring checks (158 hard, 168 soft limits in ocp in 6.3.4).5 The pcf table of 6.5.0 is identical to that of 6.3.4, row for row.6

All 2 841 names are also in ASW_sw_para.58 Version 6.5.0 adds one row, ZIA58950.6

    Commands¶

    The 6.3.4 IDB has 198 commands, all named ZIA58... and all with CCF_ACK = 9 (acceptance and completion reports): 45 of type 200, 43 each of types 201 and 202, 33 of 203, 21 of 204, and 13 standard ones - memory management (4), housekeeping (3), event enable/disable (2), science transfer enable/disable (2), time (1, TC(9,129)) and connection test (1).5 Version 6.5.0 has 201: one more of type 200 and one more each of 201 and 202.6 The DPU ICD's HIS internal table lists 27 type-204 commands; the IDB has 21 of those subtypes, and the release notes record six HIS commands removed in IDB 4.2.0 (August 2017).2167

    The single TC header NOM_TC has the same layout as the spacecraft one, but the 8-bit source ID is a fixed value 0x78 (120) - the ground source ID that the packet structure ICD reserves for direct commands - where the 2025 spacecraft MIB uses the element type O.5378 Two verification stages are defined: 58901 (acceptance) and 58907 (completion), both report-based (CVS_SOURCE = R) with a start offset of 0 and an interval of 20 seconds; every command uses both, which makes the 396 (6.3.4) and 402 (6.5.0) cvp rows.56 See Command verification in the MIB.

    Worked example: the cadence command, from ICD to IDB¶

    TC(200,162) "Sensor Cadence Mode" changes how often each sensor generates its science products. ICD issue 8.2 defines one 16-bit application data word: 8 spare bits, then a 2-bit rate for EAS1, EAS2, PAS and HIS. For EAS the values are 0b00 10 s (high cadence), 0b01 100 s (nominal) and 0b10 400 s (low); for PAS and HIS only nominal and low are defined.18 The IDB command ZIA58728 SWA_TC_SENS_CADENCE_MODE encodes exactly this layout:6

    The IIC packet in the database¶

    The inter-instrument communication note SOL-SGS-TN-0007 specifies SWA's contribution as a TM(3,25) with process ID 95, category 5 and SID 255, generated every 4 seconds, carrying 16 octets for distribution: a 4-octet heartbeat copied from the OBT coarse time, the PAS proton density (2 octets), the three solar wind velocity components (2 octets each) and 4 spare octets.1 Section 9 of the DPU ICD defines the same packet from the instrument side: generated once every 4 seconds, packet length field 0x1A, the heartbeat being the coarse time field of the on-board time, the density the order-0 PAS moment and Vx, Vy, Vz the order-1 PAS moments, all 16-bit values.24 The IDB's packet SWA_TM_II_INFO (SPID 58907) on APID 1525 implements exactly that:5

    The offsets and types are the plf and pcf entries of the IDB; the packet's TPCF_SIZE of 33 octets is 16 octets of headers, 1 octet of SID and the 16 octets of distributed data.5 The ICD's length field agrees: a packet data length of 0x1A = 26 means 27 octets after the 6-octet primary header, 33 in all. The types follow the SCOS-2000 code table, in which PTC 3 PFC 12 is a 16-bit and PFC 14 a 32-bit unsigned integer.34 The SID is not placed in the OBC data pool, and the OBC copies the 16 octets into octets 207 to 222 of the TC(20,128) it distributes to all instruments - to SWA itself at 8 Hz.3839 The same packet exists with the same SPID and layout in the 2025 spacecraft MIB; browse it as SPID 58907 in the SWA explorer or NIA01553 in the spacecraft MIB.8

    Inference

    The pattern - every 6.5.0 parameter, packet and layout present in the 2025 spacecraft MIB three months later with the same names, numbers and values, all commands but one, and mission-level additions (DARC flags, applicability conditions, spacecraft verification stages, the dropped TC(9,129)) only on the spacecraft side - indicates that the spacecraft MIB imports the SWA definitions from the instrument team's database and that ESA or the spacecraft team adds mission-level fields and decisions. The merging process itself is not described in the available sources: the 2007 Experiment Interface Document Part A leaves its section "Inputs to Satellite Database" to be written (TBW).28 The STIX database shows the same pattern (see STIX).
