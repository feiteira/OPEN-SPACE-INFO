    The Solar Orbiter MIB¶

    The Solar Orbiter Mission Information Base is the set of ASCII tables that tells the SCOS-2000 mission control system how to recognise every telemetry packet of the spacecraft, how to extract and calibrate every parameter, how to check limits, and how to encode, verify and sequence every telecommand. It follows the SCOS-2000 Database Import ICD (EGOS-MCS-S2K-ICD-0001), whose issue 7.0 is published next to the MIB as the "MOC-applicable" issue.12 Because more than a hundred operational releases were posted publicly, it is the only flight MIB this wiki can analyse row by row.

    Every number on this page comes from this wiki's own SQL queries on two releases:

    • 2025-09-16, MIB__20250916M25925PFMS001_SOL, the newest release (library page), and
    • 2020-04-16, MIB__20200416M10720PFMS001_SOL, the oldest (library page).

    Both were loaded into read-only SQLite databases with one table per .dat file, using the ICD 7.2 column names where known. The queries are shown in collapsed "SQL used" blocks. The tables themselves are explained on the MIB data model and the per-table pages such as pcf; every parameter, packet and command can be opened in the MIB explorer.

    Decoding the release name¶

    The vdf table of each release has a single record. The ICD defines VDF_NAME (Char(8)) as the database version name, VDF_COMMENT as a free comment and VDF_RELEASE and VDF_ISSUE as release and issue numbers; the name is shown on displays and checked, for example, when a saved command stack is reloaded.9

    Field 2020-04-16 2025-09-16
    VDF_NAME 10720PFM 25925PFM
    VDF_COMMENT 20200416-CSW3.0.3p1_MAS6.51 20250916-CSW3.1.2_MAS7.33
    VDF_DOMAINID 0 0
    VDF_RELEASE 10720 25925
    VDF_ISSUE 651 733

    These values are in the archive too: the SCOS-2000 packet header that the MCS files with every packet has DB Rel and DB Iss fields recording the VDF_RELEASE and VDF_ISSUE in force when the packet was archived.1011

    MIB__ 20250916 M 259 25 PFM S001 _SOL
      |        | |   |  |   |    '-- mission (Solar Orbiter)
      |        | |   |  |   '------- not explained in the available sources
      |        | |   |  '----------- VDF_NAME suffix (meaning not stated)
      |        | |   '-------------- two-digit year (25)
      |        | '------------------ day of year (259 = 16 September 2025)
      |        '-------------------- literal "M"
      '----------------------------- release date YYYYMMDD

    Inference

    The decoding above is this wiki's reading of the two releases, not a documented convention. The three digits after M equal the day of year of the date (259 for 2025-09-16, 107 for 2020-04-16), which the project's survey also observed on the IRAP listing;7 the next two digits equal the two-digit year; and the five digits together are VDF_RELEASE (25925, 10720) and the first five characters of VDF_NAME. The comment names a Central Software (CSW) version - CSW being the OBC software of the ICD13 - and a "MAS" version whose number matches VDF_ISSUE (7.33 / 733, 6.51 / 651). The meanings of PFM, S001 and MAS are not stated in the available sources.

    Parameters¶

    Nature, type and calibration category¶

    Of the 126 745 monitoring parameters of 2025, 125 161 are raw telemetry (PCF_NATUR = R), 1 582 are dynamic OL synthetics (D) and 2 are saved synthetics (S); the ICD defines these natures, plus P (SPEL), H (hard-coded) and C (constant), which Solar Orbiter does not use.1116 By calibration category, 100 087 are numerical (N), 26 538 status (S, textual calibration) and 120 text strings (T), the categories defined for PCF_CATEG.1117 The most common types are PTC 3 unsigned integers (50 341), PTC 5 reals (29 718) and PTC 2 enumerations (29 443); see MIB parameter types for the full breakdown.11

    107 791 parameters are placed in fixed packets by plf and 2 720 in variable packets by vpd. 15 067 raw parameters appear in neither; 11 945 of those are listed in the mission-specific ASW_sw_para file and 10 786 are "detail" entries of pcf_glob_det (see mission-specific files).11

    Inference

    Solar Orbiter's naming convention is not documented in the library sources. The pattern is consistent with: first letter = object kind (N monitoring parameter, Z command, A sequence, Y packet, C calibration, P command parameter); second letter = owner family (C central software, I instrument, S SSMM/STR/SADE, P PCDU, R RIU and wheels, A antenna mechanisms, D DEU/transponder, M IMU, T thermal, X derived monitoring definitions, Y ground); third letter = application or instrument. The instrument letters are M MAG, U EUI, D EPD, P PHI, X STIX, W RPW, H SOLOHI, C SPICE, A SWA and T METIS, the same letters as in the commands (ZIA... goes to the SWA APID 1532, ZIT... to METIS APID 1084). Other ESA projects used different conventions, for example SPIRE's SM/SC prefixes.33

    The instrument databases support the instrument letters for two cases: every SWA database parameter but four ZZPAD fillers is named NIA... and every SWA command ZIA..., and every STIX parameter but four fillers is NIX... and every STIX command ZIX....3435

    APIDs and packets¶

    The 2025 release defines 11 150 packets (SPIDs) on 293 distinct APIDs, with 193 distinct type/subtype pairs across 66 service types; the 2020 release had 9 027 packets on 268 APIDs.1112 The packetiser recognises a packet by its APID, type, subtype and up to two extra identification fields located by pic, and looks up the SPID in pid; APIDs 0 to 2047 are for spacecraft packets and 2048 and above for packets generated on the ground.2324 Solar Orbiter's APID is a 7-bit process ID followed by a 4-bit packet category (see the mission page), so every APID can be decoded:25

    APID Packets What it is

    34 1 OBC_HPTM_packet, process 2 category 2

    The time, idle, frame and internal packets match the DDID and the packet structure ICD.292711 The 2048-2065 range is the one the ICD reserves for packets not generated by the spacecraft.23 The station codes NNO, CEB and MLG match the New Norcia, Cebreros and Malargüe stations of the DDID's ground station list, but what "LMS" means is not stated in the available sources.30

    The virtual APIDs 1953 to 1996 are the most interesting. Their PIC rules add a second identification field: for example events TM(5,1) on APID 1975 are split by an 8-bit field at octet 18, giving 12 packets "LEOP_AS_Step_1_Executed" to "Step_12"; TM(12,9) monitoring list reports on APIDs 1986-1990 are split into parts #1 to #3 by an 8-bit field at octet 19 and a second 8-bit field deep inside the packet (octet 883 to 2755 depending on the APID); TM(6,6) dumps on 1961, 1965, 1976 and 1977 by a 32-bit field at octet 18.11 The mission file dup.dat lists 69 (SPID, APID) pairs whose SPIDs are ordinary packets of real APIDs - for instance SPID 10153 (event 2753 on APID 231) is paired with APID 1975.11

    Inference

    dup.dat appears to tell a mission-specific ground process to duplicate selected packets onto a virtual APID, where the PIC and PID tables then decode them with a finer identification than the spacecraft's APID allows. This explains why APID 1975 holds 12 variants of one LEOP event and why APIDs 1986-1990 and 1992-1996 hold per-application monitoring list and functional monitoring status reports (1991 carries star tracker 2 mode transition events). Neither dup.dat nor this mechanism is described in the ICD or the DDID.

    Packet sizes¶

    The ICD defines TPCF_SIZE as the total size of the SCOS-2000 packet, recommending the source packet length plus the SCOS-2000 header (64 or 76 octets depending on the header version), and 0 for truly variable packets.21 The time packet has TPCF_SIZE = 14, exactly 6 octets of primary header plus the 8 data octets of Annex 4,1128 and the SWA inter-instrument packet has 33, its source packet length (see the SWA page).

    Inference

    These values suggest that Solar Orbiter fills TPCF_SIZE with the source packet length rather than with the SCOS-2000 packet size that the ICD recommends. The field is not used by SCOS-2000 itself, and the mission's convention is not stated in the available sources.

    Quality notes¶

    • Referential integrity is good. All 400 792 plf records point to an existing packet, and all but one (NYM0796V in SPID 66028) to an existing parameter; every pcf_glob_det name and every dup SPID exists.11
