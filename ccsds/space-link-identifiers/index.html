    Space link identifiers: SCIDs, VCIDs, APIDs and SANA¶

    Every CCSDS space link protocol labels its data units with identifiers. These are small numeric fields that say which kind of frame or packet this is, which spacecraft it belongs to, and which channel or application it is for. Some values are defined by CCSDS in the protocol standards. Some are assigned by CCSDS when an agency asks for one. Others are left to each project.25 This page lists all of them, gives their sizes and reserved values, explains the procedure by which the Space Assigned Numbers Authority (SANA) assigns spacecraft identifiers, and shows what the identifiers look like in a real mission database, the Solar Orbiter MIB.

    Status of the sources

    CCSDS 135.0-B-4 Space Link Identifiers (October 2009) collected the identifiers in one Blue Book. The copy in this wiki's library is stamped CCSDS Historical Document: it is no longer current. The CCSDS overview Green Book (2023) states that SANA replaces the retired Space Link Identifiers Blue Book: the identifier names and values now live in SANA registries. SCID assignment follows the Magenta Book CCSDS 320.0-M-7.140 This page therefore uses 135.0-B-4 for structure and history and the current protocol Blue Books for values, and says where they differ.

    Three ways of managing an identifier¶

    CCSDS manages each identifier in one of three ways, so that values can be added or changed without editing the protocol standards:54

    Method Who sets the values Examples
    Defined by CCSDS Fixed in the protocol specification Transfer Frame Version Number, Packet Version Number, Proximity-1 Port IDs, Encapsulation Protocol IDs
    Assigned by CCSDS Given out on request by agencies, under a separate procedure Spacecraft Identifier (SCID)
    Managed by projects Each project, independently. CCSDS may reserve a few values for cross-agency use VCID, MAP ID, APID, CFDP Entity ID

    Lossless data compression, SCPS-FP and the TM and TC synchronization and channel coding standards use no identifiers and are left out.5

    The identifier hierarchy¶

    The data link protocols nest their identifiers. A Physical Channel, one stream of bits in one direction, is named only by management and never appears in a frame. Frames with the same Master Channel Identifier (MCID) form a Master Channel. Usually that is the whole Physical Channel, but several spacecraft can share one Physical Channel as several Master Channels with the same TFVN. Frames with the same Global Virtual Channel Identifier (GVCID) form a Virtual Channel. In TC and USLP, frames that also share a MAP ID form a MAP Channel.41454953

    \[\begin{aligned} \text{MCID} &= \text{TFVN} + \text{SCID}\\ \text{GVCID} &= \text{MCID} + \text{VCID}\\ \text{GMAP ID} &= \text{GVCID} + \text{MAP ID} \quad\text{(TC and USLP)} \end{aligned}\]
    flowchart TB
    PC["Physical Channel<br/>(name set by management)"] --> MC["Master Channel<br/>MCID = TFVN + SCID"]
    MC --> VC["Virtual Channel<br/>GVCID = MCID + VCID"]
    VC --> MAP["MAP Channel (TC, USLP)<br/>GMAP ID = GVCID + MAP ID"]
    VC --> PKT["Packets in the data field<br/>PVN, then APID (Space Packet)<br/>or Protocol ID (Encapsulation)"]
    MAP --> PKT
    PX["Proximity-1 link"] --> PXI["SCID + Source-or-Destination flag<br/>PCID (one of two receivers)<br/>Port ID (output port)"]

    Channel nesting of TM, TC, AOS and USLP, and the Proximity-1 triad.4142

    Packets add their own naming level. The APID of a Space Packet is unique only inside one naming domain, which usually corresponds to one spacecraft or one element of a constellation. Each project allocates the APIDs of its own domain.67

    Transfer Frame Version Numbers¶

    The TFVN tells receivers which frame format follows. It is defined by CCSDS. A Physical Channel must not mix frames of different versions.1141

    Version Binary Frame Defined in
    1 00 TM Transfer Frame CCSDS 132.0
    1 00 TC Transfer Frame CCSDS 232.0
    2 01 AOS Transfer Frame CCSDS 732.0
    3 10 Proximity-1 (Version-3) Transfer Frame CCSDS 211.0
    4 1100 USLP (Version-4) Transfer Frame CCSDS 732.1

    The first four rows come from 135.0-B-4. TM and TC share version 1 and are told apart by the TM Attached Sync Marker or the TC Start Sequence.1146 USLP took the last free 2-bit value, 11, and appended 00 to form a 4-bit TFVN, 1100. This leaves room for future versions.55 A Proximity-1 receiver uses the same two bits to accept Version-3 (10) or Version-4 (11) frames and rejects 00 and 01.63

    Spacecraft identifiers per frame version¶

    The SCID field size depends on the frame version, so CCSDS 320.0-M-7 keeps a separate SCID table for each TFVN:24

    Version TFVN SCID range Bits Protocols
    1 00 0–1023 10 TC and TM
    2 01 0–255 8 AOS
    3 10 0–1023 10 Proximity-1
    4 1100 0–65 535 16 USLP

    Linking a spacecraft to a TFVN is a managed parameter. A spacecraft that uses protocols with different TFVNs may need two or more distinct SCIDs.24 In USLP the 20-bit global SCID (TFVN.SCID, the same thing as the MCID) runs from 0xC0000 to 0xCFFFF.59

    The SCID is static throughout all mission phases in TM and TC.4650 The TM Blue Book adds that SCIDs are unique only within the spacecraft's frequency band. The same value may be given to another spacecraft in another band.46 In TM, TC and AOS the SCID names the spacecraft associated with the data. Proximity-1 and USLP add a Source-or-Destination Identifier: 0 means the SCID is the sender, 1 means it is the intended receiver.6256 ECSS-E-ST-50C requires that all telecommands carry an identifier of the destination spacecraft. All telemetry must carry an identifier of the source spacecraft, which ground systems normally keep as an annotation. Frames must identify the spacecraft and link, and the frame version number can identify the link.747576

    Assigning SCIDs: CCSDS 320.0-M-7¶

    The CCSDS Spacecraft Identification Field Code Assignment Control Procedures govern how SCIDs are requested, assigned and given back. They also define who may take part and how SCIDs may be used. Issue 7 (November 2017, with Technical Corrigendum 1 of July 2019) applies to TC, TM, AOS, Proximity-1 and USLP. All organisations that need a SCID for CCSDS space communication must follow it.22

    Issue Date Change from the document control page
    320.0-B-1 to -B-6 1993 to 2013 "CCSDS Global Spacecraft Identification Field" Blue Books
    320.0-M-7 November 2017 Adds the frequency band as a qualifier (Q-SCID); replaces the paper request form by the SANA web form; becomes a Recommended Practice (Magenta Book)
    Cor. 1 July 2019 Adds USLP (version 4) frames; frequency bins now use ITU ranges; editorial updates

    Restated from the document control pages.2021

    Why SCIDs are qualified¶

    The SCID fields of version 1 to 3 frames are only 8 or 10 bits long, and they must tell apart all the spacecraft that are operating at the same time. The SCID therefore cannot be a permanent identifier, and SCIDs must be reused. The procedures are meant to ensure that data from one spacecraft is never mistaken for another's, and that commands are never acted on by the wrong spacecraft.25 Missions with different frequency bands are already isolated, so each band can be treated as a separate namespace. Hence:2523

    • GSCID (global spacecraft identifier) = TFVN . SCID, where "." means concatenation.
    • Q-SCID (qualified spacecraft identifier) = FB . TFVN . SCID, where FB is the frequency band.
    • Each TFVN has its own assignment table, and each frequency band within a TFVN has its own table.
    • A spacecraft that uses more than one protocol or band may receive several Q-SCIDs. SANA tries, but does not guarantee, to give the same number in each domain.
    • Every registered spacecraft also receives a permanent ISO object identifier. The SCID is valid only during operations, but the object identifier is permanent.

    The frequency bands follow ITU usage for Earth exploration-satellite (EESS), space research (SRS) and space operation (SOS) services. SANA uses frequency band designators for them:27

    Range Band Near-Earth downlink allocation (SANA designator) Deep-space downlink allocation (designator)

    Roles¶

    Role Duties
    CCSDS Secretariat Resolves issues the procedures do not cover; finds an Agency Representative for requests from organisations without a CCSDS agency; keeps the lists of agencies and Heads of Delegation
    Agency Head of Delegation (HoD) Appoints the agency's Agency Representative (AR) and keeps the AR's contact data up to date in SANA
    Agency Representative Submits Q-SCID requests, deals with SANA on them, watches the agency's missions, and relinquishes their Q-SCIDs no later than two months after the end of the operational phase
    SANA Keeps the agency, HoD and AR lists; reviews, logs and assigns Q-SCIDs per band; assigns object identifiers; keeps separate Q-SCID registries per band and TFVN; recovers Q-SCIDs of finished missions for reuse

    Request, assignment, use and relinquishment¶

    flowchart LR
    A["Agency Representative<br/>fills the SANA web form:<br/>TFVN, uplink and downlink bands"] --> S["SANA reviews and logs<br/>the request"]
    S --> Q["Assigns Q-SCID(s) by availability<br/>(same number in each band if possible)<br/>+ spacecraft object identifier"]
    Q --> U["Used through the active phases:<br/>pre-launch tests, launch, operations"]
    U --> E["End of operations<br/>(AR and mission manager decide)"]
    E --> R["AR relinquishes via the form<br/>within two months"]
    R --> B["SANA puts the number at the<br/>bottom of the free stack"]

    Sections 3.2 to 3.5.33343236

    • Requests. Only the designated AR may request, using the online form at the SANA site, one form per request. Organisations without a CCSDS agency go through the Secretariat. The form gives the TFVN and the uplink and downlink bands, not exact frequencies. E-mail is accepted only in exceptional cases.33
    • Assignment. SANA alone assigns, based on availability. Each Q-SCID is unique within its TFVN and band while assigned, and assignments are made spacecraft by spacecraft. Requests to reserve blocks for unspecified spacecraft are refused, but a multi-spacecraft mission may receive several Q-SCIDs. A specific number is honoured only in exceptional cases and only if free, so requesters should check the registry first.3435
    • Simulators. SANA no longer assigns SCIDs for simulation, test or ground assemblies, because they never radiate. Missions may manage such SCIDs internally. Protoflight models and simulators may receive their own object identifier, treated as a "non-radiating" Q-SCID, but no separate SCID.2635
    • Lifetime. A Q-SCID may be used through all active phases. Soon after telemetry is received, the SCID should be replaced by the permanent object identifier or another agency identifier, because SCIDs are reused and identifying archived data by SCID is problematic.32
    • Relinquishment. The AR and the mission manager decide when operations are complete. The AR marks "RELINQUISH current GSCID" on the form. SANA puts the number at the bottom of the stack of free SCIDs, so that it is reused as late as possible.36

    The SANA spacecraft identifier registry¶

    Annex A describes the registry: one table per Q-SCID version, with these columns:3738

    Column Content
    Spacecraft Name Up to 64 characters, assigned by the agency
    Channel TC, TLM, AOS or Other
    Version Number(s) From table 1-1; may be extended for new protocols
    SCID Hex, from 001 to the maximum for the version
    GSCID Hex, per frequency band
    Object ID ISO object identifier under 1.3.112.4.7
    Requestor Name, Affiliation, Affiliation Country Must match the AR, Organization and ISO country registries
    Last Request Date, Registered by, Status Status: Assigned, Returned, object identifier only, or null
    Spacecraft Name Abbreviation and Alias(es) Agency abbreviation, pre- and post-launch names
    S/C Transmitting and Receiving Frequency Band(s) Band designators from table 2-1
    Expected Launch Date, Expected Mission End Date, Note Dates in yyyy-mm-dd; the end date can be extended on request

    The registration rules allow a request for an object identifier only, which helps organisations that do not use CCSDS link protocols but want a registered designator. If a request names a band that has no bin yet, SANA creates bins for it in all TFVNs. Requests are accepted only from organisations of type member agency, observer agency or affiliate, and only from persons with the AR role.3839

    Who assigns, in the Blue Books

    The TM, AOS and USLP Blue Books say that SANA assigns SCIDs under CCSDS 320.0-M. The TC Blue Book (issue 4, 2021) still says the CCSDS Secretariat assigns them. Under 320.0-M-7, all Q-SCID assignments are made by SANA.4652545034

    Virtual channel and MAP identifiers¶

    VCIDs and MAP IDs are managed by projects. They need not be numbered consecutively.10475051

    • TM: 3 bits, VCIDs 0 to 7, none reserved. A frame with only idle data is marked by the First Header Pointer value 11111111110, not by a VCID.4748
    • TC: 6 bits, none reserved. The MAP ID is in the segment header (bits 2–7). If MAPs are not used but a segment header is present, the MAP ID is a constant.5051
    • AOS: 6 bits. All zeros if only one VC is used. VCID 63 (all ones) is reserved for Only Idle Data (OID) frames. This was the only VCID that 135.0-B-4 reserved.5212
    • USLP: 6 bits. VCIDs 0 to 62 are free, and VCID 63 is reserved for OID frames, which also use MAP ID
    • MAP IDs are 4 bits (1 to 16 MAP channels). Each SDU is on one MAP at a time and must be finished before another MAP's SDU starts on the same VC. SANA lists USLP VCIDs as unmanaged.575859
    • Proximity-1 has no VCID. With Version-4 frames over Proximity-1, the most significant VCID bit stands for the PCID, which leaves 32 VCIDs.60

    Proximity-1 identifiers¶

    Proximity-1 uses a triad: the SCID with its source-or-destination flag, a PCID that selects one of two receivers, and a Port ID that routes user data to a logical or physical port inside the receiving spacecraft.4264 Port IDs are defined by CCSDS. 135.0-B-2 (2005) added them, and 135.0-B-3 clarified the meaning of the packets port.310 The last published assignment is:16

    Port ID Forward link (both PCIDs) Return link (both PCIDs)
    000 Bitstream Bitstream
    001 Hardware commands Reserved by CCSDS
    010 Packets (Space Packet, SCPS-NP, Encapsulation, IPv4) Packets
    011–111 Reserved by CCSDS Reserved by CCSDS

    The current Proximity-1 Blue Book refers to the SANA registry for the reserved Port IDs. Its issue 6 required no SANA action and keeps the existing registries.6566

    Packet-level identifiers¶

    Packet Version Numbers¶

    Every packet carried by a Space Data Link Protocol starts with a 3-bit Packet Version Number. Its values are defined by CCSDS and held in SANA. Receivers use the PVN to find each packet's length field:141944

    PVN Binary Packet Length field (bits from packet start) Meaning of the length
    1 000 Space Packet 32–47 Data field octets minus 1 (add 7 for the whole packet)
    2 001 SCPS-NP 3–16 Total octets including the header (minimum 4)
    8 111 Encapsulation Packet 8–15, 16–31 or 32–63 Total octets including the header

    Application Process Identifier (APID)¶

    The APID is bits 5–15 of the Space Packet primary header: 11 bits, 0 to 2047. It names the managed data path and may identify the sending or receiving application on a spacecraft. Missions decide whether it means source, destination or packet type.6968 APIDs are managed by projects, need not be consecutive, and are unique only within their naming domain. A mission with several processors or spacecraft must sub-allocate the single domain or extend it through its own secondary header fields.69688

    Reserved APIDs have shrunk over time:871

    Source Reserved APIDs
    CCSDS 135.0-B-4 (2009), table 5-2 2040–2044 possible future use; 2045 CFDP; 2046 ISO 8473; 2047 idle packet
    CCSDS 133.0-B-2 (2020) and the SANA policy it set 0–2046 unmanaged; 2047 idle packet (11111111111) only

    Issue 1 of the Space Packet Protocol reserved APIDs for carrying PDUs of other protocols such as CFDP and LTP. Issue 2 made that coupling mission-specific and removed those reservations from the SANA registry.86971

    Encapsulation and other protocol identifiers¶

    The Encapsulation Packet names its payload with a 3-bit Encapsulation Protocol ID (bits 3–5). The value 000 marks an Encapsulation Idle Packet, 110 means the 4-bit extension field identifies the protocol, and 111 means mission-specific private data. The recognised values are held in SANA.7273 135.0-B-4 listed 010 IPE, 011 CFDP, and 001, 100 and 101 reserved. All extended IDs 0000–1111 were reserved at the time.15 Its annex A defined the Internet Protocol Extension (IPE): a header of one or more octets after the Encapsulation header. The least significant bit of each octet is 0 if another octet follows and 1 in the last octet, so only odd values are valid (33 IPv4, 87 IPv6, 97–113 header-compression formats).1718 USLP adds a 5-bit USLP Protocol Identifier (UPID) in its data field header. SANA manages the values 00000–11111.59

    Security aspects¶

    135.0-B-4 defines no confidentiality, integrity, authentication, access control, availability or auditing measures for the identifiers. It refers to the individual protocols for these.6 See security in CCSDS space links.

    A small inconsistency in the ICD

    The ICD says the suggested TC VCID values are "Zero and One", but the two values it lists are 000001 and 000010, that is 1 and 2.78 The MIB uses 1 and 2 (below).

    None of the MIB tables queried for this page holds the SCID or the VCIDs as a configuration value. The MIB does, however, decode them where they appear in telemetry. The packet "Good mini-transfer frame" (SPID 66980, TM(161,5) on APID 1966: process ID 122, in the ICD's EGSE range 112–127, and packet category 14, "Reserved OCC/EGSE") lays out the TM frame header: a 2-bit TF version number at bit 0, a 10-bit "Spacecraft Id." at byte 0 bit 2 (PCF_PTC 3, PCF_PFC 6), a 3-bit "VC Id." at byte 1 bit 4, then the frame counts, data field status, secondary header and the CLCW. Bad and idle frames have their own SPIDs, 66981 and 66982.92838182 These positions are exactly bits 0–1, 2–11 and 12–14 of the TM primary header.46 In the CLCW part, 18 parameters are split per TC virtual channel ("VC1 ..." and "VC2 ..."). Each is valid only when the CLCW's 6-bit VC Id (NYGD0659) equals 1 or 2, through PCF_VALID and PCF_VALPAR. A textual calibration shows the value as "VC 1" or "VC 2".9284 The OBC's own housekeeping, TM(3,25) "DMS OBC Status Slow", reports the VCIDs of both decoders' CLCWs (PDEC_CLCW.A.VCID, PDEC_CLCW.B.VCID).92 Ground-generated packets carry a 16-bit "GS Spacecraft ID" (TM(165,1), APID 1966), matching the NCTRS packet headers described on NCTRS and NIS.92

    See the packets in the explorer: good mini-transfer frame, NYGD0659 and NYGDA659.

    Inference

    The "mini-transfer frame" packet has fields for the frame header (6 octets), a 4-octet secondary header (8-bit ID at octet 6 and 24-bit data at octet 7), the CLCW at octet 10, the frame error control field at octet 14 and the earth reception time from octet 16. These are exactly the header and trailer fields that the ICD puts in every Solar Orbiter TM frame: a secondary header with an 8-bit ID and a 24-bit extension of the VC frame count, a CLCW in the Operational Control Field and a Frame Error Control Word.80 The packet apparently carries a TM frame without its data field, so that the control system can monitor frame-level identifiers and the CLCW of every frame. The MIB also defines "Good", "Bad" and "Idle complete transfer frame" packets (SPIDs 1000006, 1000002 and 1000003, type 0, APID 1), which fits this reading of "mini".92 This is deduced from the parameter offsets and descriptions. The packets are not described in the documents in this wiki's library.

    On the telecommand side the MIB does carry the MAP ID. The ICD defines CCF_HIPRI as marking a high-priority command whose MAP ID is forced to the value in CCF_MAPID (0–63), and which cannot be time-tagged on board or aggregated with others. CCF_MAPID is irrelevant unless CCF_HIPRI is Y.89 In the September 2025 release:92

    CCF_PKTID (header) CCF_HIPRI CCF_MAPID Commands APID What they are
    HPC1_TC (HPC_TC_Packet_Header) Y 0 125 44 CPDU high-priority (HPC-1) commands, e.g. ZBC04001 "Select PM A EEPROM Image 1"
    NO_HDR (TCP Header for CF/CS) Y (empty) 5 none Frame-level directives: UNLOCK and SETVR (control frames, CCF_CTYPE F), RESET, TC_ONLY and REIN_TTR (control segments, R)
    NOM_TC (NOM_DH_TC_Packet_Header) N empty, 1 or 54 5 318 30 APIDs Ordinary PUS commands

    MAP ID 0 for the 125 CPDU commands matches the ICD (process ID 2 is "High Priority TC Functions to CPDU (MAP ID = 0)").7782 The NO_HDR entries have no APID because they are not packets. The ICD defines CCF_CTYPE F as a BC frame (Unlock and Set V(R)) and R as a control segment, whose PCDF/CDF entries describe a frame data field, not a packet.87 These are the COP-1 control commands. 128 ordinary commands carry CCF_MAPID 1 and 77 carry 54, all with CCF_HIPRI = N.92

    Inference

    The values 1 and 54 in non-high-priority commands have no effect under the ICD rule above. The value 1 is the MAP ID that the Solar Orbiter ICD assigns to all normal (non-CPDU) commands, so those 128 entries merely restate the MAP ID the commands use anyway.77 The 77 commands with 54 are all on APID 876, whose process ID is 54 (an EPD process). This suggests that an instrument team's tool copied the process ID into the field. The 2020 release already has the same pattern (115 commands with 1, 77 with 54).93

    APIDs in the MIB¶

    SCOS-2000 extends the APID beyond 11 bits for its own purposes. PID_APID and CCF_APID are 0–2047 for spacecraft packets and commands, and 2048–65 535 for anything else, such as packets generated by SCOS-2000 or by SCOE equipment.8588 When a command is encoded, its packet header comes from the tcp/pcdf tables. A pcdf element of type A takes its value from CCF_APID, and the source sequence counter is kept per APID.86 In the Solar Orbiter headers NOM_TC and HPC1_TC, that element is the 11-bit field at bit 5, after a fixed version 000 and type bit 1. The secondary header flag is 1 for PUS commands and 0 for CPDU commands, and the sequence flags are fixed at 11.92 CCF_RAPID may name a redundant APID for redundant units. Solar Orbiter uses none.9092 The optional dst table routes commands per APID and sends everything else to the NCTRS. Its only Solar Orbiter row sends APID 1372 (SPICE) to EGSE.TC.0x8800, discussed on SCOS-2000 as EGSE.9192

    Solar Orbiter divides the 11-bit APID into a 7-bit process ID and a 4-bit packet category. All telecommands use category 12.8182

    The MIB follows this exactly. Every command with an APID uses category 12, on 32 distinct APIDs:92

This is legal, because the Packet Type bit tells a telecommand (1) from telemetry (0) with the same APID.9270

    On the telemetry side, the 2025 release defines 11 150 packets on 293 APIDs (0 to 2065), with 287 of them below 2048. The 2020 release has 9 027 packets on 268 APIDs (0 to 2047). The command APID set is identical in the 2020 and 2025 releases.9293

    All information on this site was retrieved from sources that are publicly available online. They include CCSDS and ECSS standards, ESA/ESOC documents, conference papers, and a Solar Orbiter MIB release posted by an instrument team. Every page cites the documents it relies on.

    The Sources & copies page lists each document with a link back to its original location and the date and time we copied it.

    This is an independent, community wiki. It is not affiliated with or endorsed by ESA, CCSDS, ECSS or any mission team. Third-party documents remain the property of their owners.
