    SLE forward service: Forward Space Packet (FSP)¶

    The Forward Space Packet (FSP) service lets a mission send telecommand Space Packets to a spacecraft through someone else's ground system. The packets can go in sequence-controlled mode or in expedited mode.1 Of the forward SLE services for conventional telecommand (FCLTU, FSP and Enhanced FCLTU), it is the one that works at packet level.3 The user hands over whole packets. The provider does the rest: it blocks or segments the packets into TC Transfer Frames, runs the sending end of COP-1, encodes each frame into a CLTU and radiates it.2 Several users, each with its own service instance, can share one Virtual Channel (VC) and one uplink. The provider multiplexes their packets by fixed rules, so the users do not have to coordinate with each other.23

    Compare this with FCLTU, where the user builds the frames and CLTUs and runs COP-1 itself. The SLE overview explains the concepts that FSP shares with the other services (BIND, states, authentication). The architecture behind it is on the cross support reference model and service management.

    What FSP does¶

    The user sends packets wrapped in SLE-SDUs with FSP-TRANSFER-DATA. The provider reads the Packet Primary Header to check, for example, that the APID is one the user may use. It does not otherwise look at, interpret or change the packet. A telecommand packet with a valid header is sent bit for bit as received.2 Through the operations of the service the user can bind, send annotated packets, get notifications and status reports, stop and restart sending, change some parameters, invoke COP-1 directives, throw events at complex management, and unbind.212

    FSP was conceived for packet structures in general. This issue handles only CCSDS Space Packets, and only on the TC protocol stack (TC SDLP, COP-1, TC synchronization and channel coding).9 The FSP version of the TC VC Data Insertion function does not apply Space Data Link Security. The reason given is that a user would not want to tell a third party (the FSP provider) how its SDLS is configured.19

    Where FSP sits: the forward TC functional groups¶

    Three SLE Functional Groups (SLE-FGs) produce FSP. The data channel between two FGs is carried by an SLE transfer service if the FGs are in different SLE Complexes, and by local means if they are in the same complex.10 No Recommended Standard exists for the Forward TC Frame (FTCF) service. So, until CCSDS publishes one, the CLTU Generation FG and the TC VC Data Insertion FG must be in the same complex.10

    • Forward TC VC Data Insertion FG. For each FSP instance it takes the packets out of the SLE-SDUs and blocks or segments them into TC frames. For sequence-controlled frames it sets the Frame Sequence Number and keeps a copy. It reads the CLCWs from Operational Control Field channels (Control Word Type 0 only) and retransmits or deletes the kept frames.19 It also provides the TC VC Access (TC VCA) service, but only one of the two service types is allowed on a given VC.30
    • Forward CLTU Generation FG. It optionally randomizes the frames, BCH-encodes them and adds the start and tail sequences.22 For FSP a CLTU carries exactly one TC frame, even though the coding standard allows more.23
    • Forward TC Space Link Processing FG. It checks from the CLCW that the physical channel is available, generates the acquisition and idle sequences of the PLOP in effect, and modulates and radiates the CLTUs.24 This is the same function that provides FCLTU, and annex D reuses the FCLTU rules for it.27

    The reference model gives FSP two production profiles. The AOS profile runs through the Forward AOS VC Data Insertion and AOS Space Link Processing FGs. The TC profile runs through the three FGs above.31 FSP 912.3-B-3 specifies only the TC profile.9 The reference model adds two rules for TC. Segmented packets can only be sent with sequence control. If FSP and TC-VCA are both active on one VC, only one of them can be sequence-controlled.32

    When the FGs are in different complexes, FSP depends on the FTCF and/or Forward CLTU services underneath it. The FSP schedule must then fit the schedules of those underlying services.33

    What the provider checks in each packet¶

    The provider looks only at the 6-octet Space Packet primary header, and only to enforce what service management has set up.234

    Field layout from the Space Packet Protocol. Version '000' and Type '1' for telecommand are its values.3536 The checks and diagnostic codes come from FSP-TRANSFER-DATA.3439

    The apid-list parameter is either any or an ascending list of up to 2,048 APIDs (0 to 2047).3934 The ASN.1 allows maximum-packet-length values from 7 to 65,542 octets.40 That is the length range of a complete Space Packet.37 The data parameter of FSP-TRANSFER-DATA, however, is an ASN.1 SpaceLinkDataUnit of 1 to 65,536 octets (see Notes on the specification text).8 The provider buffers only complete packets.41

    Production, provision and the managed parameters¶

    FSP separates service provision, which makes the operations available to one user, from service production, which turns the FSP channel into the RF channel. Provision parameters, such as the status-report frequency, affect one instance. Service management sets them when it creates the instance, and the user may change them through operations. Production parameters, such as maximum packet length or the VC multiplexing scheme, can affect several instances and the complex's resources, so only service management may change them. There is one exception: COP-1 directives. For each VC, one service instance may invoke them. Some directives act on the spacecraft, so FSP treats them as part of the telecommand service rather than of its management.42 One production instance may serve several FSP instances. Production extracts the packets from the concurrent streams and multiplexes them onto the space link, independently of any single instance.43

    Service packages, agreed between SLE Utilization Management and SLE Complex Management, define which instances exist, when, and their initial parameters. Production parameters include the VC, the multiplexing schemes, the maximum packet and frame lengths, and the CLTU-generation and space-link configuration. Provision parameters include the instance's start and stop times.44 The service package also sets the provider's buffer size in octets.41

    The conformance matrix (annex E) makes every operation mandatory except FSP-THROW-EVENT, which is optional. Version negotiation in FSP-BIND is optional, and so are the credentials parameters and stop-production-time.     The rules common to all operations are the usual SLE ones. Every confirmed operation returns a result, plus a diagnostic when the result is negative. 'Other reason' may be used only when no specific value fits. Checks should be made in the order the diagnostics are listed, and an implementation that uses another order must document it.49 Access control is two-level: initiator and responder must be registered with each other, and both must be authorised for the instance.50 Authentication can be 'all' (every invocation and return except PEER-ABORT), 'bind' or 'none'.51 Every confirmed operation except BIND and UNBIND carries an invoke-ID (0 to 65,535). Such operations are non-blocking, and a duplicate outstanding ID is rejected with 'duplicate invoke-ID' (common diagnostic 100).528

    FSP-BIND, FSP-UNBIND and FSP-PEER-ABORT¶

    FSP-BIND carries the usual parameters. The service-type is redundant because its only valid value is fwdTcSpacePkt, but it is kept for a future generic SLE-BIND.53 A responder that does not negotiate versions accepts the version configured in service-version-number. One that does negotiate may answer with a lower version.14 The BIND diagnostics are 'access denied' (0), 'service type not supported' (1), 'version not supported' (2), 'no such service instance' (3), 'already bound' (4), 'service instance not accessible to this initiator' (5), 'inconsistent service type' (6), 'invalid time' (7), 'out of service' (8, production halted) and 'other reason' (127).5413 A successful BIND moves the provider from state 1 to state 2.55

    FSP-UNBIND is valid only in 'ready', so the user must stop first. Its unbind-reason is 'end' (0), after which the provider may delete the instance, 'suspend' (1), 'version not supported' (2) or 'other' (127). The only possible result is 'positive result'.5613 FSP-PEER-ABORT carries one diagnostic: 'access denied' (0), 'unexpected responder ID' (1), 'operational requirement' (2), 'protocol error' (3), 'communications failure' (4, gateways only), 'encoding error' (5), 'return timeout' (6), 'end of service instance provision period' (7), 'unsolicited invoke-ID' (8) or 'other reason' (127). Values 128 to 255 are reserved for the communications technology. PEER-ABORT carries no credentials.5713

    What survives the end of an association matters for commanding. The provider discards the packets it holds for the instance. Packets already turned into Frame Data Units and placed in the segment queues are still sent. Three things persist across associations: accounting information, the identifiers that link notifications to the operations that caused them, and the COP parameters set by directives. Other provision parameters return to the values set by service management.5859

    After 'unable to comply' the user may try again later. If complex management decides the problem is more than transient, the provider may abort.60 FSP-STOP discards the instance's packets that have not yet reached the segment queues. Packets already in the segment queues are completed, and any radiation or acknowledgement notifications that were asked for are still sent.     The time window. Times may not go backwards from one packet to the next. If the earliest time is null, processing starts at once, provided production is operational and the required transmission mode is available, or the latest time is also null.26 If the latest time is null, the packet waits as long as the instance is 'active' and production is not halted. If a latest time is given, the provider holds the packet back while production is 'interrupted' or the transmission mode is unavailable, until recovery or expiry.26 Two notes in the standard matter in practice. First, the processing steps (for example blocking) take a non-negligible time. Setting the latest time equal to the earliest time therefore usually produces 'late sldu'. Second, once a packet is inside a TC frame, its latest time no longer applies. Multiplexing may then radiate it later than that time.26

    Delay time. The delay runs from the trailing edge of the last radiated bit of the last CLTU that carries part of the packet to the leading edge of the first bit of the next CLTU. Zero means no delay. The delay also applies when a frame is retransmitted under COP-1, and whatever VC the next frame is on. When several packets are blocked into one frame, the largest of their delay times is used. An unacceptable value is caught by the space link processing FG, and the rejection travels back up so that the TRANSFER-DATA return is negative.65

    Transmission mode and AD blocking. After a 'packet transmission mode mismatch', the AD mode of the instance is blocked. Every later AD request is rejected with 'invalid transmission mode' until the user sends a packet with mode 'sequence-controlled and unblock AD mode'. That mode is accepted only while AD is blocked. If the unblocking packet has to start before the AD service is back, a new mismatch occurs and AD is blocked again.66

    MAP and blocking. With a polling-vector MAP scheme, a packet on a permitted MAP that is not in the vector is queued but not processed until the vector changes. Segment Headers are needed when packets can exceed the frame's data field, or when MAPs are used on the VC.67 If blocking-usage is 'not permitted', the per-packet blocking flag is ignored, and each frame carries at most one packet.68

    Status reports¶

    FSP-SCHEDULE-STATUS-REPORT asks for one report now ('immediately'), periodic reports ('periodically', with a 2 to 600 s cycle), or no more reports ('stop').     The queue rules, in order:

    1. Each instance has one requests queue. It has one packets queue, or one per permitted MAP if MAPs are used. Each packets queue has one segments queue. The instance allowed to invoke directives also has a directives queue, so a VC has at most one.93
    2. A packet is stamped with its arrival time when it enters the requests queue. It moves to its MAP's packets queue when that queue has room and one of these holds. Production is operational with the needed mode available (sub-state 'AD and BD' for AD packets) and the earliest time is null. Or the same, with the earliest time reached. Or both times are null. Or the latest time, minus an implementation guard period, has been reached. The guard period makes sure the user gets the right notification ('packet transmission mode mismatch' or 'production interrupted') rather than 'late sldu'. Only the packet at the head of the requests queue is examined.93
    3. When a segments queue is empty, the head packet of its packets queue is segmented if needed and moved. If blocking is permitted and the packet allows it, the provider starts a blocking timer (blocking-timeout-period). It adds same-mode packets until the Frame Data Unit is full, a no-blocking packet comes next, or the timer expires.9394
    4. The latest-time check is made when a packet leaves the packets queue, and never again afterwards.94
    5. A Frame Data Unit takes the time stamp of its (first) packet. MAP multiplexing then picks Frame Data Units for the FOP. FIFO takes the earliest time stamp. Absolute priority always searches from the highest-priority MAP, and all priorities must be different. A polling vector visits MAPs in vector order and wraps round. VC multiplexing between FOPs works the same way, and the chosen frame goes to CLTU Generation.9596 The MAP schemes of different VCs and the VC scheme are independent.21
    6. Directives go into the directives queue for immediate execution.95
    7. Discards. STOP, PEER-ABORT, 'sldu expired' and protocol abort discard packets not yet in a segments queue and keep the built Frame Data Units. A transmission mode mismatch discards the built AD Frame Data Units, plus all AD packets of every instance that lost one. 'Abort VC' clears every queue of the VC. 'Interrupted' clears all queues of the instances that had Frame Data Units in progress. 'Halted' clears all queues.95
    8. When the FOP sliding window is full of unacknowledged AD and BC frames, BD Frame Data Units still pass to the FOP.96
    9. Frame repetition (optional). AD frames go to CLTU Generation sequence-controlled-frames-repetition times, and BC frames cop-control-frames-repetition times. Neither may exceed repetition-limit. BD frames go once. Repetition is meant for links with long light-time delay, where it raises the chance that a sequence of frames gets through in a short session. A provider that does not support repetition sets both parameters to 1.96

    Assume maximum-frame-length = 256 octets, a Frame Error Control Field and Segment Headers on the VC. A TC frame has a 5-octet header and an optional 2-octet FECF.97 That leaves 256 − 5 − 2 = 249 octets of frame data field, and after the 1-octet Segment Header, 248 octets of packet per frame. A 1,000-octet AD packet on MAP 2 therefore needs five segments (4 × 248 = 992, plus 8). Their Sequence Flags are 0b01, 0b00, 0b00, 0b00 and 0b10.98 It must be sent sequence-controlled, because segmented packets cannot go without sequence control.32 FSP puts each frame in its own CLTU, so this means five CLTUs. The packet's delay-time applies after the fifth.2365

    Next, three 40-octet AD packets with blocking allowed, on the same MAP, with delay times 0, 20,000 and 5,000 µs. They fit in one frame (120 + 1 octets ≤ 249), carry Sequence Flags 0b11, and the CLTU that carries them gets the largest delay, 20,000 µs.6598

    Security¶

    FSP provides authentication (three levels) and access control. Everything else is left to the communications service or to the mission. It specifies no confidentiality, no denial-of-service protection and no auditing.110 For integrity it has the monotonically increasing packet-identification, which makes it harder to inject extra packets, and the strict operation sequence of the state table. Neither prevents a third party from replacing the data of a PDU in transit. Protection against that has to come from above (for example encrypted packets), from below (the network), or from bilateral additions.110 The standard states that the consequences of not applying security can include losing the ability to command the spacecraft, and losing the spacecraft.110 This page describes the protections only. See also security in CCSDS space links.

    The API references FSP issue 2 (912.3-B-2), whose BIND version is 4.114113 The service book in this library is issue 3, which defines version 5.14 Whether an API issue covers version 5 is not stated in the available sources. Generation 1 is not valid for FSP, because FSP was first issued as part of generation 2.113

    A comparison of the two parameter lists shows the same gap. The API's FSP_ParameterName enumeration lacks codes 202, 203, 300, 301, 303 and 304, which the 2016 FSP ASN.1 defines.1158

    Inference

    The missing codes (clcwGlobalVcId, clcwPhysicalChannel, copCntrFramesRepetition, minReportingCycle, sequCntrFramesRepetition, throwEventOperation) are probably additions of issue 3, so a 2015 API implementation could not report them. The issue 2 book is not in the library to confirm this.

    The provider-side service instance answers GET-PARAMETER by itself, generates the STATUS-REPORT invocations by itself (the application never creates that operation object), and can send the notifications on the application's behalf.121122 It also keeps the status counters. For example, packet-buffer-available is reset to the maximum after STOP, 'buffer empty', PEER-ABORT and protocol abort. expected-sldu-identification is set from the first-packet-identification of a START that the application confirms positively, and then from the packet-identification of each TRANSFER-DATA return.123124 The initial values after configuration are zero or null for all counters and identifiers, 'invalid' for packet status, and the configured values for production status, buffer size and directive-invocation-online.125

    What the API does not check, and why¶

    The API deliberately leaves several checks to the application. Production status can change between the moment the service element looks at a PDU and the moment the application sees it. So the API need not check production status for BIND and START, the 'blocked' and 'AD blocked' states, time windows against the current time, or the production period. The API treats packets as opaque, so it does not check APID, packet version or packet type either.126 For TRANSFER-DATA, THROW-EVENT and INVOKE-DIRECTIVE, it may pass an invocation that failed its own checks to the application with the diagnostic already set. The application then fills in the next expected identifier (and, for TRANSFER-DATA, the free buffer space) before the return goes out. This departs from the core API's handling of confirmed operations. Applications that want substitutable API products must expect it.127128

    The checks the service element does make on TRANSFER-DATA, in its own order, are: time range consistent, window overlaps the provision period, MAP valid for the Segment Header setting, mode matches the permitted mode, no acknowledgement request for expedited packets, and packet not too long.129 As a result, the documented order of diagnostics is split.130

    FSP in ESA's ground segment and the Solar Orbiter MIB¶

    The public Solar Orbiter MIB shows that the ESOC ground interface knows about FSP but that the mission's TC links are opened as FCLTU. The NIS throw-event command parameter ENISTE03 "SLE Service Type" is calibrated by the textual calibration CNISX207TC. It lists RAF (1), RCF (2), ROCF (3), FCLTU (4) and FSP (5). Yet both TC-link commands, EGENRTCO "GENERIC OPEN TC LINK" and EGENRTCC, fix it to FCLTU. The TM-link commands fix it to RCF. The 2020-04-16 release has the same values.133134 The NIS throw events are described on NCTRS, NIS and the ground station interface.

    The MIB's "Releaser G/S response" telemetry parameter NYG02202 "GS Packet Type" (in SPID 66850) has textual calibration CYGT2202TM. Beside CLTU, COP-1 directive and throw-event values, it defines FSPPkt (20), FSPPkt_Resp (21), FSPdirective (22) and FSPdir_Resp (23).133

    Inference

    The GS packet types suggest that the NCTRS/NIS ground interface has message types for forwarding packets and COP-1 directives to an FSP provider. The two Solar Orbiter TC-link commands use FCLTU, so on this mission frames and COP-1 appear to be produced on the ground side of the SLE interface and FSP appears unused. The NIS interface document that would confirm this is not public.

    The MIB also shows a real SLE service instance identifier, split across the elements of EGENRTCO. The values sagr=144.spack=, NN11-PERM.fsl-f and g=1.cltu=cltu01 join up as sagr=144.spack=NN11-PERM.fsl-fg=1.cltu=cltu01.133 That is exactly the attribute syntax that the FSP ASN.1 defines. It names the service agreement (sagr), the service package (spack), the forward functional group (fsl-fg) and the service (cltu plus an instance number), separated by dots. An FSP instance would end in fsp=fsp<n>.18 The meaning of agreements and packages is on service management.

    Notes on the specification text¶

    Some inconsistencies appear in the library copy of 912.3-B-3. They are recorded here so that implementers can check them against the current CCSDS text:

    • In FspGetParameter, context tag [27] is used for both parBitLockRequired and parClcwGlobalVcId, and tag [28] for both parClcwPhysicalChannel and parRfAvailableRequired.40
    • 3.9.2.12.2 says the acknowledged count is set to zero "if Space Packets have been acknowledged". The parallel clauses read "if no Space Packets…".82
    • One reason for 'unable to process' (3.6.2.18.1 b 2) refers to CLTU-ASYNC-NOTIFY, which is an FCLTU operation.34
    • The text calls the THROW-EVENT diagnostic 'out of sequence'. The ASN.1 names it eventIdentificationOutOfSequence.8739
    • transmission-limit is reported as 1 to 255 by GET-PARAMETER. The 'Set Transmission_Limit' directive accepts 1 to 65,535.4047
    • The text disagrees with itself on when a packet "starts to be processed". The processing-started-notification parameter (3.6.2.12) and the note in 3.7.2.9 place it at the move from a packets queue to a segments queue. The 'packet processing started' notification (3.7.2.3 a), the 'production started' packet status (3.7.2.11 c) and the note in 3.9.2.3.1 place it at the move from the requests queue to a packets queue.28717082
    • maximum-packet-length is described as the maximum "Packet Data Length" (table 3-11 and diagnostic 'packet too long'). Its ASN.1 range, 7 to 65,542 octets, is that of a whole Space Packet, while the data parameter (SpaceLinkDataUnit) stops at 65,536 octets.463440837

    The API book has its own slips:

    • The header of A3.7 (Invoke Directive) names the file IFSP_ThrowEvent.H.131
    • 3.1.5.1.1 d) has the service element check the transmission mode against the permitted mode. Yet 3.4.2 lists 'invalid transmission mode' among the diagnostics set by the application, not by the service element.129130
    • 1.1 calls the API core specification "reference [5]", but [5] in 1.7 is the C++ language standard and the core (914.0-M-2) is [4].111114
    • It dates the generation 2 book, 912.3-B-1, to December 2004. The FSP book's document control gives November 2004.1144
